When future rows rewrite the past: a calendar correction audit

Eleven same-input old/new rule comparisons, kept separate from 176 earlier published-curve differences.

ReproducibilityCostsFixed sample

Hypothesis: extending history must preserve causal targets

When the input prefix and configuration are unchanged, appending observations after date t must not change targets already determined through t. A downloaded terminal row cannot establish that a month has ended. We compare the retained old and corrected implementations on identical inputs, rather than choosing the rule with the best return.

Alternate timing rules, not equivalent implementations

CAL-01 weekday-calendar-month-turn-v2 replaces future downloaded-row counts with known Monday–Friday calendar counts. It ignores exchange holidays, and weekend observations may fall inside the contiguous window. This changes the declared rule. FACTOR-05 monthly-prior-observation-v2 decides at the first observed new-month session using the preceding completed observation; the engine then applies its normal one-row lag. Partial-month terminal rows no longer trigger rebalancing, and trading-month-end timing also changes.

Two denominators that must stay separate

The eleven same-input corrections are ten CAL-01 markets and the FACTOR-05 basket labeled SPY. Those common-date normalized comparisons may include provider revisions, cutoffs and implementation changes. They are not 176 proven code defects; subtracting eleven does not attribute the remainder. The legacy sameInputAccountingCorrections field is a separate accounting comparison.

Falsification and reproduction boundary

The calendar values and equal-input identities above are retained historical audit records. The bundled 72-scenario cost replay checks the correction table’s packet hash for consistency; it does not independently recheck those calendar outcomes or old/new input identities. For per-run public arithmetic reproduction, follow each archived manifest’s reproduction instructions; that separate process still does not regenerate decisions from original private inputs. The retained publication proof records eleven recomputed runs and 565 reused unchanged proofs; retained robustness and sensitivity studies were not independently rerun by that subset refresh. Synthetic prefix tests can test implementation causality across weekends, holidays, month transitions and partial-month endings; they do not substitute for the original-input replay.

python -B -m unittest discover -s tests -p test_calendar_causality.py
python -B -m unittest discover -s tests -p test_multi_factor_calendar.py

Run these implementation checks in a source checkout. A changed earlier target under an unchanged prefix falsifies causality; a changed input hash invalidates a same-input comparison. The weekday approximation is not a verified exchange-holiday calendar. This audit does not establish MT5 parity.

Fixed evidence, rules and reproduction

The six original pilots are MR-01 (RSI Mean Reversion), MR-16 (Connors RSI), TURTLE-01 (Turtle Trading), TREND-14 (Linear Regression Channel), RP-01 (Volatility Target) and RISK-04 (Trailing Stop Strategy). RP-01 is not the separate risk-parity basket. All 18 strategy-market pairs and 72 fee scenarios are retained. This retrospective selection was fixed before table extraction; it is not a prospective preregistration.

The cost and cross-market panels use 2021-11-05 through 2026-11-05, with 1,255 closes for SPY/GLD and 1,827 for BTC-USD. Return intervals are one fewer. The calendar audit uses each run’s full native dates. Daily site updates do not replace this frozen evidence.

The bundled replay verifies recorded arithmetic for the 18 pilot cost runs and 72 scenarios. It does not independently recheck the calendar audit outcomes or their old/new input identities, and does not regenerate decisions from fresh vendor inputs. Original-input recomputation requires matching retained private inputs and archived dependencies. The packet verifies peer sorting from 168 frozen entries in three 56-member cohorts; it does not replay every peer’s complete history. Public network retrieval must be checked at release.
