策略分析

分析 ### 2.1 核心策略概念 **JK synchro** 是一个基于**多蜡烛投票机制**的趋势判断策略，由MetaQuotes官方开发者barabashkakvn编写，展示了MQL5标准库(Standard Library)的正确使用方式。 **策略核心思想**： 1. 统计最近N根K线中上涨K线(Open>Close)和下跌K线(Open<Close)的数量 2. 当上涨K线数量多于下跌K线时 → 判断为上涨趋势 → 做多 3. 当下跌K线数量多于上涨K线时 → 判断为下跌趋势 → 做空 4. 本质上是一个**简化版的价格动量投票系统** 这是一个**均值回归+趋势跟踪混合策略**，但更偏向于**趋势确认**而非反转，因为它基于多数K线方向判断趋势。 ### 2.2 入场条件 **做多条件 (全部满足)**: 1. `CalculateAllPositions() < InpMaxPositions` - 持仓数未达上限 2. `InpStartHour <= 当前小时 <= InpEndHour` - 在指定交易时段内 3. `TimeCurrent() - m_last_deal_IN >= InpPause` - 交易间隔满足最小暂停时间 4. **核心信号**: `up > down` - 上涨K线数量 > 下跌K线数量 **做空条件 (全部满足)**: 1. 持仓数未达上限 2. 在指定交易时段内 3. 交易间隔满足最小暂停时间 4. **核心信号**: `up < down` - 下跌K线数量 > 上涨K线数量 **入场逻辑代码**: ⚠️ **重大发现：信号逻辑存在BUG！** - 代码中 `rates[i].open>rates[i].close` 表示**下跌K线**，但累加到 `up` 变量 - 代码中 `rates[i].open<rates[i].close` 表示**上涨K线**，但累加到 `down` 变量 - 变量命名与实际逻辑完全**相反** - 实际效果：做多时实际是**多数下跌K线**，做空时实际是**多数上涨K线** - **这是一个反转策略，而非趋势跟踪策略！** ### 2.3 出场条件 **止损**: - 固定点数止损：`InpStopLoss` 点 (默认50点) - 做多止损 = Ask - ExtStopLoss - 做空止损 = Bid + ExtStopLoss **止盈**: - 固定点数止盈：`InpTakeProfit` 点 (默认150点) - 做多止盈 = Ask + ExtTakeProfit - 做空止盈 = Bid - ExtTakeProfit **追踪止损**: - 当价格朝有利方向移动超过 `ExtTrailingStop + ExtTrailingStep` 时触发 - 止损跟随价格移动，保持 `ExtTrailingStop` 距离 **盈亏比**: 默认 TP=150/SL=50 = **3:1**，非常良好！ ### 2.4 风险管理 **手数管理** (二选一): 1. **固定手数模式**: `InpLots > 0` 且 `Risk == 0` 2. **风险百分比模式**: `InpLots == 0` 且 `Risk > 0` - 使用 `CMoneyFixedMargin` 类计算动态手数 - 根据账户余额百分比和止损距离计算 **其他风控措施**: 1. **最大持仓数限制**: `InpMaxPositions` (默认10) 2. **交易时间过滤**: 仅在 `InpStartHour` 到 `InpEndHour` 之间交易 (默认3:00-6:00) 3. **交易间隔控制**: 两次交易之间必须间隔 `InpPause` 秒 (默认540秒=9分钟) 4. **手数合法性检查**: `CheckVolumeValue()` 验证最小/最大手数和步长 5. **预检查机制**: `m_trade.CheckVolume()` 在下单前验证手数有效性 6. **持仓检查**: 每次开仓前检查当前持仓数量

劣势

  • ❌ 信号逻辑BUG:
  • 变量实际统计下跌K线
  • 变量实际统计上涨K线
  • 策略行为与命名完全相反
  • ❌ 策略逻辑过于简单:
  • 仅统计K线涨跌数量，不考虑实体大小
  • 无趋势强度判断
  • 无支撑阻力位考虑
  • ❌ 无新K线检测机制:
  • 每个Tick都会重新计算信号
  • 可能重复开仓或错过最佳入场点
  • ❌ 时段设置不合理:
  • 默认3:00-6:00过于狭窄
  • 仅覆盖亚洲早盘初期
  • ❌ 分析周期过长:
  • 18根K线的投票机制滞后严重
  • 响应速度慢
