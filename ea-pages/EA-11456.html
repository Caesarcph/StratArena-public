摘要

该EA是一个监控工具，将账户状态、订单通知和交易历史报告写入文本文件。它通过逐tick比较订单号数组来追踪新开仓和已平仓的订单，并将变化输出到通知文件中。它本身不执行任何开仓、修改或平仓操作。

策略分析

该EA并非交易策略，而是一个纯监控/报告工具。它不包含任何入场条件或出场条件，不会自动下单或平仓。其核心功能有三个：一是WriteStatus()函数，实时写入账户余额、当前持仓品种、方向、手数和浮动盈亏点数到status.txt；二是WriteNotify()函数，通过比较当前订单号数组和上一次tick的订单号数组，检测新增订单和已平仓订单，将变化写入notify.txt；三是WriteReport()函数，当账户余额变化时，读取历史订单并按平仓时间排序，生成包含开平仓时间、价格、手续费、掉期和盈亏的CSV格式报告。仓位管理和资金管理方面完全不存在，因为该EA不执行任何交易操作。整体逻辑简单直接，但代码质量较低，存在变量作用域问题和排序效率低下的缺陷。

Summary

This EA is a monitoring utility that writes account status, order notifications, and trade history reports to text files. It tracks opened and closed orders by comparing ticket arrays across ticks and outputs changes to a notify file. It does not open, modify, or close any trades on its own.

Strategy Analysis

This EA is not a trading strategy but a pure monitoring/reporting utility. It contains no entry or exit conditions and does not place or close any trades automatically. Its core functionality has three parts: first, WriteStatus() writes real-time account balance, current positions with symbol, direction, lot size, and floating profit in pips to status.txt; second, WriteNotify() detects newly opened and closed orders by comparing the current ticket array against the previous tick's ticket array, writing changes to notify.txt; third, WriteReport() reads historical orders when account balance changes, sorts them by close time using an inefficient O(n²) selection sort, and generates a CSV report with open/close times, prices, commission, swap, and profit. There is no position sizing or money management since the EA does not execute any trades. The overall logic is straightforward but the code quality is low, with variable scoping issues and an inefficient sorting algorithm.

优势

  • 实时监控账户状态和持仓信息，便于外部程序读取
  • 自动检测订单开仓和平仓事件并记录通知，提供及时的订单变动追踪
  • 生成排序后的历史交易报告，包含完整的交易明细和盈亏信息
  • 文件输出格式清晰，便于与其他系统集成或远程监控
  • 资源占用低，仅在每个tick执行文件写入操作

劣势

  • WriteReport()中的排序算法使用O(n²)的选择排序，当历史订单数量大时性能极差
  • 变量作用域管理混乱，循环变量i和j在for循环外声明却在循环内使用，存在潜在的编译问题
  • WriteReport()第174行存在严重bug：closeprice应使用OrderClosePrice()而非OrderOpenPrice()
  • 每个tick都执行文件写入操作，频繁的磁盘I/O可能影响终端性能
  • 缺少错误处理和文件锁定机制，多实例运行时可能导致文件写入冲突
  • notify文件每次覆写而非追加，之前的通知信息会丢失

改进建议

  • 修复closeprice使用OrderOpenPrice()而非OrderClosePrice()的严重bug
  • 将O(n²)选择排序替换为数组排序或更高效的排序算法，提升大量历史订单时的性能
  • 通知文件应采用追加模式写入而非覆写，避免丢失历史通知记录
  • 添加新bar检查机制，避免每个tick都执行文件写入，减少不必要的磁盘I/O
  • 规范变量作用域，将循环变量声明在for语句内部

Strengths

  • Real-time monitoring of account status and position info, easy for external programs to read
  • Automatically detects order open and close events and logs notifications, providing timely order change tracking
  • Generates sorted historical trade reports with complete trade details and P&L information
  • Clean file output format, easy to integrate with other systems or remote monitoring
  • Low resource usage, only performs file writes on each tick

Weaknesses

  • The sorting algorithm in WriteReport() uses O(n²) selection sort, which has terrible performance with large order history
  • Variable scoping is messy — loop variables i and j are declared outside for loops but used inside, potentially causing compilation issues
  • Critical bug on line 174 of WriteReport(): closeprice uses OrderOpenPrice() instead of OrderClosePrice()
  • File writes execute on every tick, frequent disk I/O may impact terminal performance
  • Lacks error handling and file locking, concurrent instances may cause file write conflicts
  • The notify file is overwritten rather than appended, previous notification data is lost

Improvements

  • Fix the critical bug where closeprice uses OrderOpenPrice() instead of OrderClosePrice()
  • Replace the O(n²) selection sort with a more efficient sorting algorithm for better performance with large order histories
  • The notify file should use append mode instead of overwrite to preserve historical notification records
  • Add new bar check mechanism to avoid file writes on every tick, reducing unnecessary disk I/O
  • Normalize variable scoping by declaring loop variables inside for statements
