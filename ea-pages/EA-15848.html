摘要

一个通用的移动止损工具，支持7种不同的移动止损方式，包括固定点数、分形、ATR、抛物线指标、均线、利润百分比和固定距离。它既可以作为真实移动止损运行，也可以作为虚拟移动止损运行，并支持对冲账户通过分别计算买卖仓位的加权平均入场价来管理止损。

策略分析

该EA不是一个自主交易策略，而是一个移动止损管理工具。它的核心概念是根据用户选择的7种方法之一动态调整止损水平：固定点数、分形、ATR、抛物线SAR、均线、利润百分比或固定点距。对于真实移动止损模式，它通过TRADE_ACTION_SLTP修改仓位的止损价；对于虚拟移动止损模式，它不修改实际止损，而是在价格触及虚拟止损线时直接市价平仓。在对冲账户中，它计算所有买单和卖单的加权平均开仓价作为无亏损水平（NL），虚拟止损模式以该加权平均价作为基准计算止损位。出场条件为价格触及动态计算的止损位，没有独立的入场逻辑。仓位管理方面仅支持按Magic号筛选仓位，不具备独立的仓位大小计算或资金管理功能。参数StepTrall控制止损移动的最小步距以避免频繁修改，StartTrall设定止损开始跟踪的最低盈利点数阈值。

Summary

A universal trailing stop utility for MetaTrader 5 that supports 7 different trailing methods including fixed pips, fractals, ATR, Parabolic SAR, Moving Average, percentage of profit, and fixed distance. It can operate as either a real or virtual trailing stop and supports hedging accounts by calculating weighted average entry prices for buy and sell positions separately.

Strategy Analysis

This EA is not an autonomous trading strategy but rather a trailing stop management utility. Its core concept is dynamically adjusting stop loss levels based on one of seven user-selected methods: fixed pips, fractals, ATR, Parabolic SAR, Moving Average, percentage of profit, or fixed distance. For real trailing stop mode, it modifies position stop losses via TRADE_ACTION_SLTP; for virtual trailing stop mode, it does not modify actual stop losses but instead closes positions at market when price hits the virtual stop line. On hedging accounts, it calculates the weighted average entry price for all buy and sell positions as the no-loss level (NL), and the virtual stop mode uses this weighted average as the basis for calculating stop levels. Exit conditions are price hitting the dynamically calculated stop level, with no independent entry logic. Position management only supports filtering by Magic number, lacking independent lot size calculation or money management capabilities. The StepTrall parameter controls the minimum step for stop loss adjustment to avoid frequent modifications, while StartTrall sets the minimum profit threshold in points before trailing begins.

优势

  • 支持7种不同的移动止损方式，灵活度极高，适应不同交易风格
  • 虚拟移动止损模式可以隐藏真实止损意图，防止经纪商猎杀止损
  • 对冲账户支持，自动计算买卖仓位的加权平均价作为基准
  • 可视化止损线和箭头标记，方便交易者实时监控止损状态
  • StepTrall和StartTrall参数有效避免止损频繁修改和过早跟踪

劣势

  • 代码中存在多处严重bug，如使用OrderGetInteger检查仓位Magic号而非PositionGetInteger
  • 虚拟止损模式在每次tick都执行平仓判断，无新bar检测，可能导致重复下单或延迟
  • StrPer函数中H3映射为M3、H4映射为M4等明显错误
  • 没有止损合法性检查(OrderCheck)对买单的处理，仅卖单有检查
  • 分形止损逻辑的for循环可能无法找到有效分形，导致prc为0或无效值

改进建议

  • 修复Magic号判断bug：将OrderGetInteger(ORDER_MAGIC)改为PositionGetInteger(POSITION_MAGIC)
  • 修复StrPer函数中的时间周期映射错误，正确返回H3/H4/H6/H8/H12
  • 添加新bar检测机制避免每个tick都执行止损计算和修改操作
  • 统一买单和卖单的止损修改逻辑，为买单也添加OrderCheck预检查

Strengths

  • Supports 7 different trailing stop methods offering extreme flexibility for various trading styles
  • Virtual trailing stop mode hides true stop intent from brokers, preventing stop hunting
  • Hedging account support with automatic weighted average price calculation for buy/sell positions
  • Visual stop lines and arrow markers allow traders to monitor stop status in real time
  • StepTrall and StartTrall parameters effectively prevent frequent SL modifications and premature trailing

Weaknesses

  • Multiple serious bugs: using OrderGetInteger for position Magic instead of PositionGetInteger
  • Virtual stop mode executes close logic every tick without new bar check, risking repeated orders or delays
  • StrPer function has obvious mapping errors like H3→M3, H4→M4, H6→M6, H8→M8, H12→M12
  • No OrderCheck validation for buy position modifications, only sell positions have pre-check
  • Fractal stop logic loop may fail to find a valid fractal, leaving prc at 0 or invalid

Improvements

  • Fix Magic number bug: replace OrderGetInteger(ORDER_MAGIC) with PositionGetInteger(POSITION_MAGIC)
  • Fix timeframe mapping errors in StrPer function to correctly return H3/H4/H6/H8/H12
  • Add new bar detection mechanism to avoid executing SL calculations and modifications every tick
  • Unify buy/sell SL modification logic, add OrderCheck pre-validation for buy positions as well

风险评估 / Risk Assessment

总体 / Overall:MEDIUM

风险点

  • 虚拟止损模式不设置真实止损，若EA断开连接则仓位无保护
  • Magic号判断使用OrderGetInteger而非PositionGetInteger，可能导致错误匹配仓位或遗漏仓位
  • 无新bar检测导致每个tick都尝试修改止损，可能在快速行情中产生过多交易请求被经纪商限制

Risk Assessment

Overall:MEDIUM

Risk Points

  • Virtual trailing stop mode sets no real SL, leaving positions unprotected if EA disconnects
  • Magic number check uses OrderGetInteger instead of PositionGetInteger, potentially matching wrong positions or missing valid ones
  • No new bar check causes SL modification attempts every tick, which may trigger broker rate limits during fast markets
