摘要

该EA使用布林带和ADX指标在价格触及外轨且趋势较弱时寻找均值回归入场点。采用马丁格尔仓位管理策略，在亏损交易后将手数乘以倍数。隐身模式允许设置对经纪商不可见的虚拟止损和止盈。

策略分析

策略概念是基于布林带均值回归，当价格触及下轨时做多、触及上轨时做空，同时要求ADX低于阈值以确认市场处于震荡状态。入场条件为：做多需Ask价低于布林带下轨且ADX[1]低于45且上一笔交易非买入；做空需Bid价高于布林带上轨且ADX[1]低于45且上一笔交易非卖出。出场条件包括实体止损止盈和隐身模式下的虚拟止损止盈，隐身模式通过每tick检测浮盈浮亏点数来手动平仓。仓位管理采用马丁格尔策略，亏损后下一单手数=上一单手数×KLot（默认2倍），若超过MaxLot则重置为基础手数Lot。资金管理方面，初始手数固定为0.1，最大手数限制为5手，但缺乏基于账户余额的动态计算。此外，该EA限制同时只持有一个仓位，且根据上一笔交易方向决定当前可开仓方向，避免连续同方向交易。

Summary

This EA uses Bollinger Bands and ADX to identify mean reversion entry points when price touches the outer bands during low-trend conditions. It employs a Martingale position sizing strategy that multiplies lot size by a factor after each losing trade. Stealth mode allows virtual stop-loss and take-profit levels that are not visible to the broker.

Strategy Analysis

The strategy concept is based on Bollinger Bands mean reversion, going long when price touches the lower band and going short when price touches the upper band, while requiring ADX below a threshold to confirm the market is in a ranging state. Entry conditions are: buy when Ask is below the lower Bollinger Band, ADX[1] is below 45, and the last deal was not a buy; sell when Bid is above the upper Bollinger Band, ADX[1] is below 45, and the last deal was not a sell. Exit conditions include real stop-loss and take-profit levels, or virtual SL/TP in stealth mode where the EA monitors floating P/L in points every tick and manually closes positions. Position sizing uses a Martingale approach where the lot size after a loss is multiplied by KLot (default 2x), and if it exceeds MaxLot it resets to the base Lot value. Money management uses a fixed initial lot of 0.1 with a maximum lot cap of 5 lots, but lacks dynamic calculation based on account equity or balance. Additionally, the EA limits to holding only one position at a time and restricts consecutive same-direction trades based on the last deal type.

优势

  • 布林带配合ADX过滤趋势行情，避免在强趋势中逆势交易
  • 隐身模式可隐藏止损止盈，防止经纪商猎杀止损
  • 设有最大手数限制，防止马丁格尔策略无限加仓
  • 新K线检测避免同一根K线内重复开仓

劣势

  • 马丁格尔策略本质风险极高，连续亏损后手数指数增长可能导致爆仓
  • IsNewBar函数存在逻辑bug，m_TOld为局部变量每次调用都重置为0，导致每次调用都返回true
  • PutLable函数中ObjectSetInteger代码位于return之后，永远不会被执行
  • 止损(1400点)小于止盈(1200点)但差距不大，马丁格尔加倍后风险收益比恶化严重
  • 仅允许单持仓，无法对冲或分散风险

改进建议

  • 修复IsNewBar函数，将m_TOld改为static变量以确保正确检测新K线
  • 将马丁格尔策略替换为更安全的仓位管理方式，如固定分数法或凯利公式
  • 修复PutLable函数中return之后的死代码，将对象属性设置移到return之前
  • 增加点差过滤和最大连续亏损次数限制

Strengths

  • Bollinger Bands combined with ADX filters out trending markets, avoiding counter-trend entries during strong moves
  • Stealth mode hides SL/TP from the broker, preventing stop hunting
  • Maximum lot size cap prevents the Martingale strategy from scaling infinitely
  • New bar check prevents duplicate entries within the same candle

Weaknesses

  • Martingale strategy carries extreme risk; exponential lot growth after consecutive losses can blow the account
  • IsNewBar function has a critical bug: m_TOld is a local variable reset to 0 on every call, always returning true
  • PutLable function has ObjectSetInteger calls after the return statement, which are unreachable dead code
  • Stop-loss (1400 points) is larger than take-profit (1200 points), and the risk-reward ratio deteriorates severely after Martingale doubling
  • Single position only, no hedging or risk diversification possible

Improvements

  • Fix IsNewBar function by making m_TOld a static variable so it correctly detects new bars
  • Replace Martingale with safer position sizing such as fixed fractional or Kelly criterion
  • Fix PutLable dead code by moving ObjectSetInteger calls before the return statement
  • Add spread filter and maximum consecutive loss count limit

风险评估 / Risk Assessment

总体 / Overall:DANGEROUS

风险点

  • 马丁格尔策略在连续亏损时手数指数增长，极端行情下可能导致账户爆仓
  • 止损大于止盈(1400>1200)，盈亏比不利，需要更高胜率才能盈利
  • IsNewBar函数bug导致每个tick都可能开仓而非每根K线一次
  • 隐身模式下虚拟止损依赖EA持续运行，VPS断线或EA崩溃将导致无止损保护
  • Volume函数中HistoryDealGetTicket(orders-1)当orders为0时可能访问无效索引

Risk Assessment

Overall:DANGEROUS

Risk Points

  • Martingale lot doubling on consecutive losses can lead to account blow-up during adverse markets
  • Stop-loss exceeds take-profit (1400>1200), unfavorable risk-reward ratio requires high win rate
  • IsNewBar bug causes potential entry on every tick instead of once per bar
  • Stealth mode virtual SL depends on EA running continuously; VPS disconnect or EA crash leaves no stop protection
  • Volume function may access invalid index when HistoryDealGetTicket(orders-1) is called with orders=0
