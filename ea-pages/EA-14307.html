摘要

该EA基于当前会话中买卖订单数量和成交量的比率来判断市场情绪并进行交易。当买方或卖方在订单数和成交量上显著占优时开仓，当情绪比率低于动态阈值时平仓。交易仅限工作日的特定时段。

策略分析

策略概念基于市场情绪分析，通过比较当前会话中买单与卖单的数量比和成交量比来判断多空力量对比。入场条件为：在允许的交易时段内（工作日10:15:30至23:35:30），买单数量/卖单数量>=DiffTraders且买单成交量/卖单成交量>=DiffVolumes时做多；反之卖单占优时做空，同时要求订单数或成交量分别达到MinTraders和MinVolume的最低门槛。出场条件为：持仓后若情绪比率回落至较低阈值以下则平仓，或在非交易时段强制平仓。仓位管理采用固定手数（Lots参数），无加仓减仓机制。资金管理仅依赖固定点数的止盈止损（TpPips和SlPips），缺乏基于账户余额或波动率的动态仓位调整。值得注意的是，开仓后DiffVolumes和DiffTraders阈值会降低，使得持仓更容易维持，这是一种情绪确认的滞后保持机制。

Summary

This EA trades based on market sentiment derived from the ratio of buy vs. sell orders and volumes in the current session. It opens BUY or SELL positions when one side significantly dominates the other in both order count and volume, and closes positions when the sentiment ratio falls below a dynamic threshold. Trading is restricted to a specific time window on weekdays.

Strategy Analysis

The strategy concept is based on market sentiment analysis, comparing the ratio of buy order count to sell order count and buy volume to sell volume in the current session to gauge bullish vs bearish pressure. Entry conditions: within the allowed trading window (weekdays 10:15:30 to 23:35:30), a BUY is opened when BUYorders/SELLorders >= DiffTraders AND BUYvolume/SELLvolume >= DiffVolumes; conversely a SELL is opened when sell-side ratios dominate, with minimum thresholds of MinTraders for order count and MinVolume for volume. Exit conditions: positions are closed when the sentiment ratio falls below a lowered threshold after opening, or forced closed outside trading hours. Position sizing uses a fixed lot size (Lots parameter) with no scaling or pyramiding mechanism. Money management relies solely on fixed-pip take profit and stop loss (TpPips and SlPips), lacking dynamic sizing based on account equity or volatility. Notably, after opening a position, DiffVolumes and DiffTraders thresholds are reduced to MinDiffVolumesEx and MinDiffTradersEx, making it easier to hold the position — a sentiment confirmation lag mechanism.

优势

  • 基于市场情绪数据（订单数量和成交量比率）进行交易，逻辑直观且具有市场微观结构依据
  • 设有交易时段过滤，避免周末和非活跃时段交易
  • 持仓后降低阈值机制有助于减少因短期情绪波动导致的过早平仓
  • 设有最低成交量和订单数量门槛，过滤低流动性虚假信号
  • 同时要求成交量和订单数量两个维度达标，双重确认提高信号可靠性

劣势

  • 使用Sleep()阻塞OnTick线程，会冻结整个EA包括其内部计时器和事件处理，严重影响EA运行稳定性
  • pos变量类型为int但用false赋值，存在类型混淆的编程错误
  • tradeResult作为全局标志位控制开仓，一旦开仓成功后在平仓前无法再次开仓，缺乏多仓位管理能力
  • 止损止盈使用TickSize计算而非点值(Point)，可能导致在不同品种上实际点数与预期不符
  • 无滑点保护、无重试机制、无订单状态检查，OrderSend失败后仅简单设pos=false
  • 平仓逻辑中同时判断当前持仓和反向情绪，但未检查是否实际存在持仓就调用PositionClose

改进建议

  • 将Sleep()替换为基于时间戳的非阻塞延时机制（如记录上次检查时间并比较），避免阻塞EA线程
  • 修复pos变量类型为int却赋值false的问题，应统一使用明确的整数常量（如0表示无持仓）
  • 添加实际持仓检查（使用PositionSelect或PositionsTotal）而非仅依赖全局变量跟踪状态，确保平仓逻辑与真实持仓一致
  • 增加基于账户风险百分比的动态仓位计算，替代固定手数，提升资金管理能力
  • 添加OrderSend重试机制和错误码日志输出，提高交易执行的鲁棒性

Strengths

  • Trades based on market sentiment data (order count and volume ratios), which is intuitive and grounded in market microstructure
  • Includes trading session filter to avoid weekends and inactive hours
  • Threshold reduction after opening helps prevent premature exits due to short-term sentiment fluctuations
  • Minimum volume and order count thresholds filter out low-liquidity false signals
  • Requires both volume and order count dimensions to confirm signals, improving reliability through dual confirmation

Weaknesses

  • Uses Sleep() which blocks the OnTick thread, freezing the entire EA including timers and event handling, severely impacting stability
  • The pos variable is declared as int but assigned false (bool), indicating a type confusion programming error
  • tradeResult as a global flag prevents opening new positions until the current one is closed, lacking multi-position management
  • SL/TP calculated using TickSize instead of Point, which may cause actual pip distances to differ from expectations on certain instruments
  • No slippage protection, no retry mechanism, no order state verification; OrderSend failure simply sets pos=false
  • Close logic calls PositionClose without verifying an actual position exists, potentially causing unnecessary trade requests

Improvements

  • Replace Sleep() with a timestamp-based non-blocking delay mechanism (e.g., record last check time and compare), avoiding EA thread blocking
  • Fix the pos variable type mismatch (int assigned false); use explicit integer constants (e.g., 0 for no position) consistently
  • Add actual position verification (using PositionSelect or PositionsTotal) instead of relying solely on global variable state tracking, ensuring close logic matches real positions
  • Implement dynamic position sizing based on account risk percentage instead of fixed lots, improving money management
  • Add OrderSend retry mechanism and error code logging to improve trade execution robustness

风险评估 / Risk Assessment

总体 / Overall:HIGH

风险点

  • Sleep()阻塞OnTick线程可能导致错过重要市场事件和价格变化，增加滑点风险
  • 无实际持仓状态验证，全局变量可能与真实持仓不同步，导致错误平仓或重复开仓
  • 固定手数无风险比例控制，在大幅波动时可能造成过大亏损
  • 止损止盈基于TickSize计算，在某些品种上可能与预期点数差距很大

Risk Assessment

Overall:HIGH

Risk Points

  • Sleep() blocking the OnTick thread may cause missed market events and price changes, increasing slippage risk
  • No actual position state verification; global variable may desync from real positions, causing incorrect closes or duplicate opens
  • Fixed lot size without risk-proportional control may cause excessive losses during high volatility
  • SL/TP based on TickSize may differ significantly from expected pip distances on certain instruments
