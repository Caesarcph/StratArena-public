摘要

Trailing Star是一款移动止损工具EA，通过修改已有持仓的止损来跟踪价格走势。它有两个变体：基于点数（从入场价获利固定点数后触发）和基于价格（价格突破用户指定入场价后触发）。该EA本身不开仓，仅管理已有持仓的止损。

策略分析

策略概念：这是一个纯粹的移动止损管理工具，不涉及任何开仓策略。入场条件：EA本身不开仓，仅对已有持仓进行管理。Point版本的触发条件是当持仓浮盈超过设定的entry_point点数后开始移动止损；Price版本的触发条件是当价格突破用户指定的entry_price后开始移动止损。出场条件：通过移动止损来保护利润，止损会跟随价格移动trailing_point点数的距离，当价格回撤触及移动止损时平仓。仓位管理：EA不进行任何仓位管理，也不开仓。资金管理：没有任何资金管理逻辑，不计算风险百分比或动态调整仓位。两个版本的核心逻辑相同：对于BUY仓位，当价格上升时将止损上移；对于SELL仓位，当价格下降时将止损下移，止损始终保持在距离当前价格trailing_point点数的位置。

Summary

Trailing Star is a trailing stop utility EA that modifies existing position stop-losses to follow price movement. It comes in two variants: Point-based (triggers after a fixed point profit from entry) and Price-based (triggers when price crosses a user-specified entry price). The EA does not open any trades itself; it only manages stop-losses of already-open positions.

Strategy Analysis

Strategy concept: This is a purely trailing stop management utility with no trade entry logic of its own. Entry conditions: The EA does not open positions; it only manages stop-losses on existing positions. The Point variant triggers trailing when floating profit exceeds the configured entry_point in points from the open price; the Price variant triggers when price crosses the user-specified entry_price. Exit conditions: Exits occur when price retraces to hit the trailing stop-loss, which locks in profit by following price at a distance of trailing_point points. Position sizing: The EA performs no position sizing or lot management whatsoever. Money management: There is no money management logic — no risk percentage calculation, no dynamic position sizing, no equity-based controls. Both variants share the same core mechanism: for BUY positions, the stop-loss is ratcheted upward as bid price rises; for SELL positions, the stop-loss is ratcheted downward as ask price falls, always maintaining a distance of trailing_point points from the current market price.

优势

  • 逻辑简单清晰，易于理解和配置，适合初学者使用
  • 提供两种触发方式（点数和价格），适应不同的交易场景和需求
  • 同时支持BUY和SELL仓位的移动止损管理，功能完整

劣势

  • PositionGetSymbol(idx)在循环中修改仓位列表时可能导致索引错位，应使用倒序循环
  • 没有检查PositionGetSymbol的返回值是否与当前图表品种匹配，会修改其他品种的仓位
  • entry_point和trailing_point默认值为0，用户忘记设置时EA不会生效且无任何提示
  • 没有对CTrade.PositionModify的返回值进行检查，修改失败时无错误处理
  • 未考虑止损修改的最小距离限制（StopsLevel），可能导致修改请求被服务器拒绝

改进建议

  • 使用倒序循环遍历仓位，并在PositionGetSymbol后检查是否匹配当前品种符号
  • 添加止损修改的最小距离限制检查（SymbolInfoInteger(SYMBOL_TRADE_STOPS_LEVEL)），并检查PositionModify返回值
  • 为参数设置合理的非零默认值，并在OnInit中验证参数有效性，无效时发出警告或返回INIT_FAILED

Strengths

  • Simple and clear logic, easy to understand and configure, suitable for beginners
  • Provides two trigger variants (point-based and price-based) to accommodate different trading scenarios
  • Supports trailing stop management for both BUY and SELL positions, functionally complete

Weaknesses

  • PositionGetSymbol(idx) in a forward loop can cause index misalignment when the position list changes; should use reverse iteration
  • Does not check if PositionGetSymbol matches the current chart symbol, so it may modify positions on other symbols
  • entry_point and trailing_point default to 0, and if the user forgets to set them, the EA silently does nothing with no warning
  • No return value check on CTrade.PositionModify, so failed modifications go unhandled and unnoticed
  • Does not account for the broker's minimum stop level (StopsLevel), which can cause modification requests to be rejected by the server

Improvements

  • Use reverse iteration for the position loop and check PositionGetSymbol return value against Symbol() to filter by current instrument
  • Add minimum stop distance validation using SymbolInfoInteger(SYMBOL_TRADE_STOPS_LEVEL) and check CTrade.PositionModify return values for error handling
  • Set sensible non-zero default values for parameters and validate them in OnInit, issuing warnings or returning INIT_FAILED on invalid input

风险评估 / Risk Assessment

总体 / Overall:LOW

风险点

  • 正向循环遍历仓位列表可能在仓位被删除时导致索引跳过，造成部分仓位未被管理
  • 未检查品种匹配可能意外修改其他品种仓位的止损
  • 未考虑止损级别限制可能导致修改请求频繁失败

Risk Assessment

Overall:LOW

Risk Points

  • Forward iteration through the position list can skip positions if one is closed during iteration, leaving some positions unmanaged
  • Missing symbol filter may inadvertently modify stop-losses on positions of other symbols on the same account
  • Ignoring the broker's stop level may cause frequent modification request failures
