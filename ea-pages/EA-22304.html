EA-22304 · Trend Following

Technical Trader

This EA uses a dual moving average crossover combined with a statistical support/resistance detection mechanism to generate buy and sell signals. It scans historical close prices to find levels where price has touched multiple times (resistance/support clusters) and enters trades when price is near these cluster levels and the MAs confirm trend direction. Positions are managed with fixed stop loss and take profit, executing only on new bars.

Strategy analysis

The strategy concept combines dual moving average crossover with a price cluster-based support/resistance detection mechanism. Entry conditions require: for buys, the short-period MA(25) must be above the long-period MA(30) and the current ask price must be near and above a resistance cluster level (within 0.0005); for sells, the short MA must be below the long MA and the current bid price must be near and below a support cluster level. Exit conditions rely entirely on fixed stop loss and take profit with no trailing stop or conditional exit logic. Position sizing uses the symbol's minimum lot size with no scaling or position accumulation logic. Money management attempts to check free margin but contains a critical bug—the margin variable is used uninitialized in the comparison, making the check effectively meaningless. Additionally, the hardcoded 0.0005 threshold is completely inappropriate for instruments like XAUUSD, the buy order uses a hardcoded magic number 15489 instead of the input parameter EA_Magic, and the 5/3 digit multiplier for SL/TP may not handle all broker configurations correctly.

Strengths

  • Uses a statistical price clustering method to identify support/resistance levels, which is conceptually innovative
  • Only executes trading logic on new bar formation, avoiding high-frequency duplicate signals
  • Has basic stop loss and take profit protection mechanism in place
  • Includes point value adaptation for 5/3 digit brokers
  • Contains data synchronization check logic during initialization for robustness

Weaknesses

  • The margin variable is used uninitialized, making the money management check completely ineffective and potentially allowing trades with insufficient margin
  • Buy orders use hardcoded magic number 15489 instead of the input parameter EA_Magic, creating inconsistency with sell orders
  • The 0.0005 price proximity threshold is hardcoded and completely unusable for high-value instruments like XAUUSD
  • The support/resistance scanning uses a 0.001 step loop which is extremely inefficient and the precision is inappropriate for all instruments
  • PositionSelect only checks for a single position per symbol, unable to handle multiple positions or hedging accounts
  • ORDER_FILLING_FOK is hardcoded but not supported by all brokers, which will cause order rejection
  • The statParam struct is defined but never used, representing dead code

Possible improvements

  • Fix the margin variable initialization issue by using OrderCalcMargin to properly calculate required margin before comparison
  • Replace the hardcoded price proximity threshold with an ATR-based or tick-value-adaptive parameter to work across all instruments
  • Unify buy and sell order magic numbers to use the EA_Magic input parameter, removing hardcoded values
  • Optimize the support/resistance scanning algorithm to avoid O(n²) loops, using histogram statistics or sorted clustering instead
  • Add automatic fill mode detection logic to select the appropriate ORDER_FILLING based on broker-supported modes

Risk assessment

Overall risk: High risk

  • Uninitialized margin variable makes money management check ineffective, potentially placing trades with insufficient margin
  • Hardcoded price proximity threshold is invalid for non-forex instruments, potentially generating incorrect signals
  • Inconsistent magic numbers between buy and sell orders cause position management confusion, potentially failing to identify EA-held positions
