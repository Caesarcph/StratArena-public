EA-275 · Trend Following

bobnaley

This EA opens long positions when the Moving Average is rising, price is above MA, and Stochastic is rising from below the oversold level. It opens short positions when the MA is falling, price is below MA, and Stochastic is declining from above the overbought level. Position sizing is dynamically calculated based on free margin with a maximum lot cap of 15.

Strategy analysis

This EA employs a combined Moving Average and Stochastic oscillator trend-following strategy. Entry conditions for longs require the MA to be consecutively rising over 3 bars, the Ask price above the current MA value, Stochastic rising and below the oversold level of 30. Entry for shorts requires MA consecutively declining, Bid below MA, and Stochastic declining above the overbought level of 70. However, there is a critical logic bug: the buy condition uses maVal[0]<maVal[1]<maVal[2], which actually checks for MA decreasing (since index 0 is the most recent value from CopyBuffer), contradicting the comment that says 'MA increases'. Exit relies entirely on fixed take-profit and stop-loss levels with no trailing stop or dynamic exit. Position sizing is calculated via Money_M() using free margin divided by 100000 multiplied by 50, clamped between 0.1 and 15 lots with variable decimal normalization. Money management requires at least 5000 in free margin and restricts to one position per symbol at a time. The StopLoss and TakeProfit input values appear to be in price units (0.0035 and 0.007) rather than points, which may cause issues depending on the symbol's price scale.

Strengths

  • Dual indicator filter (MA + Stochastic) reduces false breakout signals
  • Dynamic position sizing adapts lot size to account equity for some self-adaptation
  • Maximum lot cap (15) and minimum free margin requirement (5000) prevent excessive leverage
  • Single position per symbol restriction avoids pyramiding risk on the same direction

Weaknesses

  • Critical logic bug in MA direction check: maVal[0]<maVal[1] actually means MA is declining not rising, completely reversing the intended strategy logic
  • StopLoss and TakeProfit use price units instead of points, which may fail on symbols with different quote precision
  • The Lot input parameter (5) is completely unused as Money_M() overrides it, misleading the user
  • No new bar detection means signal logic runs every tick, risking redundant trade attempts
  • Trade execution result from PositionOpen is not checked, so failed orders go unnoticed
  • Fixed SL/TP values without ATR or volatility-based dynamic adjustment limit adaptability across instruments

Possible improvements

  • Fix the MA direction logic bug: buy condition should use maVal[0]>maVal[1]&&maVal[1]>maVal[2], sell condition should use maVal[0]<maVal[1]&&maVal[1]<maVal[2]
  • Convert SL/TP to point-based units with symbol tick size normalization, or use ATR-based dynamic calculation
  • Add new bar detection (e.g. compare current vs previous bar time) to avoid redundant per-tick signal evaluation and trade attempts
  • Check PositionOpen return value and handle trade failures, remove the unused Lot input parameter or integrate it into money management logic

Risk assessment

Overall risk: High risk

  • MA direction logic is reversed from strategy intent, potentially causing counter-trend entries: shorting in uptrends and buying in downtrends
  • SL/TP using absolute price values instead of points may produce extremely small or large stop ranges on 5-digit quotes or different instruments
  • Per-tick signal evaluation without new bar filtering could lead to duplicate position attempts during fast market moves due to PositionSelect latency
  • Unchecked trade execution results mean SL/TP levels rejected by the server would silently fail, leaving positions unprotected
