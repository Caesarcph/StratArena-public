摘要

该EA基于ATRStops和StepUpDown双指标趋势跟踪系统进行交易。当两个指标同时发出上升趋势信号时开多仓，同时发出下降趋势信号时开空仓，可选追踪止损和反向信号平仓功能。资金管理支持固定手数和基于风险百分比的动态手数。

策略分析

该EA采用双指标确认的趋势跟踪策略，入场条件要求ATRStops和StepUpDown两个指标同时发出同方向信号才开仓。ATRStops指标基于ATR倍数(Kv=2.5)计算动态止损通道，当价格突破通道上轨时信号为多头(+1)，突破下轨时为空头(-1)。StepUpDown指标通过快速SMA(周期2)和慢速SMMA(周期30)的交叉及背离判断趋势方向。出场条件包括：反向信号平仓(CloseByOppositeSignal)、追踪止损(TrailingStop)和StepUpDown反转时获利平仓。仓位管理支持固定手数和动态手数两种模式，动态模式根据账户余额、风险百分比和杠杆计算手数。止损和止盈通过CalculateSLTP函数根据资金风险和点值动态计算，TP为SL的TPvsSLRatio倍，最低止损为38个pip。同一小时内不重复开仓以避免过度交易。

Summary

This EA trades based on a dual-indicator trend following system combining ATRStops and StepUpDown indicators. It opens buy positions when both indicators signal uptrend and sell positions when both signal downtrend, with optional trailing stop and opposite-signal close functionality. Money management supports both fixed lot sizing and dynamic lot sizing based on risk percentage.

Strategy Analysis

This EA employs a dual-indicator confirmation trend following strategy where entry requires both ATRStops and StepUpDown indicators to signal the same direction simultaneously. The ATRStops indicator calculates a dynamic stop channel based on ATR multiples (Kv=2.5), signaling bullish (+1) when price breaks above the upper channel and bearish (-1) when breaking below the lower channel. The StepUpDown indicator determines trend direction through crossover and divergence between a fast SMA (period 2) and slow SMMA (period 30). Exit conditions include: close on opposite signal (CloseByOppositeSignal), trailing stop (TrailingStop), and profit close when StepUpDown reverses direction. Position sizing supports both fixed lot and dynamic lot modes, with the dynamic mode calculating lots based on account balance, risk percentage, and leverage. Stop loss and take profit are dynamically calculated via the CalculateSLTP function based on money risk and tick value, with TP set as a multiple (TPvsSLRatio) of SL and a minimum SL of 38 pips. A same-hour no-reentry rule prevents overtrading by checking if a position was already closed within the current hour.

优势

  • 双指标确认机制降低了假信号风险，要求ATRStops和StepUpDown同时确认才入场
  • 动态止损计算基于真实资金风险和点值，确保每笔交易的风险可控
  • 支持固定手数和动态手数两种资金管理模式，灵活适应不同交易需求
  • 同小时内不重复开仓的规则有效防止过度交易
  • ATRStops指标的自适应通道能根据市场波动性动态调整止损距离

劣势

  • 内存管理存在严重问题：每次OnTimer触发都new创建CTrade等对象但从不delete，导致持续内存泄漏
  • ModifySLTP函数中修改失败后直接break跳出循环，只能修改第一个符合条件的持仓
  • ClosePosition函数中PositionGetTicket调用位置不当，在循环外获取的持仓信息可能导致错误匹配
  • CalculateSLTP中leveragerisk计算方式不合理，将杠杆除以100并取整作为风险乘数，缺乏理论依据
  • 代码中存在冗余的iOpen/iHigh/iLow/iClose/iTime函数定义但未被使用

改进建议

  • 修复内存泄漏：将CTrade等对象改为OnInit中创建并复用，或在OnTimer结束时delete释放内存
  • 移除ModifySLTP中的break语句，允许遍历所有持仓进行修改，并将OrderSend移到条件判断外统一处理
  • 优化StepUpDown指标逻辑，当前循环中ups/dns变量被反复覆盖，只有最后一次迭代的值生效，可能不符合预期
  • 添加点差过滤和最大持仓数量限制，防止在高点差环境下频繁交易和过度持仓

Strengths

  • Dual-indicator confirmation reduces false signal risk by requiring both ATRStops and StepUpDown to agree before entry
  • Dynamic SL calculation based on actual money risk and tick value ensures controllable risk per trade
  • Supports both fixed lot and dynamic lot money management modes for flexible trading needs
  • Same-hour no-reentry rule effectively prevents overtrading
  • ATRStops adaptive channel dynamically adjusts stop distance based on market volatility

Weaknesses

  • Critical memory leak: new CTrade/CSymbolInfo/CPositionInfo/CAccountInfo objects created every OnTimer call but never deleted
  • ModifySLTP breaks after first modification attempt, only modifying one position per call instead of iterating all
  • ClosePosition has misplaced PositionGetTicket call that may match incorrect positions due to stale position info
  • CalculateSLTP leveragerisk calculation (leverage/100 rounded) lacks theoretical justification and may produce misleading stop distances
  • Redundant iOpen/iHigh/iLow/iClose/iTime function definitions exist but are never called in the code

Improvements

  • Fix memory leak: either create CTrade etc. objects once in OnInit and reuse, or delete them at the end of each OnTimer call
  • Remove break statement in ModifySLTP to allow iterating all positions for modification, and unify OrderSend handling outside conditional blocks
  • Fix StepUpDown indicator logic where ups/dns variables are repeatedly overwritten in the loop, making only the last iteration's value effective, which may not match intended behavior
  • Add spread filter and maximum position count limit to prevent frequent trading in high-spread environments and overexposure

风险评估 / Risk Assessment

总体 / Overall:MEDIUM

风险点

  • 每次OnTimer触发都创建新对象但不释放，长时间运行会导致严重内存泄漏和性能下降
  • 追踪止损模式下修改失败后直接break，可能导致部分持仓无法及时调整止损
  • 动态手数计算中Opentotal变量使用了不直观的取值逻辑（最小为5），可能在高持仓时低估风险
  • 使用Sleep(1000)在开仓后等待1秒再平仓，在快速行情中可能导致平仓价格滑点

Risk Assessment

Overall:MEDIUM

Risk Points

  • Memory leak from creating new objects every OnTimer without deletion causes severe performance degradation over long runtimes
  • Trailing stop modification breaks after first attempt, potentially leaving some positions without updated stops
  • Dynamic lot calculation uses non-intuitive Opentotal logic (minimum 5) that may underestimate risk with high position counts
  • Using Sleep(1000) between open and close operations can cause slippage in fast-moving markets
