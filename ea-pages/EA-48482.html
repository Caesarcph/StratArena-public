摘要

该EA使用两个ONNX神经网络模型——主模型和元模型——生成EURUSD的二元分类交易信号。主模型预测交易方向（买入/卖出），元模型作为置信度过滤器，仅在其输出超过阈值时允许交易。它以固定止损/止盈和基于风险比例的仓位管理执行交易。

策略分析

策略概念基于双模型机器学习架构：主模型输出分类概率作为方向信号，元模型输出概率作为信号置信度过滤。入场条件为：当元模型概率大于meta_threshold时，若主模型概率小于(1-main_threshold)则买入，若大于main_threshold则卖出；买入信号低于0.5意味着模型预测上涨概率更高，卖出信号高于0.5则预测下跌概率更高。出场条件为：当元模型确认时，若持有多头且主模型信号大于main_threshold则平多仓，若持有空头且主模型信号小于(1-main_threshold)则平空仓。仓位管理通过MaximumRisk参数按账户可用保证金比例计算手数，也支持固定手数ManualLot，并有最小/最大手数限制和手数步长规范化。资金管理使用CheckMoneyForTrade函数在下单前检查保证金是否充足，防止因资金不足导致订单失败。

Summary

This EA uses two ONNX neural network models — a main model and a meta-model — to generate binary classification signals for EURUSD trading. The main model predicts trade direction (buy/sell) while the meta-model acts as a confidence filter, only allowing trades when its output exceeds a threshold. It executes trades with fixed SL/TP and position sizing based on risk percentage.

Strategy Analysis

The strategy concept is built on a dual-model machine learning architecture: the main model outputs classification probabilities as directional signals, while the meta-model outputs probabilities as a confidence filter for signal quality. Entry conditions: when the meta-model probability exceeds meta_threshold, a buy is triggered if the main model probability is below (1-main_threshold), and a sell is triggered if it exceeds main_threshold; a buy signal below 0.5 indicates the model predicts higher upward probability, while a sell signal above 0.5 predicts higher downward probability. Exit conditions: when the meta-model confirms, existing long positions are closed if the main model signal exceeds main_threshold, and short positions are closed if the signal falls below (1-main_threshold). Position sizing calculates lot size based on the MaximumRisk parameter as a fraction of account free margin, with support for fixed ManualLot, and enforces min/max volume limits plus volume step normalization. Money management uses the CheckMoneyForTrade function to verify sufficient margin before placing orders, preventing order failures due to insufficient funds.

优势

  • 双模型架构设计合理，元模型作为置信度过滤器能有效减少低质量信号的交易
  • 使用ONNX模型进行推理，能够捕捉非线性市场特征，比传统技术指标更有潜力
  • 包含完整的资金管理检查（保证金验证、手数规范化、最小/最大手数限制）

劣势

  • 无限重试循环（do-while res==-1）可能导致无限阻塞，缺少最大重试次数限制
  • countOrders函数使用PositionSelect而非PositionGetTicket遍历，在多持仓时会重复选择同一持仓导致计数错误
  • 止损止盈固定为2000点且无追踪止损机制，无法根据市场波动动态调整
  • 元模型和主模型使用相同特征时缺乏正交性验证，可能导致过滤效果有限

改进建议

  • 为do-while重试循环添加最大重试次数限制和超时机制，避免无限阻塞
  • 修复countOrders函数，使用PositionGetTicket(k)正确遍历持仓而非PositionSelect
  • 添加spread过滤和滑点控制，防止在高点差环境下开仓
  • 考虑添加追踪止损或动态止损机制，根据ATR等波动指标调整止损距离

Strengths

  • Dual-model architecture is well-designed, with the meta-model acting as a confidence filter that effectively reduces trades on low-quality signals
  • ONNX model inference can capture non-linear market features, offering more potential than traditional technical indicators
  • Includes comprehensive money management checks (margin verification, lot normalization, min/max volume limits)

Weaknesses

  • Infinite retry loops (do-while res==-1) can cause indefinite blocking without a maximum retry count limit
  • countOrders uses PositionSelect instead of PositionGetTicket for iteration, which can repeatedly select the same position and cause incorrect counts with multiple positions
  • Fixed SL/TP of 2000 points with no trailing stop mechanism prevents dynamic adjustment based on market volatility
  • No orthogonality verification between meta-model and main model features, potentially limiting the filtering effectiveness

Improvements

  • Add maximum retry count and timeout mechanism to do-while retry loops to prevent indefinite blocking
  • Fix countOrders function to use PositionGetTicket(k) for proper position iteration instead of PositionSelect
  • Add spread filter and slippage control to prevent opening positions in high-spread environments
  • Consider adding trailing stop or dynamic stop-loss mechanism adjusted by volatility indicators like ATR

  • 无点差过滤，在流动性低的时段可能以较大滑点成交
