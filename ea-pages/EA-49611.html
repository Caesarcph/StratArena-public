摘要

该EA扫描所有持仓，按票号降序排列后，在图表上显示第N笔交易的详细信息。支持按魔术号和交易品种进行可选过滤，通过Comment()函数在图表上打印交易信息。

策略分析

该EA并非交易策略，而是一个持仓查询工具。其核心功能是遍历当前所有持仓，根据用户设定的魔术号和交易品种过滤器进行筛选，将符合条件的持仓信息存入结构体数组中。然后通过冒泡排序按票号降序排列所有持仓，最终根据用户指定的索引（TRADE_INDEX）从排序后的数组中提取对应交易的信息并显示在图表上。该工具不执行任何开仓、平仓或修改操作，仅用于监控和展示持仓状态。排序算法使用简单的冒泡排序，效率较低但不影响功能正确性。

Summary

This EA scans all open positions and displays the details of the Nth trade from the sorted list on the chart. It supports optional filtering by magic number and symbol, sorts positions by ticket number in descending order, and prints trade information via the Comment() function.

Strategy Analysis

This EA is not a trading strategy but a position inquiry utility. Its core functionality iterates through all current open positions, filtering them based on user-configured magic number and symbol filters, and stores matching positions into a struct array. It then sorts all positions by ticket number in descending order using a bubble sort algorithm, and finally extracts the trade at the user-specified index (TRADE_INDEX) from the sorted array to display its details on the chart. The tool does not execute any opening, closing, or modification operations — it is purely for monitoring and displaying position status. The sorting algorithm uses a simple bubble sort which is inefficient but does not affect functional correctness. There is no entry or exit logic since no trades are placed.

优势

  • 支持按魔术号和交易品种灵活过滤持仓
  • 结构化存储交易详情，便于扩展和调用
  • 以图表注释方式直观展示持仓信息，使用方便

劣势

  • 冒泡排序效率低，持仓数量多时性能不佳
  • 缺少边界检查，TRADE_INDEX越界时会导致数组越界错误
  • 每次tick都执行全量扫描和排序，缺乏节流机制造成不必要的资源消耗
  • MAGICNUMBER未声明为input变量，无法在参数面板中修改

改进建议

  • 将MAGICNUMBER改为input变量以便在参数面板中配置
  • 添加边界检查防止数组越界，并增加定时器或新K线检测减少执行频率

Strengths

  • Supports flexible filtering by magic number and trading symbol
  • Uses structured storage for trade details, easy to extend and integrate
  • Displays position information intuitively on chart via Comment()

Weaknesses

  • Bubble sort is inefficient and performs poorly with many positions
  • Missing boundary checks — TRADE_INDEX out of range causes array out-of-bounds errors
  • Performs full scan and sort on every tick with no throttling, causing unnecessary resource consumption
  • MAGICNUMBER is not declared as an input variable, making it unmodifiable from the parameter panel

Improvements

  • Change MAGICNUMBER to an input variable so it can be configured from the parameter panel
  • Add boundary checks to prevent array out-of-bounds errors, and implement a timer or new bar check to reduce execution frequency
