摘要

该EA在每个tick处放置BuyStop和SellStop挂单，形成突破式入场系统。它包含移动止损功能来管理持仓，将止损移至保本后跟踪止损。然而，TrailingStop()函数从未在OnTick()中被调用，使其完全无法运行。

策略分析

策略概念是基于突破入场，在每个tick检查是否存在买单和卖单挂单，若不存在则在当前Ask价上方放置BuyStop挂单，在当前Bid价下方放置SellStop挂单，形成双向突破捕捉系统。入场条件为当前无同类型挂单且手数和资金检查通过，订单有效期为当日结束。出场条件依赖StopLoss和TakeProfit设置，以及TrailingStop函数实现保本止损和跟踪止损——但TrailingStop从未被调用。仓位管理为固定0.01手，无任何动态调整机制。资金管理通过CheckMoneyForTrade检查可用保证金是否充足，并有手数合规性验证。该EA存在严重逻辑缺陷：TrailingStop未被调用、重复的资金检查、循环索引越界（PositionsTotal和OrdersTotal应从Total-1开始）、以及第二阶段止损计算错误（bid-ValidBuy和ask+ValidSell）。

Summary

This EA places BuyStop and SellStop pending orders at the current Ask/Bid prices on every tick, creating a breakout-style entry system. It includes a trailing stop function to manage open positions by moving the stop loss to breakeven and then trailing it. However, the TrailingStop() function is never called from OnTick(), making it completely non-functional.

Strategy Analysis

The strategy concept is a breakout entry system that places BuyStop and SellStop pending orders at the current Ask and Bid prices on every tick, capturing price movement in either direction. Entry conditions require no existing pending order of the same type (checked by comment string matching), valid volume, and sufficient free margin. Exit conditions rely on fixed StopLoss and TakeProfit values set at order creation, plus a trailing stop mechanism that moves SL to breakeven once profit exceeds the trailing threshold. Position sizing is fixed at 0.01 lots with no dynamic adjustment or scaling. Money management checks free margin via OrderCalcMargin before placing orders, and validates lot size against broker minimum/maximum/step requirements. Critical flaws exist: TrailingStop() is defined but never called from OnTick(), duplicate margin checks appear on lines 60-70, loop indexing is off-by-one (i starts at Total instead of Total-1), and the second-stage SL calculations for already-trailing positions are mathematically incorrect (e.g., bid - ValidBuy subtracts a price from another price, producing nonsense).

优势

  • 双向挂单设计可捕捉多空两个方向的突破行情
  • 包含资金检查和手数合规性验证，有基本的风控意识
  • 挂单有效期限制为当日，避免过夜持仓风险
  • 订单注释机制便于识别和管理自身挂单

劣势

  • TrailingStop()函数从未被调用，移动止损功能完全失效
  • 每个tick都尝试下挂单，无新bar检查，会频繁产生无效订单请求
  • 循环索引从Total开始而非Total-1，导致越界访问
  • 第二阶段跟踪止损计算错误：bid-ValidBuy和ask+ValidSell是价格减价格，结果无意义
  • 重复的资金检查代码（60-70行重复了56-64行的逻辑）
  • 固定0.01手无任何仓位优化机制

改进建议

  • 在OnTick()中调用TrailingStop()函数，使移动止损功能生效
  • 添加新bar检查机制，避免每个tick重复下单
  • 修复循环索引为i=Total-1，修复第二阶段止损计算逻辑
  • 将固定手数改为可配置参数，并考虑基于ATR或风险的动态仓位管理
  • 添加点差过滤和交易时段过滤，避免在高点差或低流动性时段交易

Strengths

  • Dual pending order design captures breakout moves in both directions
  • Includes margin check and volume validation with basic risk awareness
  • Pending order expiration limited to current day, avoiding overnight risk
  • Order comment mechanism facilitates identification and management of own pending orders

Weaknesses

  • TrailingStop() function is never called from OnTick(), making the trailing feature completely non-functional
  • Attempts to place pending orders on every tick without new bar check, causing excessive invalid order requests
  • Loop indexing starts at Total instead of Total-1, causing out-of-bounds access
  • Second-stage trailing SL calculations are mathematically wrong: bid-ValidBuy and ask+ValidSell subtract/add prices to prices producing nonsensical values
  • Duplicate margin check code (lines 60-70 repeat logic from lines 56-64)
  • Fixed 0.01 lot size with no position sizing optimization

Improvements

  • Call TrailingStop() from OnTick() to activate the trailing stop feature
  • Add new bar check to prevent repeated order attempts on every tick
  • Fix loop index to start at Total-1 and fix second-stage SL calculation logic
  • Make lot size a configurable input parameter and consider ATR-based or risk-based dynamic position sizing
  • Add spread filter and trading session filter to avoid high-spread or low-liquidity periods

风险评估

总体:HIGH

风险点

  • 无新bar检查导致每个tick尝试下单，可能触发broker限频或产生大量无效请求
  • 移动止损功能完全失效，持仓只能靠初始止损保护
  • 双向挂单同时成交时将形成对冲持仓，加倍保证金占用且无额外风控
  • 止损计算存在数学错误，可能在跟踪阶段设置错误的止损位

  • Trailing stop feature is completely non-functional, positions only protected by initial SL
  • Dual pending orders filling simultaneously creates hedged positions, doubling margin usage without additional risk control
  • SL calculation contains mathematical errors that may set incorrect stop levels during trailing phase
