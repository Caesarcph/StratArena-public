摘要

这是一个马丁格尔风格的网格EA，基于RSI和近期价格方向开仓，当现有仓位亏损超过动态点数阈值时，以指数递增的手数加仓摊平。它包含多种出场机制如追踪止损、净值止损、CCI止损和时间止损，但默认缺少强制硬止损。

策略分析

该EA的核心策略是马丁格尔加仓摊平：首次入场依赖RSI指标和最近两根K线的价格方向判断，RSI低于30且价格上涨时做多，RSI高于70且价格下跌时做空。当已有仓位亏损超过动态计算的点数阈值时，EA会按LotExponent的幂次递增手数开立同方向的新仓位进行摊平。动态点数阈值通过最近Glubina根K线的最高价与最低价之差除以DEL系数计算，并受DefaultPips上下限约束。出场方面，所有仓位共享基于加权均价计算的统一止盈，另有可选的追踪止损、CCI极端值平仓、净值回撤止损和超时平仓四种保护机制。仓位管理采用指数递增手数（Lots × LotExponent^(N+1)），这属于典型的马丁格尔资金管理方式，在连续亏损时仓位会急剧放大。

Summary

A martingale-style grid EA that opens an initial position based on RSI and recent price direction, then adds averaging positions with exponentially increasing lot sizes when the existing position goes into loss beyond a dynamic pip threshold. It includes multiple exit mechanisms including trailing stop, equity stop, CCI stop, and time-based stop, but lacks a mandatory hard stop-loss by default.

Strategy Analysis

The EA's core strategy is martingale-style averaging down: the initial entry relies on RSI readings and the price direction of the last two bars — going long when RSI is below 30 and price is rising, going short when RSI exceeds 70 and price is falling. When an existing position's loss exceeds a dynamically calculated pip threshold, the EA opens a new same-direction position with lot size multiplied by LotExponent raised to the power of the current position count, effectively averaging down the entry price. The dynamic pip threshold is derived from the High-Low range of the last Glubina bars divided by the DEL factor, bounded by DefaultPips/DEL (lower) and DefaultPips*DEL (upper). For exits, all positions share a common take-profit calculated from the weighted average price, with four optional protective mechanisms: trailing stop, CCI extreme level exit, equity drawdown stop, and time-based closure. Position sizing uses exponential lot increase (Lots × LotExponent^(N+1)), which is classic martingale money management that causes position sizes to escalate dramatically during consecutive losses.

优势

  • 动态点数阈值根据市场波动自适应调整，比固定间距更灵活
  • 提供多种出场保护机制（追踪止损、净值止损、CCI止损、时间止损），风险控制选项丰富
  • 代码结构清晰，模块化程度高，使用面向对象库封装交易状态和环境
  • 通过加权均价统一计算止盈，确保所有仓位整体盈利时才平仓

劣势

  • 马丁格尔加仓策略在极端行情下可能导致仓位指数级放大，存在爆仓风险
  • 默认关闭所有止损保护（UseStopLoss、UseEquityStop、UseTrailingStop、UseCCIStop均为false），裸奔风险极高
  • 追踪止损对空头仓位的逻辑有bug：stopLevel应小于currStopLoss才修改，但代码中使用了与多头相同的>比较
  • 缺少点差过滤和交易时间过滤，在流动性差或点差大的时段容易遭受滑点损失
  • 最大持仓数10配合1.4倍手数递增，在连续亏损后手数可增至0.1×1.4^11≈1.58，是初始手的15.8倍

改进建议

  • 修复空头追踪止损的比较逻辑bug，将stopLevel>currStopLoss改为stopLevel<currStopLoss
  • 默认启用至少一种止损保护机制（如净值止损），避免用户在无保护状态下运行
  • 增加点差过滤和交易时段过滤，避免在高点差和低流动性时段交易
  • 限制最大总仓位占账户净值比例，防止单品种过度集中风险

Strengths

  • Dynamic pip threshold adapts to market volatility using recent High-Low range, providing more flexible grid spacing than fixed intervals
  • Offers multiple exit protection mechanisms (trailing stop, equity stop, CCI stop, time-based stop) giving traders flexible risk control options
  • Clean code structure with good modularization using object-oriented libraries for trade state and environment management
  • Unified take-profit based on weighted average price ensures all positions close only when the overall basket is profitable

Weaknesses

  • Martingale position sizing causes exponential lot escalation during adverse moves, creating catastrophic blow-up risk in trending markets
  • All stop-loss protections are disabled by default (UseStopLoss, UseEquityStop, UseTrailingStop, UseCCIStop all false), leaving positions completely unprotected out of the box
  • Trailing stop logic for short positions contains a bug: stopLevel comparison uses > instead of <, so trailing will never correctly ratchet down for shorts
  • No spread filter or trading session filter, making the EA vulnerable to slippage and wide spreads during low-liquidity periods
  • With MaxTrades=10 and LotExponent=1.4, the final lot size reaches 0.1×1.4^11≈1.58, which is 15.8x the initial lot — massive exposure concentration

Improvements

  • Fix the trailing stop comparison bug for short positions: change stopLevel>currStopLoss to stopLevel<currStopLoss so the stop correctly ratchets down
  • Enable at least one stop-loss protection by default (e.g., equity stop) to prevent users from running unprotected
  • Add spread filter and trading session filter to avoid trading during high-spread or low-liquidity periods
  • Add maximum total exposure as a percentage of account equity to prevent over-concentration in a single instrument
