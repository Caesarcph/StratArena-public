摘要

该EA在图表上提供一个可视化的止盈/止损面板，允许交易者手动为现有持仓设置止盈和止损价格水平。当市场价格达到设定的止盈或止损水平时，EA会自动通过执行反向市价单来平仓。它不会自行产生交易信号或独立开仓。

策略分析

该EA的策略概念是作为已有持仓的辅助管理工具，通过图表面板手动设置虚拟止盈止损价位。入场条件方面，EA本身不进行入场，而是依赖用户已有持仓，仅在检测到有未平仓仓位时才允许激活TP/SL监控。出场条件为当当前价格触及用户设定的止盈或止损价格时，EA执行一笔反向市价单来平掉原有仓位——对于买单触及TP时卖出，触及SL时也卖出；对于卖单反之亦然。仓位管理方面，平仓时使用固定的手数（LotSize参数），而非根据原始仓位手数自动匹配，这可能导致部分平仓或过度平仓的问题。资金管理方面，EA没有任何资金管理逻辑，不计算风险比例、不检查账户余额、不设置最大亏损限制。止盈止损并非通过服务器端挂单实现，而是通过客户端Ontick轮询检测价格，这存在断连漏单的风险。

Summary

This EA provides a visual TP/SL panel on the chart that allows traders to manually set take-profit and stop-loss price levels for an existing open position. When the market price reaches the specified TP or SL level, the EA automatically closes the position by executing a reversing market order. It does not generate its own trading signals or open new positions independently.

Strategy Analysis

The strategy concept of this EA is to serve as an auxiliary management tool for existing positions, allowing users to manually set virtual take-profit and stop-loss levels via a chart panel. Regarding entry conditions, the EA does not initiate entries itself; it relies on the user having an existing open position and only allows TP/SL monitoring activation when an open position is detected. The exit condition is that when the current price reaches the user-specified TP or SL price, the EA executes a reversing market order to close the original position — selling when a buy position hits TP or SL, and buying when a sell position hits TP or SL. For position sizing, the closing trade uses a fixed lot size (LotSize parameter) rather than automatically matching the original position's volume, which can lead to partial close or over-close issues. There is no money management logic whatsoever — no risk percentage calculation, no account balance check, and no maximum loss limit. The TP/SL is not implemented via server-side pending orders but through client-side OnTick polling, which carries the risk of missed executions during disconnections.

优势

  • 提供直观的图表面板界面，用户可通过点击图表设置止盈止损价格，操作便捷
  • 支持仅设置TP、仅设置SL或同时设置TP/SL三种模式，灵活性较好
  • 具有运行前验证逻辑，检查持仓状态和TP/SL合理性（如TP是否已被触及），防止无效设置

劣势

  • 止盈止损通过客户端OnTick轮询实现而非服务器端挂单，断连或EA停止运行时止盈止损将失效，存在重大风险
  • 平仓手数使用固定LotSize参数而非自动匹配原始持仓手数，可能导致平仓手数不正确
  • GetBarPrice函数中'close'价格实际返回的是bid价格而非真正的收盘价，函数命名和逻辑存在误导
  • ObjectFind返回值使用有误——ObjectFind返回0表示找到对象，但代码中用if(ObjectFind(...))来判断对象存在，逻辑恰好相反
  • ORDER_FILLING_FOK填充模式可能在某些经纪商处不被支持，缺乏对填充模式兼容性的检查

改进建议

  • 应使用服务器端止损挂单（SL/TP字段或止损限价单）替代客户端轮询，确保断连时止盈止损仍然有效
  • 平仓时应自动读取原始持仓手数而非使用固定参数，确保完全平仓
  • 应修复ObjectFind的返回值判断逻辑，并增加对订单填充模式的自动适配

Strengths

  • Provides an intuitive chart panel interface where users can set TP/SL prices by clicking on the chart, making operation convenient
  • Supports three modes — TP only, SL only, or both TP and SL — offering good flexibility
  • Includes pre-run validation logic that checks position status and TP/SL validity (e.g., whether TP has already been reached), preventing invalid setups

Weaknesses

  • TP/SL is implemented via client-side OnTick polling instead of server-side pending orders, meaning TP/SL will fail if the connection drops or the EA stops — a significant risk
  • The closing trade uses a fixed LotSize parameter instead of automatically matching the original position's volume, which can result in incorrect closing lot sizes
  • The GetBarPrice function returns bid price when 'close' is requested, which is misleading — the function name and logic don't match
  • ObjectFind return value is used incorrectly — ObjectFind returns 0 when an object is found, but the code uses if(ObjectFind(...)) to check existence, inverting the logic
  • ORDER_FILLING_FOK filling mode may not be supported by all brokers, and there is no compatibility check for the filling mode

Improvements

  • Should use server-side stop orders (SL/TP fields or stop-limit orders) instead of client-side polling to ensure TP/SL remains effective during disconnections
  • Should automatically read the original position's volume when closing instead of using a fixed parameter, ensuring complete position closure
  • Should fix the ObjectFind return value check logic and add automatic adaptation for order filling mode compatibility

风险点

  • 客户端轮询止盈止损，网络断连或EA崩溃时止盈止损完全失效
  • 平仓手数不自动匹配原始持仓，可能只部分平仓导致风险敞口
  • 无滑点保护、无点差过滤、无重试机制，订单失败后仅报警而不重试

Risk Assessment

Overall:MEDIUM

Risk Points

  • Client-side polling for TP/SL means complete TP/SL failure during network disconnection or EA crash
  • Closing lot size doesn't auto-match the original position, potentially leaving residual risk exposure from partial closes
  • No slippage protection, no spread filter, and no retry mechanism — order failures only generate alerts without retry attempts
