摘要

该EA检测冲动蜡烛形态（高成交量、强实体、方向性收盘）并在冲动方向入场交易，使用基于ATR的止损/止盈以及自适应的时段/成交量/波动率过滤器。它配备了智能追踪止损系统，包含保本、固定ATR、动态ATR和混合模式来管理持仓。

策略分析

策略概念基于'冲动延续'——当市场出现异常放量的方向性蜡烛时，认为动量将延续并顺势入场。入场条件要求当前bar的成交量超过均量的自适应倍数（伦敦/纽约时段0.9倍，亚洲/太平洋时段1.3倍）、实体比率超过自适应阈值、收盘位置在蜡烛范围的60%以上、范围扩展大于前一根bar的5%，且价格必须与50周期MA方向一致（斜率确认）。出场条件包括ATR倍数止损（1.2倍）和止盈（1.8倍），以及四种追踪止损模式：无追踪、保本、固定ATR追踪、动态ATR追踪和混合模式。仓位管理基于账户余额的风险百分比（默认0.1%）计算手数。资金管理包含最低净值检查、保证金水平检查、亏损后降低风险比例的功能，以及61.8%斐波那契回撤的冲动衰减监控机制。此外还有自适应时段过滤、低成交量过滤和点差过滤等安全机制。

Summary

This EA detects impulse candle formations (high volume, strong body, directional close) and enters trades in the impulse direction, using ATR-based stop loss/take profit and adaptive session/volume/volatility filters. It features a smart trailing stop system with breakeven, fixed ATR, dynamic ATR, and hybrid modes to manage open positions.

Strategy Analysis

The strategy concept is based on 'impulse continuation' — when the market produces an abnormally high-volume directional candle, the EA assumes momentum will persist and enters in that direction. Entry conditions require the current bar's volume to exceed an adaptive multiple of the average (0.9x in London/NY sessions, 1.3x in Asian/Pacific), body ratio above an adaptive threshold, close position above 60% of the candle range, range expansion greater than 5% over the previous bar, and price must align with the 50-period MA direction (slope confirmation). Exit conditions include ATR-multiplier stop loss (1.2x) and take profit (1.8x), plus four trailing stop modes: no trailing, breakeven only, fixed ATR trailing, dynamic ATR trailing, and hybrid. Position sizing is calculated based on risk percentage of account balance (default 0.1%). Money management includes minimum equity check, margin level check, post-loss risk reduction feature, and a 61.8% Fibonacci retracement impulse decay monitoring mechanism. Additional safety mechanisms include adaptive session filtering, low volume filtering, and spread filtering.

优势

  • 多层级自适应过滤系统（时段、成交量、波动率、点差）有效减少虚假信号
  • 完整的资金管理体系：净值检查、保证金水平检查、亏损后风险降低、ATR止损
  • 四种追踪止损模式（保本/固定ATR/动态ATR/混合）提供灵活的持仓管理
  • 61.8%斐波那契回撤衰减监控比简单的bar计数更科学地判断冲动失效
  • MA斜率+位置双重趋势确认防止逆势入场

劣势

  • IsGoodTradingSession()函数内部每次调用都创建iATR句柄（handle_long）但从未释放，会造成严重的资源泄漏
  • CheckTradingConditions()中存在重复检查：第6步和第7步重复检查了点差和交易时段
  • 大量注释掉的替代代码块（三个ProcessNewBar版本、两个IsImpulseDecayed版本等）使代码臃肿难维护
  • 缺少对已有持仓的检查逻辑，可能重复开仓导致过度暴露
  • 冲动衰减检查中使用的iOpen基于start_bar索引，但start_bar在ProcessNewBar中递增，可能导致引用错误的bar数据

改进建议

  • 修复IsGoodTradingSession()中的指标句柄泄漏：将长周期ATR句柄移至OnInit()创建并在OnDeinit()释放
  • 删除所有注释掉的替代代码块，使用版本控制系统管理代码变体，保持源文件整洁
  • 添加持仓检查逻辑，防止同一冲动信号重复开仓，限制同方向最大持仓数
  • 在CheckTradingConditions()中移除重复的点差和时段检查（第6-7行与第3-5行重复）
  • 为InpUseVolatilityAdjust参数添加实际实现逻辑，当前声明了但未在追踪计算中使用

Strengths

  • Multi-layer adaptive filtering system (session, volume, volatility, spread) effectively reduces false signals
  • Complete money management system: equity check, margin level check, post-loss risk reduction, ATR-based stop loss
  • Four trailing stop modes (breakeven/fixed ATR/dynamic ATR/hybrid) provide flexible position management
  • 61.8% Fibonacci retracement decay monitoring is more scientific than simple bar counting for determining impulse failure
  • MA slope + positional dual trend confirmation prevents counter-trend entries

Weaknesses

  • IsGoodTradingSession() creates an iATR handle (handle_long) on every call but never releases it, causing serious resource leaks
  • Duplicate checks in CheckTradingConditions(): steps 6 and 7 redundantly re-check spread and trading session
  • Large blocks of commented-out alternative code (three ProcessNewBar versions, two IsImpulseDecayed versions, etc.) bloat the codebase and hurt maintainability
  • Missing check for existing open positions, which could lead to duplicate entries and overexposure
  • Impulse decay check uses iOpen based on start_bar index, but start_bar is incremented in ProcessNewBar, potentially referencing wrong bar data

Improvements

  • Fix the indicator handle leak in IsGoodTradingSession(): move the long-period ATR handle creation to OnInit() and release it in OnDeinit()
  • Remove all commented-out alternative code blocks, use version control to manage code variants, keep source files clean
  • Add position checking logic to prevent duplicate entries from the same impulse signal, limit max positions per direction
  • Remove duplicate spread and session checks in CheckTradingConditions() (lines 6-7 duplicate lines 3-5)
  • Implement actual logic for InpUseVolatilityAdjust parameter, which is declared but not used in trailing calculations
