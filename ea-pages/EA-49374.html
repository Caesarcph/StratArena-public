Last Closed Trade

This EA monitors the account's deal history and displays information about the last closed deal on the chart via Comment(). It retrieves the last deal's profit, symbol, and type, then outputs them as an on-chart overlay. It does not open, close, or manage any trades.

摘要

该EA监控账户的历史成交记录，并通过Comment()函数在图表上显示最后一笔已平仓成交的信息。它获取最近一笔成交的利润、交易品种和类型，并将其作为图表叠加层输出。该EA不执行任何开仓、平仓或仓位管理操作。

策略分析

此EA并非交易策略，而是一个纯粹的信息监控工具。它没有任何入场条件或出场条件，因为根本不执行交易操作。仓位管理和资金管理在此EA中完全不适用。其核心逻辑是在每个tick调用CheckLastClosed()函数，从当日起始时间到当前时间的历史成交记录中获取最后一笔成交的票据号，然后读取该成交的利润、品种和方向信息。需要注意的是，代码中存在明显的逻辑错误：当成交类型为BUY时，标签被标记为'Sell Trade'，而成交类型为SELL时，标签被标记为'Buy Trade'，买卖方向的显示与实际成交类型完全相反。此外，该EA使用HistoryOrderGetString来获取品种信息，但实际上应该使用HistoryDealGetString，因为Ticket是成交票据而非订单票据。每个tick都重复执行历史查询和Comment输出，没有做任何防重复或新交易检测，效率较低。

Summary

This EA monitors the account's deal history and displays information about the last closed deal on the chart via Comment(). It retrieves the last deal's profit, symbol, and type, then outputs them as an on-chart overlay. It does not open, close, or manage any trades.

Strategy Analysis

This EA is not a trading strategy but a purely informational monitoring tool. It has no entry or exit conditions since it does not execute any trading operations whatsoever. Position sizing and money management are entirely inapplicable to this EA. Its core logic calls CheckLastClosed() on every tick, which selects deal history from the day's start time to the current time, retrieves the last deal's ticket number, and reads that deal's profit, symbol, and direction. A critical logic bug exists: when the deal type is BUY, it is labeled 'Sell Trade', and when the deal type is SELL, it is labeled 'Buy Trade' — the displayed direction is reversed from the actual deal type. Additionally, the code uses HistoryOrderGetString to retrieve the symbol, but it should use HistoryDealGetString since Ticket is a deal ticket, not an order ticket. The EA redundantly re-executes history queries and Comment output on every tick without any new-deal detection or deduplication, making it inefficient.

优势

  • 代码非常简洁，易于阅读和理解
  • 作为信息展示工具，不涉及任何交易风险
  • 使用Comment()在图表上直接输出信息，方便用户实时查看

劣势

  • 买卖方向标签完全颠倒，BUY显示为Sell Trade，SELL显示为Buy Trade，属于严重逻辑错误
  • 使用HistoryOrderGetString获取品种信息而非HistoryDealGetString，在成交票据上调用订单函数可能导致返回空值或错误数据
  • 每个tick都重复查询历史和刷新Comment输出，没有检测是否有新成交，效率低下且可能闪烁

改进建议

  • 修正买卖方向标签的逻辑，BUY应对应'Buy Trade'，SELL应对应'Sell Trade'
  • 将HistoryOrderGetString改为HistoryDealGetString以正确获取成交品种信息
  • 添加新成交检测机制，仅在最后一笔成交变化时才更新输出，避免每个tick重复查询

Strengths

  • Code is very concise and easy to read and understand
  • As an informational display tool, it involves zero trading risk
  • Uses Comment() to output information directly on the chart for convenient real-time viewing

Weaknesses

  • Buy/sell direction labels are completely reversed — BUY displays as 'Sell Trade' and SELL displays as 'Buy Trade', which is a critical logic bug
  • Uses HistoryOrderGetString to get the symbol instead of HistoryDealGetString; calling an order function on a deal ticket may return empty or incorrect data
  • Repeats history queries and Comment output on every tick without checking for new deals, making it inefficient and potentially causing chart flickering

Improvements

  • Fix the reversed buy/sell direction labels — BUY should display 'Buy Trade' and SELL should display 'Sell Trade'
  • Replace HistoryOrderGetString with HistoryDealGetString to correctly retrieve the deal symbol
  • Add a new-deal detection mechanism so the output only updates when the last deal changes, avoiding redundant per-tick history queries
