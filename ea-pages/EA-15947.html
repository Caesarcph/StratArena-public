策略分析

分析 ### 2.1 核心策略概念 这是一个基于**DMI(Directional Movement Index)方向性指标穿越**的趋势跟踪策略。策略使用自定义ADXDMI指标,该指标将经典的ADX(平均方向性指数)与DMI指标结合,通过+DI与-DI线的穿越产生交易信号。 **核心算法**: 1. 计算正向动量PD(Positive Directional): 当当前最高价>前一根最高价,且涨幅大于跌幅时,记录涨幅 2. 计算负向动量ND(Negative Directional): 当当前最低价<前一根最低价,且跌幅大于涨幅时,记录跌幅 3. 对PD和ND进行EMA平滑(DMIPeriod周期) 4. 计算真实波动范围TR(True Range): 最高价、最低价、前收盘价三者极差的最大值 5. 归一化输出: `UpBuffer=100000×(PD/TR)` 和 `DnBuffer=100000×(ND/TR)` 6. 计算ADX平滑值用于趋势强度评估 **云带可视化**: 使用DRAW_FILLING绘制双色云带,蓝色表示多头强势,红色表示空头强势 ### 2.2 入场条件 **做多条件** (BUY_Open=true): 1. Ind[1] > Sign[1] (前一根K线Ind线在Sign线上方) 2. Ind[0] <= Sign[0] (当前K线Ind线穿越Sign线向下) 3. BuyPosOpen开关启用 4. **入场时机**: Ind线从上方向下穿越Sign线时做多 (⚠️这是**趋势反转信号**,而非趋势确认信号) **做空条件** (SELL_Open=true): 1. Ind[1] < Sign[1] (前一根K线Ind线在Sign线下方) 2. Ind[0] >= Sign[0] (当前K线Ind线穿越Sign线向上) 3. SellPosOpen开关启用 4. **入场时机**: Ind线从下方向上穿越Sign线时做空 (⚠️同样是**趋势反转信号**) **信号逻辑解读**: - Ind线 = ADXDMI指标的主线(UpBuffer/DnBuffer的相对位置) - Sign线 = 可能是信号线或零轴 - **穿越确认**: 使用双K线确认模式(Ind[1]/Sign[1]和Ind[0]/Sign[0]双重判断) - ⚠️ **潜在问题**: 入场时机为趋势反转时(Ind穿越Sign),可能导致逆势交易 ### 2.3 出场条件 **平多仓** (BUY_Close=true): - 当产生做空信号时(Ind线从下方穿越Sign线向上),平掉所有多头仓位 - BuyPosClose开关必须启用 **平空仓** (SELL_Close=true): - 当产生做多信号时(Ind线从上方穿越Sign线向下),平掉所有空头仓位 - SellPosClose开关必须启用 **信号时间戳机制**: - UpSignalTime/DnSignalTime记录信号产生时间 - 用于防止重复入场和信号追踪 ### 2.4 风险管理 **止损止盈**: - 默认止损(StopLoss_): 1000点 (⚠️过大,约100-200 pip) - 默认止盈(TakeProfit_): 2000点 (约200-400 pip) - 盈亏比: 2:1 (良好) - ⚠️ **问题**: 默认止损过大,应根据品种ATR动态调整 **手数管理**: - 参数MM=0.1 (固定0.1手或10%风险,取决于MMMode) - MMMode=LOT表示固定手数模式 - ⚠️ **问题**: 固定0.1手过大,无资金管理 **滑点控制**: - Deviation_=10 (最大滑点10点) - 用于订单执行时的价格偏差容忍度 **其他风控措施**: - 四开关交易控制系统(BuyPosOpen/SellPosOpen/BuyPosClose/SellPosClose独立控制) - 信号时间戳防止重复交易 - GlobalVariable状态持久化(EA重启后恢复状态) - IsNewBar新K线检测(避免重复信号) - BarsCalculated检查指标缓冲区完整性 - LoadHistory加载历史数据确保指标计算正确

优势

  • DMI经典趋势指标应用
  • DMI是Wilder开发的经典趋势强度指标
  • 通过+DI/-DI穿越识别趋势转折点
  • 归一化输出便于跨品种信号评分
  • Nikolay Kositsin专业级代码架构
  • 四开关交易控制系统(BuyPosOpen/SellPosOpen/BuyPosClose/SellPosClose独立控制)
  • CIsNewBar新K线检测类(避免重复交易)
  • GlobalVariable状态持久化机制(EA重启后恢复)
  • 信号时间戳记录(UpSignalTime/DnSignalTime防止重复入场)
  • TradeAlgorithms完整交易函数库
  • 5模式手数计算(FREEMARGIN/BALANCE/LOSSFREEMARGIN/LOSSBALANCE/LOT)
  • OrderCheck预检查机制(保证金充足性验证)
  • 完整的开仓/平仓/修改函数封装
  • 错误处理和重试机制
  • 双K线穿越确认逻辑
  • 使用Ind[1]/Sign[1]和Ind[0]/Sign[0]双重判断
  • 有效降低单根K线假突破风险
  • 云带可视化系统(DRAW_FILLING)
  • 蓝色表示多头强势,红色表示空头强势
  • 直观显示趋势状态,便于人工确认

劣势

  • 默认止损过大(1000点)
  • 对于主流货币对,100-200 pip止损过大
  • 风险敞口过高,不适合小资金账户
  • 固定手数过大(MM=0.1)
  • 无资金管理,对$10,000账户风险过高
  • 不符合风险管理最佳实践
  • 无趋势强度过滤
  • 虽然计算了ADX值,但未用于入场确认
  • 可能导致震荡市频繁假信号
  • 入场时机存疑
  • 策略在Ind线穿越Sign线时入场(趋势反转信号)
  • 可能过早入场,逆势交易,风险较高
  • 依赖外部库和指标
  • 需要TradeAlgorithms.mqh和ADXDMI.mq5
  • 增加部署复杂度
  • 非标准时间框架(H8)
  • 部分平台可能不支持H8时间框架
  • 限制了策略的通用性

改进建议

  • 降低止损至150-300点,或使用ATR×2-3动态止损
  • 实现动态手数计算(风险1-2%),或降低固定手数至0.01-0.02
  • 添加ADX>25趋势强度过滤
  • 测试顺趋势入场逻辑
  • 改用H4或D1标准时间框架
  • 可吸收亮点
