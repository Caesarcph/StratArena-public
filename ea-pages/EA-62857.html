策略分析

分析 ### 2.1 核心策略概念 **三角套利(Triangular Arbitrage)**是一种无风险套利策略，通过同时交易三个相关货币对来利用价格差异获利。 **命名由来**: 以Giuseppe Tardio命名（Brigantaggio politico - 政治土匪），暗示这种策略可能在某些环境下"掠夺"利润。 **核心原理**: 1. 选择三个相关货币对（如EUR/USD, GBP/USD, EUR/GBP） 2. 计算理论交叉汇率：EUR/GBP理论值 = EUR/USD实际值 / GBP/USD实际值 3. 比较理论汇率与实际市场汇率的差异 4. 当差异超过阈值时，同时开立三个仓位锁定无风险利润 **六组预设套利组合**: 1. EUR/USD, GBP/USD, EUR/GBP 2. GBP/USD, USD/JPY, GBP/JPY 3. EUR/GBP, GBP/CHF, EUR/CHF 4. AUD/USD, USD/NZD, AUD/NZD 5. EUR/CAD, CAD/JPY, EUR/JPY 6. USD/SGD, EUR/USD, EUR/SGD ### 2.2 入场条件 **卖套利(Sell Arbitrage)**: - 条件1: `ratio_ask - symbols[2].ask > threshold + MinArbitrageThreshold` - 理论交叉汇率高于实际汇率，说明第三对货币被高估 - 执行: 卖第一对 + 买第二对 + 买第三对 - 示例(EUR/USD, GBP/USD, EUR/GBP): 卖EURUSD + 买GBPUSD + 买EURGBP **买套利(Buy Arbitrage)**: - 条件2: `ratio_bid - symbols[2].bid < -threshold - MinArbitrageThreshold` - 理论交叉汇率低于实际汇率，说明第三对货币被低估 - 执行: 买第一对 + 卖第二对 + 卖第三对 - 示例(EUR/USD, GBP/USD, EUR/GBP): 买EURUSD + 卖GBPUSD + 卖EURGBP **阈值计算**: **交叉汇率计算**: - 标准组合: `ratio = symbols[0].ask / symbols[1].bid` - JPY组合: `ratio = symbols[0].ask / symbols[1].ask` - USD/SGD组合: `ratio = symbols[0].ask / symbols[1].bid` ### 2.3 出场条件 **主动出场**: - 反向套利机会出现时，自动平仓获利 - ClosePosSide(): 平掉盈利侧仓位 - CloseNegSide(): 平掉亏损侧仓位 **强制出场**: - MaxTradeDuration超时强制平仓（默认60秒） - CloseStaleTrades()检查并关闭超时仓位 **无止损止盈**: - EA设计理念为"瞬时套利"，理论上无需传统止损止盈 - 完全依赖价格回归套利窗口实现盈利 - ⚠️ **致命风险**: 如果套利窗口不关闭，仓位将无限期持有 ### 2.4 风险管理 **资金管理**: - 手数计算公式: `vol = balance / 1000 × Lot_Size_Per_Thousand` - 默认: 每千英镑0.002手（极其保守） - 三仓位同时开立，需验证所有品种手数有效性 - 保证金预检: 检查FreeMargin是否充足 **交易限制**: - MaxDailyTrades: 每日最大交易次数（默认5次） - 防止过度交易和过度暴露风险 - 每日UTC 00:00重置计数器 **安全检查**: - Equity检查: `equity < balance × 0.5`时停止交易并发送通知 - Margin检查: FreeMargin < RequiredMargin时拒绝交易 - Symbol验证: 所有三个品种必须可用且数据有效 - 价格变化检测: 价格变化小于1 pip时跳过更新（优化性能） **佣金与点差处理**: - 区分JPY品种和非JPY品种的不同佣金结构 - JPY品种佣金通常为非JPY的100倍（如700 vs 7英镑） - 点差成本计入阈值计算，确保套利利润覆盖交易成本

优势

  • 理论无风险套利:
  • 通过同时开立三个相关仓位，理论上可锁定无风险利润
  • 无论市场涨跌，三仓位的盈亏总和应趋向零
  • 代码质量高:
  • MIT开源许可证，代码透明
  • 结构清晰，注释详尽（EA Overview部分非常详细）
  • OOP设计良好，SymbolData结构体封装数据
  • 完整的风控框架:
  • Equity检查（权益低于余额50%停止）
  • Margin检查（保证金不足拒绝交易）
  • 每日交易次数限制
  • 超时强制平仓机制
  • 六组预设组合:
  • 覆盖主要货币三角关系
  • 支持不同小数位数品种（3位JPY，5位其他）
  • 自动适配品种精度
  • 成本计算精确:
  • 区分JPY和非JPY品种佣金结构
  • 点差成本计入阈值
  • 实时更新价格数据

劣势

  • 🔴 实际执行风险极高:
  • 零售交易环境延迟难以满足三角套利需求
  • 三笔交易无法保证同时成交
  • 滑点可能吞噬理论利润
  • 🔴 无止损机制:
  • 套利失败时无保护措施
  • 浮亏可能无限扩大
  • 极端行情可能爆仓
  • 🔴 过度乐观的理论假设:
  • 假设报价实时同步（实际可能延迟）
  • 假设流动性充足（实际可能滑点）
  • 假设无隐藏成本（实际有隔夜利息等）
  • 🟡 细节实现问题:
  • SendNotification()函数被调用但未实现
  • UTF-16编码影响代码可读性
  • 手数计算过于保守（0.002手/千英镑）
  • 🟡 未考虑的重要成本:
  • 隔夜利息（Swap）未计入成本
  • 周末持仓成本
  • 滑点缓冲未预留
