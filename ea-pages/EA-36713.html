摘要

该EA使用随机指标(Stochastic)生成动量入场信号，当主线上穿或下穿其滞后值时放置Buy Stop或Sell Stop挂单。当持仓被止损平仓后，它会自动在反方向开立新的挂单，形成一个持续交易的循环。

策略分析

该EA的策略概念基于Stochastic动量指标判断趋势方向，当主线值低于2根K线前的值时判定为下跌动量并下Sell Stop挂单，当主线值高于2根K线前的值时判定为上涨动量并下Buy Stop挂单。入场条件为Stochastic主线的动量变化，挂单价格设在当前价加减止损距离之外，确保在突破后入场。出场条件为止损和止盈，同时支持固定点数的追踪止损。仓位管理使用固定手数(PriceVolume)，限制最大持仓数为Maxposition。资金管理方面有CheckMoneyForTrade函数检查可用保证金，CheckVolumeValue函数验证手数合规性。特别之处在于OnTradeTransaction中检测止损成交事件(DEAL_REASON_SL)，当持仓被止损平仓后立即在反方向放置新的挂单，形成一种止损后反转的循环交易逻辑。挂单有过期时间设置，Sell Stop和Buy Stop分别使用H4和用户指定的过期周期。

Summary

This EA uses the Stochastic oscillator to generate momentum-based entry signals, placing Buy Stop or Sell Stop pending orders when the main line crosses above or below its lagged value. When a position is closed by stop loss, it automatically opens a reversal pending order in the opposite direction, creating a continuous trading cycle that re-enters after every SL hit.

Strategy Analysis

The EA's strategy concept is based on the Stochastic momentum indicator to determine trend direction: when the main line value is below its value 2 bars ago, it identifies bearish momentum and places a Sell Stop pending order; when above, it identifies bullish momentum and places a Buy Stop pending order. Entry conditions rely on Stochastic main line momentum shifts, with pending order prices set beyond the current price plus the stop level distance, ensuring entry after a breakout. Exit conditions are stop loss and take profit, with a fixed-pip trailing stop also supported via CTrailingFixedPips. Position sizing uses a fixed lot size (PriceVolume) with a maximum position count controlled by the Maxposition parameter. Money management includes the CheckMoneyForTrade function to verify available margin and CheckVolumeValue to validate lot size compliance with broker requirements. The distinctive feature is in OnTradeTransaction where it detects stop loss deal events (DEAL_REASON_SL): when a position is closed by stop loss, it immediately places a new pending order in the opposite direction, creating a stop-loss-then-reverse cycle. Pending orders have expiration times, with the OnTick orders using H4 expiration and the reversal orders using the user-configured Expirydate parameter.

优势

  • 止损后自动反转挂单，能在震荡行情中捕捉来回波动
  • 包含完整的资金检查和手数验证，防止违规下单
  • 使用挂单而非市价单入场，减少假突破风险
  • 限制最大持仓数(Maxposition)，控制风险敞口
  • 有挂单过期机制，避免过期订单堆积

劣势

  • 止损后无限制地反转挂单，可能在单边趋势中连续亏损
  • Step和TargetProfit参数声明但未在核心逻辑中使用，存在冗余
  • OnTick和OnTradeTransaction中挂单过期时间不一致(H4 vs Expirydate)，逻辑不统一
  • 止损反转条件(trans.price > trans.price_sl)逻辑可疑，止损价与成交价关系判断可能不正确
  • 缺少新K线检测，每个tick都会重复检查指标并可能频繁下单
  • SumPosition函数遍历从PositionsTotal()开始但索引最大值应为PositionsTotal()-1，存在越界风险

改进建议

  • 添加连续止损次数限制，防止在强趋势中无限反转亏损
  • 添加新K线检测逻辑，避免每个tick重复计算指标和下单
  • 统一OnTick和OnTradeTransaction中的挂单过期时间逻辑，消除不一致性
  • 修复SumPosition和CheckPendingOrder的索引越界问题(应从Total-1开始)
  • 增加Step参数的实际使用，实现持仓间距控制

Strengths

  • Automatic reversal pending order after stop loss hit, capturing oscillating market moves
  • Complete margin check and volume validation to prevent non-compliant orders
  • Uses pending orders instead of market orders for entry, reducing false breakout risk
  • Limits maximum position count (Maxposition) to control risk exposure
  • Pending order expiration mechanism prevents stale order accumulation

Weaknesses

  • Unlimited reversal pending orders after stop loss can cause consecutive losses in trending markets
  • Step and TargetProfit parameters are declared but unused in core logic, creating dead parameters
  • Inconsistent pending order expiration between OnTick (H4) and OnTradeTransaction (Expirydate), causing logical inconsistency
  • The reversal condition (trans.price > trans.price_sl) is questionable; the relationship between deal price and SL price may be incorrectly evaluated
  • No new bar detection means the EA checks indicators and potentially places orders on every tick, risking frequent repeated orders
  • SumPosition iterates from PositionsTotal() but max index should be PositionsTotal()-1, causing an out-of-bounds access risk

Improvements

  • Add a maximum consecutive stop loss count limit to prevent unlimited reversal losses in strong trends
  • Add new bar detection logic to avoid recalculating indicators and placing orders on every tick
  • Unify pending order expiration logic between OnTick and OnTradeTransaction to eliminate inconsistency
  • Fix index out-of-bounds issue in SumPosition and CheckPendingOrder (should start from Total-1)
  • Implement the Step parameter in actual logic to control distance between positions
