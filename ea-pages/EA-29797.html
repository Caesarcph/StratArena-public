摘要

这个EA是一个追踪止损工具，根据移动平均线和价格距离参数来修改已有持仓的止损位。它本身不开仓，但在止损超过最大允许距离时可以平仓。追踪逻辑根据持仓是否盈利，在MA追踪和价格追踪之间动态调整。

策略分析

这个EA的核心策略概念是利用移动平均线作为动态支撑/阻力来追踪止损，实现趋势跟踪式的利润保护。入场条件方面，该EA不负责开仓，仅管理已有持仓的止损。出场条件有两个：一是当价格触及动态追踪止损位时由止损单触发平仓，二是当持仓亏损超过max_sl点数且pre_init开启时强制平仓。仓位管理方面，该EA不涉及开仓手数设置，仅修改已有仓位的止损和止盈。资金管理方面，max_sl参数提供了最大止损限制功能，防止单笔亏损过大。追踪止损逻辑区分盈利和亏损两种状态：盈利时使用较紧的trail_behind_price距离追踪，亏损时使用较宽的trail_behind_negative距离追踪，同时MA线作为另一个追踪基准，取两者中较优者。

Summary

This EA is a trailing stop utility that modifies existing position stop-losses based on a Moving Average line and price distance parameters. It does not open any new positions itself but can close positions when the stop-loss exceeds a maximum allowed distance. The trailing logic dynamically adjusts between MA-based and price-based trailing depending on whether the position is in profit or loss.

Strategy Analysis

The core strategy concept of this EA is using a Moving Average as dynamic support/resistance to trail stop-losses, implementing trend-following profit protection. Regarding entry conditions, this EA does not open positions; it only manages stop-losses of existing positions. Exit conditions are twofold: first, when price hits the dynamically trailed stop-loss level, the position is closed by the SL order; second, when a position's loss exceeds max_sl points and pre_init is enabled, the position is forcibly closed. For position sizing, this EA does not handle lot sizes for new trades; it only modifies stop-loss and take-profit of existing positions. For money management, the max_sl parameter provides a maximum stop-loss cap to prevent excessive single-trade losses. The trailing stop logic distinguishes between profitable and losing states: when profitable, a tighter trail_behind_price distance is used; when in loss, a wider trail_behind_negative distance is applied, while the MA line serves as an alternative trailing benchmark, choosing the more favorable of the two.

优势

  • 双模式追踪止损：同时使用MA线和价格距离两个基准，取较优值，提供更灵活的止损保护
  • 区分盈利/亏损状态：盈利时收紧追踪距离，亏损时放宽追踪距离，避免在回调中被过早止损出局
  • 最大止损限制功能：pre_init和max_sl参数可以限制单笔最大亏损，具备基本的风控能力
  • 支持多空双向：对多头和空头持仓分别实现对称的追踪止损逻辑
  • 可视化MA线：可在图表上显示MA指标线，便于直观判断追踪止损位置

劣势

  • 没有新K线检查：每个tick都会执行追踪逻辑，可能导致频繁发送修改请求，增加服务器负担和被拒绝的风险
  • 没有点差过滤：在点差较大时追踪止损可能被立即触发，导致不必要的止损出场
  • PositionModify返回值未检查：调用PositionModify后未验证是否成功，可能在静默失败中遗漏止损修改
  • 仅支持当前图表品种：硬编码了_Symbol过滤，无法跨品种管理持仓
  • trail_step为0时可能导致每个tick都发送修改请求，即使止损位变化极小

改进建议

  • 添加新K线检查或最小时间间隔检查，避免每个tick都执行止损修改逻辑
  • 检查PositionModify和PositionClose的返回值，处理交易请求失败的情况
  • 添加点差过滤和最小止损距离检查，确保止损位符合经纪商的最小止损水平要求
  • 添加OnTradeTransaction回调来监控止损修改是否真正执行成功

Strengths

  • Dual-mode trailing stop: uses both MA line and price distance as benchmarks, choosing the better value for more flexible stop protection
  • Profit/loss state differentiation: tightens trailing distance when profitable, widens it when losing, avoiding premature stop-outs during pullbacks
  • Maximum stop-loss cap: pre_init and max_sl parameters limit maximum single-trade loss, providing basic risk control
  • Bidirectional support: implements symmetric trailing stop logic for both long and short positions
  • Visual MA line: can display the MA indicator on the chart for intuitive judgment of trailing stop placement

Weaknesses

  • No new bar check: trailing logic executes on every tick, potentially sending frequent modification requests, increasing server load and rejection risk
  • No spread filter: with wide spreads, the trailing stop may be triggered immediately, causing unnecessary stop-outs
  • PositionModify return value unchecked: success of PositionModify calls is not verified, potentially missing stop-loss modifications through silent failures
  • Current symbol only: hardcoded _Symbol filter prevents cross-instrument position management
  • trail_step of 0 may cause modification requests on every tick even when stop-loss change is negligible

Improvements

  • Add new bar check or minimum time interval check to avoid executing stop-loss modification logic on every tick
  • Check return values of PositionModify and PositionClose to handle trade request failures
  • Add spread filter and minimum stop-level distance check to ensure stop-loss complies with broker's minimum stop level requirements
  • Add OnTradeTransaction callback to monitor whether stop-loss modifications are actually executed successfully
