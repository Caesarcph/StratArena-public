摘要

该EA使用RSI超买超卖信号，配合双周期移动平均线趋势过滤，在M5图表上入场交易。它具有通过暴力回测进行自适应参数优化、基于ATR的仓位管理和移动止损，以及根据历史胜率动态调整风险比例的功能。系统会定期重新优化RSI周期、ATR倍数和移动止损/止盈倍数。

策略分析

策略概念是基于多周期趋势确认的均值回归思路，在M5周期使用RSI识别超买超卖区域，同时要求价格在M5和H1两个周期的移动平均线同侧才能入场。买入条件为RSI低于30且价格高于M5和H1的SMA均线，卖出条件为RSI高于70且价格低于两周期SMA均线。出场条件包括基于ATR倍数的固定止盈止损，以及三档渐进式移动止损——当浮盈超过2倍ATR时将止损移至价格-1.5倍ATR，超过1倍ATR时移至价格-1倍ATR，否则保持0.5倍ATR距离。仓位管理使用账户余额乘以风险百分比除以ATR止损距离来计算手数，并遵守品种的最小/最大手数和手数步长约束。资金管理方面，系统每4小时根据各品种的胜率动态调整风险比例——胜率低于40%时降低0.05%，高于60%时提高0.05%，但不超过初始设定的最大风险比例。此外，每小时进行一次参数暴力优化，遍历RSI周期和各ATR倍数的组合以寻找最优参数集。

Summary

This EA uses RSI overbought/oversold signals confirmed by dual-timeframe moving average trend filters to enter trades on M5 charts. It features adaptive parameter optimization via brute-force backtesting, ATR-based position sizing and trailing stops, and dynamic risk adjustment based on historical win rate. The system periodically re-optimizes its RSI period, ATR multiplier, and trailing stop/TP multipliers.

Strategy Analysis

The strategy concept is a mean-reversion approach with multi-timeframe trend confirmation, using RSI on M5 to identify overbought/oversold zones while requiring price to be on the same side of both M5 and H1 SMAs for entry. Buy condition requires RSI below 30 and price above both M5 and H1 SMAs; sell condition requires RSI above 70 and price below both SMAs. Exit conditions include fixed ATR-multiplier-based stop loss and take profit, plus a three-tier progressive trailing stop — when unrealized profit exceeds 2x ATR the stop moves to price-1.5x ATR, above 1x ATR it moves to price-1x ATR, otherwise it maintains a 0.5x ATR distance. Position sizing calculates lot size by dividing account balance times risk percentage by the ATR-based stop loss distance in points, respecting the symbol's minimum/maximum volume and volume step constraints. Money management dynamically adjusts risk percentage every 4 hours based on each symbol's win rate — reducing by 0.05% when win rate falls below 40% and increasing by 0.05% when above 60%, capped at the initial maximum risk. Additionally, the system performs brute-force parameter optimization every hour, iterating through RSI period and ATR multiplier combinations to find the best parameter set.

优势

  • 多周期趋势确认（M5+H1）减少了逆势交易的风险
  • ATR-based动态仓位管理和止损使风险适应市场波动性
  • 根据历史胜率动态调整风险比例，具有一定的自适应风控能力
  • 包含点差过滤和新闻回避机制，避免不利市场环境入场
  • 指标句柄在OnDeinit中正确释放，避免资源泄漏

劣势

  • 回测函数BacktestWithParameters是空壳占位符，参数优化实际上没有任何效果，所有参数组合的评分都是0
  • ApplyTrailingStop中没有遍历持仓，直接使用PositionGetInteger但未先选择持仓，会导致获取到错误或未定义的持仓数据
  • tradeActive标志只在开仓时设为true但从未重置为false，导致每个品种只能开一次仓后再也无法交易
  • BreakEvenMultiplier和PartialTakeProfitPercent参数定义了但从未在代码中使用
  • 新闻检查函数IsHighImpactNewsUpcoming是占位符，始终返回false，新闻回避功能形同虚设
  • OnTick中每次tick都调用LogInfo打印日志，在高频品种上会产生大量冗余日志影响性能

改进建议

  • 实现真正的回测逻辑或使用MQL5的OnTester框架，使参数优化能产生有效结果；或者移除优化功能避免误导用户
  • 在ApplyTrailingStop中使用PositionSelect或遍历所有持仓来正确选择对应品种的持仓，并在持仓关闭时将tradeActive重置为false
  • 实现BreakEvenMultiplier和PartialTakeProfitPercent的实际逻辑，或删除这些未使用的参数以减少混淆

Strengths

  • Multi-timeframe trend confirmation (M5+H1) reduces counter-trend trading risk
  • ATR-based dynamic position sizing and stop loss adapts risk to market volatility
  • Dynamic risk percentage adjustment based on historical win rate provides adaptive risk control
  • Spread filter and news avoidance mechanism prevent entries during unfavorable market conditions
  • Indicator handles are properly released in OnDeinit, avoiding resource leaks

Weaknesses

  • The BacktestWithParameters function is a stub placeholder returning 0, making parameter optimization completely ineffective as all parameter combinations score identically
  • ApplyTrailingStop does not iterate through positions — it calls PositionGetInteger without first selecting a position via PositionSelect, resulting in incorrect or undefined position data
  • The tradeActive flag is set to true on entry but never reset to false on exit, meaning each symbol can only ever open one trade and then becomes permanently blocked
  • BreakEvenMultiplier and PartialTakeProfitPercent parameters are declared but never used anywhere in the code logic
  • The IsHighImpactNewsUpcoming function is a placeholder always returning false, making the news avoidance feature completely non-functional
  • OnTick calls LogInfo on every tick, which produces massive redundant logs on liquid instruments and impacts performance

Improvements

  • Implement actual backtesting logic or use MQL5's OnTester framework so parameter optimization produces meaningful results; alternatively, remove the optimization feature to avoid misleading users
  • Use PositionSelect or iterate through all positions in ApplyTrailingStop to correctly select the position for each symbol, and reset tradeActive to false when positions are closed
  • Implement the actual logic for BreakEvenMultiplier and PartialTakeProfitPercent, or remove these unused parameters to reduce confusion

风险评估 / Risk Assessment

总体 / Overall:MEDIUM

风险点

  • 参数优化功能完全无效（回测占位符），可能导致用户误信已优化而实际使用默认参数
  • tradeActive永不重置导致品种锁死，但在锁死前可能因移动止损逻辑错误而修改错误持仓的止损
  • 缺少新K线检测，每个tick都执行信号检查和止损修改，可能在同一根K线上多次开仓或频繁修改止损
  • 止损和止盈使用ATR绝对值而非点数，未考虑品种报价精度，可能导致止损距离不合理

Risk Assessment

Overall:MEDIUM

Risk Points

  • Parameter optimization is completely non-functional (stub backtest), potentially misleading users into believing parameters are optimized while using defaults
  • tradeActive never resets causing symbol lockout, but before lockout the flawed trailing stop logic may modify the wrong position's stop loss
  • No new bar detection means signal checks and stop modifications run every tick, potentially opening multiple trades on the same bar or excessively modifying stops
  • Stop loss and take profit use ATR absolute values rather than points, without considering symbol quote precision, which may result in unreasonable stop distances
