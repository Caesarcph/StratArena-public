摘要

该EA使用两个支持向量机(SVM)模型，基于标准技术指标训练后生成买入和卖出交易信号。当SVM发出信号时，EA开仓并下挂止损和止盈订单，通过票号缓存系统将配对订单作为独立交易管理。

策略分析

策略概念：利用支持向量机(SVM)对多种技术指标（Bears Power、Bulls Power、ATR、Momentum、MACD、Stochastic、Force Index）进行机器学习训练，分别建立买入信号模型和卖出信号模型。入场条件：每个新K线形成时，classify()函数用当前指标数据评估已训练的SVM模型，若买入SVM返回true则开多仓，若卖出SVM返回true则开空仓。出场条件：通过挂单方式实现手动止损止盈，买入后放置SellStop止损和SellLimit止盈，卖出后放置BuyStop止损和BuyLimit止盈；当一方触发时，通过OnTrade()事件删除配对的另一方挂单。仓位管理：固定手数(Vol=1)，通过Current_Order_Exposure()函数计算当前挂单总量的二分之一作为风险敞口，限制不超过risk_exp(5)时才允许开仓。资金管理：仅通过最大同时持仓风险敞口参数控制，无动态仓位调整或百分比风险计算。

Summary

This EA uses two Support Vector Machine (SVM) models trained on standard technical indicators to generate buy and sell trade signals. When an SVM signals a trade, the EA opens a market position and places matching manual stop-loss and take-profit pending orders, using a ticket cache system to pair and manage them as separate trades.

Strategy Analysis

Strategy concept: Uses Support Vector Machine (SVM) models trained on seven technical indicators (Bears Power, Bulls Power, ATR, Momentum, MACD, Stochastic, Force Index) to independently generate buy and sell trade signals. Entry conditions: On each new bar, the classify() function feeds current indicator data to the trained SVM models; if the buy-SVM returns true, a long position is opened, and if the sell-SVM returns true, a short position is opened. Exit conditions: Manual stop-loss and take-profit are implemented via pending orders — after a buy, a SellStop (stop-loss) and SellLimit (take-profit) are placed; after a sell, a BuyStop (stop-loss) and BuyLimit (take-profit) are placed; when one is triggered, the OnTrade() handler deletes the paired order using a ticket cache. Position sizing: Fixed lot size (Vol=1), with Current_Order_Exposure() computing half of total pending order volume as risk exposure, allowing new trades only when exposure is below risk_exp (5). Money management: Relies solely on the maximum simultaneous order exposure parameter; there is no dynamic position sizing or percentage-based risk calculation.

优势

  • 使用机器学习(SVM)方法进行信号生成，具有较强的非线性模式识别能力
  • 买卖信号分别由独立SVM模型产生，避免了单一模型的双向判断冲突
  • 通过票号缓存系统实现止损止盈挂单配对管理，能够将多笔交易独立处理
  • 新K线判断机制避免了同一K线内重复开仓

劣势

  • SVM仅在使用时初始化训练一次(OnInit)，不会随市场变化重新训练，模型可能快速过时
  • 固定手数(Vol=1)缺乏动态仓位管理，无法根据账户资金或波动性调整风险
  • Pip_Size()函数通过取对数推算pip大小，逻辑脆弱，对JPY等非标准报价品种可能计算错误
  • Current_Order_Exposure()用挂单总量的一半估算风险敞口，方法粗糙且不准确
  • OnTrade()中遍历逻辑存在缺陷：用ticket索引访问tickets数组，当ticket值大于数组大小时可能越界

改进建议

  • 增加定期重新训练机制(如每日或每周)，使SVM模型能适应市场状态变化
  • 实现基于账户余额百分比或ATR的动态仓位管理，替代固定手数
  • 修复OnTrade()中的票号缓存查找逻辑，避免数组越界风险
  • 使用SymbolInfoDouble(SYMBOL_POINT)和SYMBOL_DIGITS正确计算pip大小

Strengths

  • Uses machine learning (SVM) for signal generation, providing strong nonlinear pattern recognition capability
  • Buy and sell signals are produced by independent SVM models, avoiding conflicting signals from a single model
  • The ticket cache system pairs stop-loss and take-profit pending orders, enabling independent management of multiple trades
  • New bar detection prevents repeated trade entries within the same candle

Weaknesses

  • SVM is trained only once during OnInit() and never retrained, causing the model to become stale as market conditions change
  • Fixed lot size (Vol=1) lacks dynamic position sizing, unable to adjust risk based on account equity or volatility
  • Pip_Size() calculates pip value via logarithmic estimation, which is fragile and may produce incorrect results for non-standard quote currencies like JPY pairs
  • Current_Order_Exposure() estimates risk exposure as half of total pending order volume, a crude and inaccurate method
  • OnTrade() loop has a bug: it uses the order ticket as an index into the tickets[] array, which can cause out-of-bounds access when ticket values exceed array size

Improvements

  • Add periodic retraining mechanism (e.g., daily or weekly) so SVM models adapt to changing market conditions
  • Implement dynamic position sizing based on account equity percentage or ATR instead of fixed lot size
  • Fix the ticket cache lookup logic in OnTrade() to prevent array out-of-bounds access
  • Use SymbolInfoDouble(SYMBOL_POINT) and SYMBOL_DIGITS for correct pip size calculation instead of the fragile logarithmic method
