摘要

该EA使用两个支持向量机（SVM）——一个用于发出买入信号，另一个用于发出卖出信号——基于七个标准技术指标进行训练。每个新K线形成时，训练好的SVM对当前市场状况进行分类，若产生信号则开仓并手动挂止损止盈订单。止损止盈订单通过票据缓存配对，当一方触发时自动删除对应订单。

策略分析

策略概念是基于支持向量机（SVM）的机器学习分类，使用7个技术指标（熊力、牛力、ATR、动量、MACD、随机指标、强制指标）作为输入特征。入场条件为：每个新K线形成时，买入SVM或卖出SVM的分类结果为真，且当前订单暴露度不超过风险上限。出场条件通过手动挂单实现：买入仓位挂SellStop止损和SellLimit止盈，卖出仓位挂BuyStop止损和BuyLimit止盈，任一挂单触发后通过票据缓存删除配对订单。仓位管理为固定手数（Vol=1），资金管理通过risk_exp参数限制最大同时持仓暴露度。训练数据由历史指标数据和假设交易结果生成，容差参数控制SVM训练精度。

Summary

This EA uses two Support Vector Machines (SVMs) — one trained to signal buy trades and another to signal sell trades — based on seven standard technical indicators. On each new bar, the trained SVMs classify current market conditions and, if a signal is generated, open a market position with manually managed stop-loss and take-profit pending orders. The stop-loss and take-profit orders are paired via a ticket cache so that when one is triggered, the matching order is automatically deleted.

Strategy Analysis

The strategy concept is based on Support Vector Machine (SVM) classification, using 7 technical indicators (Bears Power, Bulls Power, ATR, Momentum, MACD, Stochastic, Force Index) as input features. Entry conditions: on each new bar, if the buy-SVM or sell-SVM classification returns true and current order exposure does not exceed the risk limit, a trade is opened. Exit conditions are implemented via manual pending orders: buy positions get a SellStop for stop-loss and a SellLimit for take-profit, while sell positions get a BuyStop for stop-loss and a BuyLimit for take-profit; when either pending order triggers, the paired order is deleted via the ticket cache. Position sizing is fixed at 1 lot (Vol=1), and money management is handled by the risk_exp parameter which caps maximum simultaneous order exposure. Training data is generated from historical indicator values and hypothetical trade outcomes, with a tolerance parameter controlling SVM training precision.

优势

  • 采用机器学习（SVM）方法，能够从历史数据中自动学习非线性模式
  • 买卖信号分别由独立的SVM产生，避免了单一模型的偏向性
  • 通过票据缓存机制实现止损止盈配对管理，能正确处理同品种多笔独立交易

劣势

  • SVM仅在OnInit时训练一次，不会随市场变化动态重新训练，模型容易过时失效
  • 票据缓存使用订单号作为数组索引，当订单号较大时会消耗大量内存，存在严重内存效率问题
  • 固定手数交易缺乏动态仓位管理，无法根据账户余额或波动率调整仓位大小
  • Pip_Size()函数的计算逻辑不够健壮，对某些品种（如JPY对）可能返回错误的点值

改进建议

  • 添加定期重新训练机制，例如每N根K线或每N小时重新训练SVM，使模型适应市场变化
  • 使用映射表（如哈希表）替代数组索引来存储票据配对关系，避免内存浪费
  • 引入动态仓位管理，根据ATR或账户风险比例自动计算交易手数

Strengths

  • Uses machine learning (SVM) approach that can automatically learn non-linear patterns from historical data
  • Buy and sell signals are generated by separate SVMs, avoiding bias from a single model
  • Ticket cache mechanism pairs stop-loss and take-profit orders, correctly handling multiple independent trades on the same symbol

Weaknesses

  • SVM is trained only once in OnInit and never retrained dynamically, making the model prone to becoming outdated as market conditions change
  • Ticket cache uses order ticket numbers as array indices, consuming excessive memory when ticket numbers are large — a serious memory efficiency issue
  • Fixed lot size trading lacks dynamic position sizing, unable to adjust based on account balance or volatility
  • The Pip_Size() function logic is not robust and may return incorrect pip values for certain instruments (e.g., JPY pairs)

Improvements

  • Add periodic retraining mechanism, e.g., retrain SVMs every N bars or N hours to adapt to changing market conditions
  • Use a map/dictionary instead of array indexing for ticket pairing to avoid memory waste
  • Introduce dynamic position sizing that calculates lot size based on ATR or account risk percentage

风险点

  • SVM训练仅执行一次，市场状态变化后模型信号可能持续失效导致连续亏损
  • 票据缓存数组索引方案在高订单号场景下可能导致内存溢出
  • 缺乏滑点和点差过滤，在流动性差的市场环境下可能以不利价格成交

Risk Assessment

Overall:MEDIUM

Risk Points

  • SVM training is executed only once; if market regime changes, the model signals may persistently fail causing consecutive losses
  • Ticket cache array indexing scheme may cause memory overflow when order ticket numbers are large
  • No slippage or spread filter, potentially executing at unfavorable prices in low-liquidity market conditions
