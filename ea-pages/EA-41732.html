摘要

LazyBot MT5_V1是一个日内突破EA，在前一日最高价和最低价处放置BuyStop和SellStop挂单（可加偏移）。它使用固定点数止损、追踪止损机制以及可选的风险比例仓位管理。每天在设定开始时间下单一次，新单前删除旧挂单。

策略分析

策略概念是基于前一日D1周期的最高价和最低价进行突破交易，属于经典的日内突破策略。入场条件为：当价格突破前一日最高价时触发BuyStop挂单成交，突破前一日最低价时触发SellStop挂单成交，可设置距离高低价的偏移点数。出场条件仅有固定点数止损（Inpuser_SL），未设置止盈（TP=0），依赖追踪止损机制锁定利润——当浮盈超过止损点数时，止损被移动到距当前价格Inpuser_SL点数的位置。仓位管理支持固定手数和基于风险百分比的动态手数两种模式，动态模式下根据可用保证金和风险比例计算手数并向下取整到手数步长的整数倍。资金管理方面有保证金检查、手数范围验证和冻结级别检查，但没有最大持仓限制或连续亏损后的风控措施。

Summary

LazyBot MT5_V1 is a daily breakout EA that places BuyStop and SellStop pending orders at the previous day's High and Low (with an optional offset). It uses a fixed stop loss in pips, a trailing stop mechanism, and optional risk-based lot sizing. Orders are placed once per day at a configurable start hour and old pending orders are deleted before placing new ones.

Strategy Analysis

The strategy concept is a classic daily breakout system based on the previous day's D1 High and Low prices. Entry conditions are: a BuyStop pending order is placed at the previous day's High plus an optional pip offset, and a SellStop pending order is placed at the previous day's Low minus an optional pip offset, both triggered once per day. Exit conditions consist solely of a fixed stop loss in pips (Inpuser_SL) with no take profit set (TP=0), relying entirely on a trailing stop mechanism to lock in profits — when unrealized profit exceeds the stop loss pip distance, the stop loss is moved to maintain that distance from the current price. Position sizing supports both fixed lot size and a risk-percentage-based dynamic mode, where the dynamic mode calculates lots from free margin and risk percentage, rounding down to the nearest lot step multiple. Money management includes margin checks, volume range validation, and freeze level checks, but lacks maximum position limits or consecutive loss risk controls.

优势

  • 策略逻辑简单清晰，基于经典日突破模型，易于理解和验证
  • 具备完整的订单检查机制：保证金检查、冻结级别检查、止损级别检查、手数范围验证
  • 每天仅下单一次并有交易时段控制，避免过度交易
  • 支持固定手数和风险比例两种仓位管理模式，灵活性好
  • 有最大点差过滤功能，可在高波动时避免不利成交

劣势

  • 未设置止盈（TP=0），完全依赖追踪止损，在单边快速行情中可能无法锁定足够利润
  • InpEndHour参数虽存在但代码中未实际使用，交易时间过滤不完整
  • 追踪止损逻辑存在问题：仅在浮盈超过止损距离时移动止损到保本附近，并非真正的阶梯式追踪
  • 风险比例仓位计算使用FreeMargin而非Balance，且未考虑已持仓风险，可能过度杠杆
  • 每日同时挂双向单，若行情剧烈波动可能双面挨打后止损，造成双重亏损

改进建议

  • 增加真实的多级追踪止损机制，例如每达到一定盈利点数后将止损移动到特定位置，而非仅在盈利超过止损距离时移动
  • 实现InpEndHour交易结束时间的实际过滤逻辑，并增加隔夜持仓管理
  • 增加止盈设置或基于ATR的动态止盈，改善盈亏比
  • 加入最大同时持仓数量限制和连续亏损后的仓位缩减机制
  • 在DeleteOldOrds中使用更可靠的订单匹配方式而非依赖注释字符串解析

Strengths

  • Strategy logic is simple and clear, based on a classic daily breakout model that is easy to understand and verify
  • Comprehensive order validation: margin check, freeze level check, stops level check, and volume range validation
  • Orders are placed only once per day with trading hour control, avoiding overtrading
  • Supports both fixed lot and risk-percentage position sizing modes for flexibility
  • Includes a maximum spread filter to avoid unfavorable fills during high volatility

Weaknesses

  • No take profit set (TP=0), relying entirely on trailing stop which may not lock in sufficient profit in fast trending moves
  • InpEndHour parameter exists but is never used in code logic, making the trading time filter incomplete
  • Trailing stop logic is flawed: it only moves SL to breakeven vicinity when profit exceeds SL distance, not a true step-based trail
  • Risk-percentage sizing uses FreeMargin instead of Balance and doesn't account for existing position risk, potentially overleveraging
  • Both BuyStop and SellStop are placed simultaneously each day, risking double stop-outs in violent whipsaw markets

Improvements

  • Implement a true multi-step trailing stop mechanism that progressively moves SL at defined profit intervals rather than only moving it when profit exceeds the SL distance
  • Implement the InpEndHour trading end time filter in actual code logic, and add overnight position management
  • Add configurable take profit or ATR-based dynamic take profit to improve risk-reward ratio
  • Add maximum concurrent position limits and lot size reduction after consecutive losses
  • Use more reliable order matching in DeleteOldOrds instead of relying on comment string parsing which can fail

风险点

  • 双向同时挂单在震荡行情中可能两面止损造成双重亏损
  • 风险比例仓位计算基于可用保证金而非余额，随着持仓增多可能过度加仓
  • 追踪止损仅在价格有利移动超过止损距离时触发，无法在较小盈利时保护本金
  • 依赖注释字符串解析来识别和删除旧订单，如果注释被修改则可能误删或遗漏订单

Risk Assessment

Overall:MEDIUM

Risk Points

  • Simultaneous bidirectional pending orders can cause double stop-outs in choppy markets
  • Risk-percentage sizing based on free margin rather than balance may lead to overleveraging as positions increase
  • Trailing stop only triggers when price moves favorably beyond the SL distance, providing no protection at smaller profits
  • Order identification relies on comment string parsing which can fail if comments are modified, risking incorrect order deletion
