摘要

HVR（历史波动率比率）是一个自定义指标，计算6周期历史波动率与100周期历史波动率的比值，在独立窗口中显示。它使用可选用价格的对数收益率，并计算两个窗口的年化标准差。HTF版本允许在更高时间框架上应用该指标同时在当前图表上显示。

策略分析

该指标的核心策略概念是衡量短期波动率（6周期）相对于长期波动率（100周期）的比值，用于判断市场波动率的变化趋势。入场条件方面，该指标本身不执行交易，而是作为辅助分析工具——当HVR值大于1时表明短期波动率高于长期波动率，市场可能处于活跃或突破阶段；当HVR值小于1时表明短期波动率收敛，市场可能进入盘整。出场条件不适用，因为这是纯指标而非交易系统。仓位管理和资金管理均不涉及，指标仅输出比值数据。计算方法采用对数收益率的样本标准差，并乘以年化因子√252≈15.8114（代码中7.2111*2=√252*√2≈√504）进行年化处理，使用循环缓冲区Count[]来高效管理滚动窗口数据。

Summary

HVR (Historical Volatility Ratio) is a custom indicator that calculates the ratio of 6-period historical volatility to 100-period historical volatility, displayed in a separate window. It uses log returns of a selectable applied price and computes annualized standard deviation for both windows. The HTF version allows applying this indicator on a higher timeframe while displaying on the current chart.

Strategy Analysis

The core strategy concept of this indicator is measuring the ratio of short-term volatility (6-period) to long-term volatility (100-period), used to identify changes in market volatility regimes. Regarding entry conditions, the indicator itself does not execute trades but serves as an analytical tool—when HVR exceeds 1, short-term volatility exceeds long-term volatility, suggesting an active or breakout market phase; when HVR falls below 1, short-term volatility is converging, suggesting consolidation. Exit conditions are not applicable since this is a pure indicator rather than a trading system. Position sizing and money management are not involved as the indicator only outputs ratio data. The calculation method uses log returns of the selected price type, computes sample standard deviation, and multiplies by an annualization factor of approximately √252 (implemented as 7.211102550927978 * 2 in code, where 7.2111 ≈ √52 for weekly scaling). A circular buffer (Count[]) is used to efficiently manage the rolling window data without reallocating arrays each bar.

优势

  • 波动率比率是一个成熟且广泛使用的分析概念，能有效识别波动率扩张与收缩周期
  • 采用循环缓冲区Count[]管理滚动窗口，避免每根K线重新分配内存，计算效率较高
  • 支持12种不同的应用价格类型，灵活性很强，适应不同交易风格的需求

劣势

  • 代码中存在明显的bug：第151行和第152行的for循环将值赋给同一个x6[bar0]和x100[bar0]，后一次赋值覆盖前一次，导致x6数组实际上只保存了6个周期前的diff值而非完整的6个元素集合
  • 缺少波动率计算的N值（窗口大小）作为可调输入参数，100和6被硬编码，用户无法根据不同市场调整周期
  • 注释为乱码（编码问题导致中文注释无法正常显示），严重影响代码可读性和可维护性

改进建议

  • 修复x6和x100数组的赋值bug，应该将diff值分别存入x6和x100数组的不同位置而非覆盖同一索引
  • 将短期和长期波动率窗口周期（目前硬编码为6和100）改为可调输入参数，增强适应性

Strengths

  • Volatility ratio is a well-established analytical concept that effectively identifies volatility expansion and contraction cycles
  • Uses a circular buffer (Count[]) to manage rolling windows, avoiding memory reallocation each bar for efficient computation
  • Supports 12 different applied price types providing strong flexibility to accommodate various trading styles

Weaknesses

  • Critical bug in lines 151-152: the for loops assign to the same x6[bar0] and x100[bar0] index each iteration, so the last iteration overwrites previous values, meaning x6 and x100 arrays don't actually store the full element sets as intended
  • The volatility window sizes (6 and 100) are hardcoded rather than exposed as adjustable input parameters, preventing users from tuning periods for different markets
  • Comments are garbled due to encoding issues (Cyrillic text displayed as mojibake), severely hurting code readability and maintainability

Improvements

  • Fix the x6 and x100 array assignment bug—diff values should be stored at different indices in each array rather than overwriting the same bar0 index on each loop iteration
  • Convert the hardcoded volatility window periods (6 and 100) into adjustable input parameters for better adaptability to different markets and timeframes
