Futures Portfolio Control Expiration

This EA manages a portfolio of up to 3 futures contracts by automatically rolling positions to the next expiration month when the current contract nears expiration. It continuously monitors SYMBOL_EXPIRATION_TIME and closes/rolls positions before the cutoff. The user pre-configures symbols and lot sizes (positive for long, negative for short) to maintain a hedged portfolio.

Strategy analysis

The core concept of this EA is futures portfolio expiration roll management rather than a traditional directional trading strategy. Entry conditions are simple: when no position exists on a selected futures contract, it automatically opens one based on the pre-configured lot size — positive lots for long positions, negative lots for short positions. The sole exit condition is when the contract's expiration time is within hours_before_expiration hours from the current time, at which point it closes the position and rolls to the next month's contract. Position sizing is entirely user-configured with no dynamic adjustment or money management logic. The EA uses Sleep(3000) for delay operations, which is not best practice in MQL5 as it blocks the entire EA thread. The NextFutures function logic is somewhat complex, iterating through the next 12 months to find the next unexpired contract, but it has a potential flaw — when currtime!=0, it stops as soon as it finds a contract with expiration beyond currtime, which may not always select the correct next contract in all scenarios.

Strengths

  • Automatic roll-over functionality avoids the risk of futures contract expiration/delivery, which is very practical for traders holding long-term portfolio positions
  • Supports multi-symbol portfolio management (up to 3 contracts) with mixed long/short configuration, suitable for hedging strategies
  • Clean and straightforward code that is easy to understand and modify for users' specific needs

Weaknesses

  • Uses Sleep(3000) which blocks the EA thread and can delay processing of other symbol ticks — not a recommended practice in MQL5
  • No stop-loss or risk management mechanism — if roll-over fails or contract lookup errors occur, the portfolio may be left with naked exposure
  • NextFutures contract lookup logic has a flaw: it stops at the first contract with expiration beyond currtime, potentially skipping the correct next near-month contract
  • Lot parameter type is int but default values contain decimal points, causing type mismatch that may lead to compilation warnings or precision loss

Possible improvements

  • Remove Sleep() calls and use event-driven or timer-based approaches for roll-over operations to avoid blocking the EA thread
  • Add error handling and retry mechanisms to ensure roll-over reliability, such as checking trade return values and order status
  • Change Lot parameter type to double for more precise position sizing, and add maximum position limits and stop-loss parameters

Risk assessment

Overall risk: Medium

  • No stop-loss mechanism — portfolio may face unhedged market risk if roll-over fails
  • Sleep() blocking may cause missed critical ticks or roll-over timing
  • Contract lookup logic may select the wrong month contract, resulting in positions on inappropriate contracts
