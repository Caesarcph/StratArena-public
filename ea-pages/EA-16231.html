摘要

该EA利用ZigZag指标识别波段高低点，然后在最近的ZigZag波段上构建斐波那契回撤水平。在上升趋势中价格突破斐波那契支撑位时做多，在下降趋势中价格跌破斐波那契阻力位时做空，止损和止盈基于斐波那契扩展计算。

策略分析

策略概念基于斐波那契回撤理论，认为价格在趋势中会回撤至特定斐波那契比例水平后继续原趋势方向运行。入场条件：在上升趋势中，当收盘价突破23.6%、38.2%、61.8%或76.4%回撤位且前一根K线收盘价低于该水平时做多；在下降趋势中，当收盘价跌破上述回撤位且前一根K线收盘价高于该水平时做空。出场条件：止损设在固定点数（StopLossLevel参数）距离处，止盈设在Fibo00加上TakeProfitAt乘以FiboBASE的斐波那契扩展位。仓位管理采用固定手数（TradeValue参数），没有动态仓位调整机制。资金管理方面缺乏最大回撤控制、最大持仓限制和风险比例计算，仅依赖固定止损和止盈。趋势判断通过CheckTrend函数比较最近四个ZigZag拐点的高低关系来确定。

Summary

This EA uses ZigZag indicator to identify swing highs and lows, then constructs Fibonacci retracement levels on the most recent ZigZag leg. It enters buy trades when price crosses above Fibonacci support levels in an uptrend, and sell trades when price crosses below Fibonacci resistance levels in a downtrend, with stop-loss and take-profit based on Fibonacci extension.

Strategy Analysis

The strategy concept is based on Fibonacci retracement theory, assuming that price retraces to specific Fibonacci ratio levels within a trend before continuing in the original direction. Entry conditions: in an uptrend, buy when the close price breaks above the 23.6%, 38.2%, 61.8%, or 76.4% retracement level while the previous bar's close was below that level; in a downtrend, sell when the close price breaks below those retracement levels while the previous bar's close was above. Exit conditions: stop-loss is set at a fixed point distance (StopLossLevel parameter) from the entry price, and take-profit is set at the Fibo00 level plus TakeProfitAt multiplied by FiboBASE (Fibonacci extension). Position sizing uses a fixed lot size (TradeValue parameter) with no dynamic position adjustment mechanism. Money management lacks maximum drawdown control, maximum position limits, and risk-per-trade percentage calculation, relying solely on fixed stop-loss and take-profit. Trend determination is performed by the CheckTrend function comparing the relative heights of the four most recent ZigZag pivot points.

优势

  • 基于经典的斐波那契回撤理论，逻辑清晰易懂
  • 使用ZigZag指标自动识别波段拐点，避免主观判断
  • 有明确的止损和止盈机制，不完全裸露风险
  • 趋势过滤机制避免在震荡行情中频繁交易
  • 交易间隔控制（CloseBarPause）防止止损后立即重入

劣势

  • CheckTrend函数返回类型声明为bool但实际返回int值(-1,0,1)，存在类型不匹配的严重bug
  • 做空条件判断中写了'Buy condition is TRUE'，实际应为Sell，属于复制粘贴错误
  • TradeCheck函数中case 2(卖出)永远不会被调用，因为传入参数是-1而非2
  • 固定手数交易没有根据账户资金或波动率进行动态调整
  • 止损仅15点，在波动较大的市场中极易被扫损
  • OnTrade中StringFind返回值判断逻辑有误，应与-1比较而非作为布尔值使用

改进建议

  • 修复CheckTrend函数的返回类型为int，修复TradeCheck中sell分支的case值从2改为-1，修正所有复制粘贴错误
  • 增加动态仓位管理，根据ATR或账户风险比例计算手数，并加入最大回撤保护和最大持仓限制
  • 增加点差过滤和滑点保护，避免在高点差环境下入场，同时加入新K线判断防止同根K线重复交易

Strengths

  • Based on the classic Fibonacci retracement theory with clear and understandable logic
  • Uses ZigZag indicator to automatically identify swing pivots, avoiding subjective judgment
  • Has explicit stop-loss and take-profit mechanisms, not leaving risk entirely naked
  • Trend filter mechanism avoids frequent trading in ranging markets
  • Trade pause control (CloseBarPause) prevents immediate re-entry after stop-loss

Weaknesses

  • CheckTrend function is declared as returning bool but actually returns int values (-1, 0, 1), a serious type mismatch bug
  • In the sell condition block, the print message says 'Buy condition is TRUE' instead of 'Sell', a copy-paste error
  • TradeCheck function case 2 (sell) is never reachable because the passed parameter is -1 not 2
  • Fixed lot sizing with no dynamic adjustment based on account equity or volatility
  • Stop-loss of only 15 points is extremely tight and prone to being stopped out in volatile markets
  • OnTrade function's StringFind return value check is incorrect - should compare with -1, not use as boolean

Improvements

  • Fix CheckTrend return type to int, fix TradeCheck sell branch case value from 2 to -1, and correct all copy-paste errors
  • Add dynamic position sizing based on ATR or account risk percentage, and implement maximum drawdown protection and maximum position limits
  • Add spread filter and slippage protection to avoid entering trades in high-spread environments, and add new bar detection to prevent duplicate trades on the same bar

风险点

  • CheckTrend返回类型为bool但实际返回int，可能导致趋势判断失败或未定义行为
  • TradeCheck的sell分支(case 2)永远无法执行，做空信号实际上不会下单
  • 固定15点止损过小，在正常市场波动下极易触发止损
  • 没有点差过滤，高点差时入场会显著增加交易成本
  • 没有检查新K线，可能在同一根K线上重复发送交易请求

Risk Assessment

Overall:HIGH

Risk Points

  • CheckTrend returns int but is declared as bool, potentially causing trend detection failure or undefined behavior
  • TradeCheck's sell branch (case 2) is unreachable, so sell signals will never actually place orders
  • Fixed 15-point stop-loss is too tight and easily triggered by normal market noise
  • No spread filter means entering during high-spread conditions significantly increases trading costs
  • No new bar check means duplicate trade requests could be sent on the same bar
