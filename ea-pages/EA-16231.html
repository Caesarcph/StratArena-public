摘要

该EA利用ZigZag指标识别波段高低点，在最近的ZigZag段上绘制斐波那契回撤位。在上升趋势中价格从斐波那契支撑位反弹时做多，在下降趋势中价格从斐波那契阻力位回落时做空，止损为固定点数，止盈基于斐波那契扩展。

策略分析

策略概念基于斐波那契回撤理论，使用ZigZag指标自动识别波段的四个极值点(HL0-HL3)来判断趋势方向和绘制回撤位。入场条件分为两种：上升趋势中，当K线收盘价突破23.6%、38.2%、61.8%或76.4%回撤位且前一根K线收盘价在该位之下时买入；下降趋势中则反之。出场条件依赖固定点数止损（StopLossLevel参数）和基于斐波那契扩展的止盈（TakeProfitAt乘以FiboBASE）。仓位管理采用固定手数（TradeValue参数），没有根据账户资金或波动性进行动态调整。资金管理方面几乎为空白，没有最大持仓限制、没有回撤控制、没有资金百分比计算。此外，CloseBarPause参数提供了一定的交易间隔控制，防止连续亏损后立即重仓入场。

Summary

This EA uses ZigZag indicator to identify swing highs and lows, then draws Fibonacci retracement levels on the most recent ZigZag leg. It enters buy trades when price bounces above a Fibonacci level in an uptrend, and sell trades when price falls below a Fibonacci level in a downtrend, with fixed stop-loss and Fibonacci-extension-based take-profit.

Strategy Analysis

The strategy concept is based on Fibonacci retracement theory, using the ZigZag indicator to automatically identify four swing extremum points (HL0-HL3) for trend determination and retracement level drawing. Entry conditions are twofold: in an uptrend, a buy is triggered when the current bar's close breaks above one of the 23.6%, 38.2%, 61.8%, or 76.4% retracement levels while the previous bar's close was below that level; in a downtrend, the mirror condition triggers a sell. Exit conditions rely on a fixed-point stop-loss (StopLossLevel parameter) and a Fibonacci-extension-based take-profit (TakeProfitAt multiplied by FiboBASE). Position sizing uses a fixed lot size (TradeValue parameter) with no dynamic adjustment based on account equity or volatility. Money management is essentially absent—there is no maximum position limit, no drawdown control, and no percentage-of-equity calculation. The CloseBarPause parameter provides some trade interval control to prevent immediate re-entry after a stop-loss close.

优势

  • 策略逻辑清晰，基于经典的斐波那契回撤理论，技术面依据充分
  • 使用ZigZag自动识别波段，避免手动绘制斐波那契的主观性
  • CloseBarPause机制防止止损后立即重仓入场，有一定的交易节奏控制
  • 止损和止盈均有明确定义，不是裸单交易
  • SafetyBuffer参数提供价格突破确认缓冲，减少假信号

劣势

  • CheckTrend函数返回类型声明为bool但实际返回int（0/1/-1），存在严重的类型错误，可能导致趋势判断失效
  • TradeCheck函数中deal参数传入-1（卖）但switch只处理1和2，卖单永远不会执行，这是致命的逻辑bug
  • 固定手数无资金管理，在不同账户规模下风险暴露差异巨大
  • 止损仅15点过于紧缩，在波动性较大的品种上极易被扫损
  • OnTrade中StringFind对'sl'的判断逻辑有误——StringFind返回-1表示未找到，但当前代码在找到时返回非-1值仍为true
  • ZigZag指标有重绘特性，基于重绘后的波段点做决策存在前视偏差

改进建议

  • 修复CheckTrend的返回类型为int，修复TradeCheck的switch分支以正确处理卖单（case -1）
  • 加入动态仓位管理，根据账户余额百分比或ATR波动率自动调整手数
  • 增加点差过滤和最大回撤限制，提高策略在真实交易环境中的鲁棒性

Strengths

  • Clear strategy logic based on the well-established Fibonacci retracement theory with solid technical foundation
  • Automatic swing identification via ZigZag eliminates the subjectivity of manual Fibonacci drawing
  • CloseBarPause mechanism prevents immediate re-entry after a stop-loss, providing trade pacing control
  • Both stop-loss and take-profit are explicitly defined, avoiding naked positions
  • SafetyBuffer parameter provides price breakout confirmation cushion, reducing false signals

Weaknesses

  • CheckTrend function declares return type bool but actually returns int (0/1/-1), a critical type mismatch that may cause trend detection to fail
  • TradeCheck function receives deal=-1 for sells but the switch only handles cases 1 and 2, so sell orders never execute—this is a fatal logic bug
  • Fixed lot size with no money management means risk exposure varies drastically across different account sizes
  • Stop-loss of only 15 points is extremely tight and prone to being stopped out on volatile instruments
  • OnTrade's StringFind logic for 'sl' is inverted—StringFind returns -1 when not found, but the current code treats non-(-1) as truthy incorrectly
  • ZigZag indicator has repainting characteristics, creating look-ahead bias when decisions are based on repainted swing points

Improvements

  • Fix CheckTrend return type to int, and fix TradeCheck switch to properly handle sell orders (case -1 instead of case 2)
  • Add dynamic position sizing based on account equity percentage or ATR-based volatility adjustment
  • Add spread filtering and maximum drawdown limits to improve robustness in live trading environments
