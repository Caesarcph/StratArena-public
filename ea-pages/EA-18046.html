摘要

SaveTicks是一个工具型EA，按可配置的毫秒间隔将多个交易品种的tick数据（买价/卖价）记录到CSV和/或二进制文件中。它支持从市场报价、所有可用品种或自定义文件列表中选择品种，并可使用服务器时间或本地时间进行记录。

策略分析

SaveTicks并非交易策略EA，而是一个数据采集工具。它通过定时器（EventSetMillisecondTimer）按用户设定的毫秒间隔循环采集所有指定品种的最新tick数据。入场条件不适用，因为该EA不执行任何交易操作。出场条件同样不适用。仓位管理和资金管理均不涉及，因为EA仅进行数据记录。其核心功能是将SymbolInfoTick获取的MqlTick结构体中的bid和ask价格，配合时间戳写入文件，支持CSV文本格式和二进制格式两种存储方式，并可同时输出两种格式。该EA的用途是为后续的量化分析、回测或策略开发提供高质量的原始tick数据基础。

Summary

SaveTicks is a utility Expert Advisor that records tick data (bid/ask) for multiple symbols into CSV and/or binary files at a configurable millisecond interval. It supports selecting symbols from Market Watch, all available symbols, or a custom file-based list, and can record using either server or local time.

Strategy Analysis

SaveTicks is not a trading strategy EA but rather a data collection utility tool. It uses a millisecond-resolution timer (EventSetMillisecondTimer) to periodically sample the latest tick data for all specified symbols at a user-configurable interval. Entry conditions are not applicable since this EA does not execute any trading operations. Exit conditions are likewise not applicable. Position sizing and money management are completely absent as the EA only performs data logging. Its core function is to write the bid and ask prices from the MqlTick structure obtained via SymbolInfoTick, along with timestamps, to files in either CSV text format or binary format, or both simultaneously. The EA's purpose is to provide high-quality raw tick data as a foundation for subsequent quantitative analysis, backtesting, or strategy development.

优势

  • 支持多品种同时采集tick数据，覆盖面广
  • 提供CSV和二进制两种格式，CSV便于人工查看，二进制便于程序高效读取
  • 品种来源灵活，支持市场报价、全部品种和自定义文件三种方式
  • 使用毫秒级定时器，采样精度高，可按需调整间隔

劣势

  • 定时器间隔内可能丢失tick，非逐tick记录而是轮询采样
  • 文件句柄在OnInit中打开但OnDeinit仅关闭CSV和二进制句柄，缺少异常状态下的资源清理保障
  • 没有文件大小限制或自动归档机制，长时间运行可能产生超大文件
  • LoadSymbolList中信任文件内容未做充分校验，可能导致异常
  • 无数据完整性校验，如写入失败时无重试或告警机制

改进建议

  • 增加逐tick模式（使用OnBookEvent）替代纯定时器轮询，确保不遗漏任何tick
  • 添加文件大小监控和自动分割归档功能，防止生成超大文件
  • 增强LoadSymbolList的输入校验，如品种有效性检查和数量上限限制

Strengths

  • Supports simultaneous tick data collection for multiple symbols with broad coverage
  • Provides both CSV and binary formats — CSV for human readability and binary for efficient programmatic access
  • Flexible symbol source selection from Market Watch, all symbols, or custom file-based lists
  • Uses millisecond-resolution timer for high-precision sampling with configurable intervals

Weaknesses

  • Polling-based sampling may miss ticks between timer intervals — not true tick-by-tick recording
  • File handles are opened in OnInit but OnDeinit only closes CSV and binary handles without robust cleanup for abnormal states
  • No file size limit or auto-archiving mechanism — long-running sessions may produce extremely large files
  • LoadSymbolList trusts file contents without sufficient validation, potentially causing exceptions
  • No data integrity verification — no retry or alert mechanism when write operations fail

Improvements

  • Add a true tick-by-tick mode using OnBookEvent instead of pure timer polling to ensure no ticks are missed
  • Add file size monitoring and automatic splitting/archiving to prevent excessively large files
  • Enhance input validation in LoadSymbolList with symbol validity checks and upper quantity limits
