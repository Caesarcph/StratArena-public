摘要

该EA基于自适应市场水平（AML）自定义指标进行交易，该指标利用分形维度分析来自适应平滑价格数据。当AML值位于K线的开盘价-收盘价范围内时开仓做多或做空，并可选择在出现反向信号时反转持仓。仓位大小可根据账户余额相对于最大回撤阈值进行动态调整。

策略分析

策略概念基于自适应市场水平（AML）指标，该指标通过计算分形维度来衡量市场效率，并据此动态调整平滑因子alpha。入场条件为：当AML值位于前一根K线的开盘价和收盘价之间时触发交易——若开盘价低于收盘价（阳线）且AML值在两者之间则做多，若开盘价高于收盘价（阴线）且AML值在两者之间则做空。出场条件依赖固定的止损和止盈水平，分别在SL和TP参数设定的点数处设置。当启用use_opposite参数时，如果当前持仓方向与新的信号方向相反，EA会先平仓再反向开仓。仓位管理方面，提供了固定手数和基于账户余额的动态手数两种模式，动态模式下手数按（Lots×余额/Max_drawdown）计算。资金管理较为简单，动态手数模式下设有最大手数限制，但没有回撤保护或权益监控机制。

Summary

This EA trades based on the Adaptive Market Level (AML) custom indicator, which uses fractal dimension analysis to adaptively smooth price data. It opens buy or sell positions when the AML value lies within the bar's open-close range, and optionally reverses positions on opposite signals. Position sizing can be dynamically adjusted based on account balance relative to a maximum drawdown threshold.

Strategy Analysis

The strategy concept is based on the Adaptive Market Level (AML) indicator, which computes fractal dimension to measure market efficiency and dynamically adjusts the smoothing factor alpha accordingly. Entry conditions are triggered when the AML value falls within the previous bar's open-close range: a buy is opened when the open is below the close (bullish bar) and AML lies between them, while a sell is opened when the open is above the close (bearish bar) and AML lies between them. Exit conditions rely on fixed stop-loss and take-profit levels set at SL and TP parameter values in points respectively. When the use_opposite parameter is enabled, the EA closes the current position and opens a reverse one if the existing position direction conflicts with the new signal. Position sizing offers both fixed lot and dynamic lot modes, with the dynamic mode calculating lots as (Lots × Balance / Max_drawdown). Money management is relatively simple — the dynamic lot mode enforces a maximum volume cap but lacks drawdown protection or equity monitoring mechanisms.

优势

  • 使用自适应市场水平指标，基于分形维度动态调整平滑因子，具有一定的市场适应性
  • 提供固定手数和动态手数两种仓位管理模式，灵活性较好
  • 支持反向信号反转持仓功能，能及时捕捉趋势变化
  • 止损止盈修改失败后有重试机制，提高了订单设置的可靠性
  • 每根新K线仅计算一次，避免了同一K线内的重复交易

劣势

  • 仅支持单品种单持仓交易，无法同时管理多个交易品种
  • SL/TP修改请求中未设置position ticket，可能导致修改失败或修改错误持仓
  • 动态手数模式下Max_drawdown参数仅用于计算手数比例，并非真正的回撤保护机制
  • close()函数中错误处理不当，调用GetLastError()但未打印错误信息，且未处理OrderSend失败情况
  • 止损500点而止盈3500点的TP/SL比例看似合理，但缺乏对市场波动率的动态调整

改进建议

  • 在SL/TP修改请求中添加position ticket字段（通过PositionGetInteger(POSITION_TICKET)获取），确保修改正确的持仓
  • 增加真正的回撤保护机制，如当账户浮亏达到一定比例时停止开新仓或强制平仓
  • 改进close()函数的错误处理，记录错误代码和详细信息，便于调试和监控
  • 增加对持仓状态的更完整检查，支持多品种多持仓的并发管理

Strengths

  • Uses the Adaptive Market Level indicator with fractal dimension to dynamically adjust the smoothing factor, offering market adaptiveness
  • Provides both fixed lot and dynamic lot position sizing modes with reasonable flexibility
  • Supports position reversal on opposite signals, enabling timely capture of trend changes
  • Implements a retry mechanism for SL/TP modification failures, improving order setup reliability
  • Calculates only once per new bar, preventing redundant trades within the same candle

Weaknesses

  • Only supports single-symbol single-position trading, unable to manage multiple instruments simultaneously
  • The SL/TP modification request does not include the position ticket, which may cause modification failure or modify the wrong position
  • The Max_drawdown parameter in dynamic lot mode is only used for lot ratio calculation, not a true drawdown protection mechanism
  • Poor error handling in the close() function — GetLastError() is called but error info is not printed, and OrderSend failure is not properly handled
  • The 500-point SL vs 3500-point TP ratio appears reasonable but lacks dynamic adjustment based on market volatility

Improvements

  • Add the position ticket field to SL/TP modification requests (obtained via PositionGetInteger(POSITION_TICKET)) to ensure the correct position is modified
  • Implement a genuine drawdown protection mechanism, such as stopping new trades or forcing closure when account floating loss reaches a certain percentage
  • Improve error handling in the close() function by logging error codes and detailed information for debugging and monitoring
  • Add more comprehensive position state checks and support concurrent management of multiple instruments and positions
