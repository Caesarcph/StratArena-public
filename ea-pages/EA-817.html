摘要

这个EA是一个多终端价格监控工具，通过内存映射文件（DLL共享内存）在同一台机器上的多个MetaTrader 5实例之间交换买入价。它持续将自身终端的买入价写入共享内存，并读取其他已连接终端的买入价，在图表上显示水平价格线进行比较。它不进行任何交易，纯粹是监控和价格比较工具。

策略分析

此EA并非交易策略EA，而是一个基于共享内存的跨终端价格监控工具。其核心概念是利用Windows内存映射文件机制，在运行于同一台机器上的多个MT5终端之间实时共享报价数据。每个终端实例在初始化时打开或创建共享内存文件，注册自身为一个使用者，并分配一个数据槽位用于写入。在OnTick的无限循环中，每个实例持续将当前Bid价格、账户登录号、时间戳和终端名称写入自己的槽位，同时读取所有其他槽位的数据。如果某个终端的数据时间戳超过MaxLate设定的延迟阈值，则认为该终端已不活跃，不显示其价格线。入场条件和出场条件在此不适用，因为该EA不进行任何交易操作。仓位管理和资金管理同样不适用。该工具的主要价值在于让交易者能够同时监控多个终端或经纪商的报价差异，便于发现套利机会或监控连接状态。

Summary

This EA is a multi-terminal price monitor that uses memory-mapped files (shared memory via DLL) to exchange bid prices between multiple MetaTrader 5 instances running on the same machine. It continuously writes its own terminal's bid price to shared memory and reads bid prices from other connected terminals, displaying horizontal price lines on the chart for comparison. It does not open any trades and serves purely as a monitoring and price comparison utility.

Strategy Analysis

This EA is not a trading strategy EA but rather a cross-terminal price monitoring tool based on shared memory. Its core concept leverages Windows memory-mapped file mechanisms to share real-time quote data between multiple MT5 terminals running on the same machine. Each terminal instance opens or creates a shared memory file during initialization, registers itself as a user, and allocates a data slot for writing. In the infinite loop within OnTick, each instance continuously writes the current Bid price, account login, timestamp, and terminal name to its own slot while reading data from all other slots. If a terminal's data timestamp exceeds the MaxLate delay threshold, that terminal is considered inactive and its price line is not displayed. Entry and exit conditions are not applicable since this EA does not perform any trading operations. Position sizing and money management are also not applicable. The tool's primary value is enabling traders to simultaneously monitor quote differences across multiple terminals or brokers, facilitating arbitrage opportunity detection or connection status monitoring.

优势

  • 利用共享内存实现高效跨进程通信，数据交换延迟极低，适合实时监控场景
  • 同时支持32位和64位终端，通过_IsX64自动判断并调用对应DLL函数，兼容性好
  • 支持多终端动态连接和断开，通过头部计数器管理使用者数量，最后一个退出时自动关闭共享内存
  • 图表上以水平线直观展示各终端报价，便于快速识别报价差异和套利机会

劣势

  • 依赖外部DLL（MemMap32.dll/MemMap64.dll），在不允许DLL加载的环境下无法运行，且存在安全风险
  • OnTick中使用无限while循环加Sleep，阻塞了EA的正常事件处理，可能导致终端响应变慢或其他EA运行异常
  • 缺少完善的错误恢复机制，当共享内存读写失败时仅打印日志，不会尝试重新连接或重建共享内存
  • 没有对共享内存数据做任何校验或加密，恶意进程可能篡改共享内存中的数据

改进建议

  • 将无限循环改为基于Timer事件或OnBookEvent的驱动模式，避免阻塞EA事件队列，提升终端整体响应性能
  • 增加共享内存连接状态的自检和自动重连机制，当检测到共享内存失效时尝试重新初始化
  • 添加数据校验机制（如CRC校验或简单的magic number），防止共享内存数据被篡改或损坏

Strengths

  • Uses shared memory for efficient inter-process communication with minimal latency, ideal for real-time monitoring
  • Supports both 32-bit and 64-bit terminals with automatic architecture detection via _IsX64, ensuring broad compatibility
  • Supports dynamic terminal connection and disconnection with a header counter managing user count; last terminal automatically closes shared memory
  • Visually displays each terminal's quote as a horizontal line on the chart, enabling quick identification of price discrepancies and arbitrage opportunities

Weaknesses

  • Depends on external DLLs (MemMap32.dll/MemMap64.dll) which cannot run in environments that disable DLL loading and introduce security risks
  • Uses an infinite while loop with Sleep in OnTick, blocking normal event processing and potentially causing terminal slowdown or conflicts with other EAs
  • Lacks robust error recovery; when shared memory read/write fails, it only prints logs without attempting to reconnect or rebuild the shared memory
  • No data validation or encryption on shared memory content, making it vulnerable to data tampering by malicious processes

Improvements

  • Replace the infinite while loop with Timer event or OnBookEvent driven mode to avoid blocking the EA event queue and improve overall terminal responsiveness
  • Add self-checking and automatic reconnection for shared memory; attempt to reinitialize when shared memory is detected as invalid
  • Implement data validation mechanisms (e.g., CRC checksum or simple magic number) to prevent shared memory data from being tampered with or corrupted
