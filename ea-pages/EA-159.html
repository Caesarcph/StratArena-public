摘要

一个基于随机入场信号的专家顾问，通过模拟抛硬币决定交易方向。它根据随机数开多或空单，设有固定止损和止盈水平。该EA明确仅用于教育目的，警告不要用于实盘交易。

策略分析

该EA的核心策略概念是使用随机数生成器模拟抛硬币来决定交易方向，完全不考虑任何技术指标或基本面分析。入场条件为：当MathRand()返回值小于16384时做多，大于等于16384时做空，这相当于50%的概率选择方向。出场条件依赖于固定点数的止损（10000点）和止盈（1000点），止盈远小于止损，属于大止损小止盈的逆风险回报比设计。仓位管理采用固定手数（0.1手），没有任何资金管理或动态仓位调整逻辑。资金管理方面完全缺失，GetSize()函数直接返回固定的Lots参数，不考虑账户余额或风险比例。该EA在每次平仓后会重新初始化系统状态，再次等待随机入场信号。

Summary

A random-entry expert advisor that simulates coin tosses to decide trade direction. It opens either a buy or sell position based on a random number, with fixed stop-loss and profit-target levels. The EA is explicitly for educational purposes and warns against live trading.

Strategy Analysis

The core strategy concept of this EA uses a random number generator to simulate coin tosses for trade direction, completely ignoring any technical indicators or fundamental analysis. Entry conditions are: go long when MathRand() returns a value below 16384, go short when 16384 or above, effectively a 50/50 probability direction choice. Exit conditions rely on fixed point-based stop-loss (10000 points) and profit-target (1000 points), with the profit target far smaller than the stop-loss, resulting in an unfavorable risk-reward ratio. Position sizing uses a fixed lot size (0.1 lots) with no dynamic position adjustment logic whatsoever. Money management is entirely absent — the GetSize() function simply returns the fixed Lots input parameter without considering account balance or risk ratios. After each position closes, the system reinitializes its state and waits for the next random entry signal.

优势

  • 代码结构清晰，采用面向对象设计，具有良好的封装性
  • 包含实盘保护机制，检测到真实账户时会弹窗警告并拒绝初始化
  • 作为教学示例，很好地展示了MQL5的OOP框架和交易类库的使用方法
  • 随机种子可选择，方便回测时复现结果

劣势

  • 策略完全依赖随机数入场，没有任何技术分析依据，本质上是赌博
  • 风险回报比极差：止损10000点对止盈1000点，盈亏比1:10，需要90%以上胜率才能盈利
  • 没有新K线检查，每个tick都会尝试入场，可能在同一根K线上频繁开仓
  • 没有点差过滤，在宽点差环境下容易因滑点造成额外损失
  • 固定手数没有资金管理，不会根据账户余额动态调整仓位

改进建议

  • 添加新K线检查逻辑，避免在同一根K线上重复入场
  • 实现基于账户风险比例的动态仓位管理，替代固定手数
  • 调整止损止盈比例至至少1:1或更优，或引入追踪止损替代固定止盈
  • 添加点差过滤和交易时段过滤，避免不利条件下入场

Strengths

  • Clean OOP code structure with good encapsulation using MQL5 framework classes
  • Includes live account protection — detects real accounts and warns with a message box before refusing to initialize
  • Serves as an excellent educational example demonstrating MQL5 OOP framework and trade library usage
  • Configurable random seed allows reproducible backtesting results when ReallyRandom=false

Weaknesses

  • Strategy relies entirely on random entry with no technical analysis basis — essentially gambling
  • Extremely poor risk-reward ratio: 10000-point stop-loss vs 1000-point profit-target (1:10 R:R), requiring over 90% win rate to be profitable
  • No new bar check means it attempts entry on every tick, potentially opening positions too frequently on the same bar
  • No spread filter, making it vulnerable to additional losses from slippage in wide-spread environments
  • Fixed lot sizing with no money management — no dynamic position adjustment based on account balance

Improvements

  • Add new bar check logic to prevent repeated entries on the same candle
  • Implement dynamic position sizing based on account risk percentage instead of fixed lots
  • Adjust stop-loss to profit-target ratio to at least 1:1 or better, or introduce trailing stop instead of fixed profit target
  • Add spread filter and trading session filter to avoid entering under unfavorable conditions

风险评估 / Risk Assessment

总体 / Overall:HIGH

风险点

  • 纯随机入场没有任何统计优势，长期必然亏损
  • 1:10的风险回报比意味着一次亏损需要十次盈利才能弥补
  • 没有新K线检查，每个tick都可能触发交易，导致过度交易
  • 没有点差检查，高波动时段可能因点差扩大而遭受额外损失

Risk Assessment

Overall:HIGH

Risk Points

  • Pure random entry provides no statistical edge, guaranteeing long-term losses
  • 1:10 risk-reward ratio means one loss requires ten wins to recover
  • No new bar check means every tick can trigger a trade, leading to over-trading
  • No spread check means high-volatility sessions can cause additional losses from widened spreads
