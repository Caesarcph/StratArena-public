摘要

HelloSmart是一个网格类EA，仅在单一方向（买入或卖出）按固定价格间隔开仓，当持仓总量超过阈值时采用类马丁格尔的仓位倍增机制。达到盈利目标或亏损限额时全部平仓并重置手数。

策略分析

该EA的核心策略是单向网格交易，根据Step参数设定的点数间隔逐步建仓。入场条件为：无持仓时开首仓，或有持仓且价格朝不利方向移动了Step点数后加仓。买入模式在价格下跌Step点后加多，卖出模式在价格上涨Step点后加空，本质上是一种逆势加仓策略。出场条件完全依赖盈亏金额阈值——当累计浮盈超过Profit美元或浮亏超过Loss美元时，一次性全部平仓。仓位管理方面，当持仓总手数达到BigLot阈值时，下一单手数乘以Mnogitel倍数，形成类马丁格尔的加仓加速效应，但手数上限为MaxLots，超过后重置为基础手数Lot。资金管理非常简陋，没有止损止盈挂在单上，仅靠整体盈亏阈值控制风险，且没有考虑点差、滑点和资金充足率。

Summary

HelloSmart is a grid-style EA that opens positions at fixed price intervals (Step) in one direction only (buy or sell), with a martingale-like lot multiplier when total volume exceeds a threshold. It closes all positions when a profit target or loss limit is hit, then resets lot size to the initial value.

Strategy Analysis

The core strategy is a one-directional grid trading system that builds positions incrementally at fixed price intervals defined by the Step parameter. Entry conditions are straightforward: open the first position when there are no positions, or add a position when price moves adversely by Step points from the reference price. In buy mode it adds longs as price drops; in sell mode it adds shorts as price rises—essentially a counter-trend averaging-down approach. Exit conditions rely solely on aggregate profit/loss thresholds: all positions close when total floating profit exceeds the Profit dollar target or floating loss exceeds the Loss dollar limit. Position sizing uses a martingale-like multiplier—when cumulative volume reaches the BigLot threshold, the next order's lot size is multiplied by Mnogitel, accelerating exposure, but is capped at MaxLots beyond which it resets to the base Lot value. Money management is rudimentary with no individual stop-loss or take-profit on any order, relying entirely on the aggregate P/L gate, and it ignores spread, slippage, and margin sufficiency.

优势

  • 逻辑简单直观，易于理解和调参
  • 有全局盈利和亏损阈值作为风控底线
  • MaxLots手数上限避免了无限倍增的极端情况
  • 新K线检测防止同根K线重复开仓

劣势

  • 类马丁格尔倍增机制在极端行情下可迅速爆仓
  • 单笔订单无止损止盈，完全依赖整体盈亏控制
  • SymbProfit和Lots函数遍历逻辑有bug，pos.Select应传入索引而非品种名
  • 未考虑点差和滑点，短线网格容易因点差亏损
  • 盈利60美元vs亏损5100美元的盈亏比极度失衡
  • 没有资金和保证金检查，可能在加仓时因保证金不足而失败

改进建议

  • 修复pos.Select的调用bug，应先通过PositionGetSymbol或按索引选择仓位再筛选品种
  • 为每笔订单设置独立止损止盈，减少无保护敞口风险
  • 增加保证金充足率检查和最大持仓数量限制
  • 加入点差过滤，避免高点差时段加仓

Strengths

  • Simple and intuitive logic, easy to understand and tune parameters
  • Has global profit and loss thresholds as a risk control floor
  • MaxLots cap prevents infinite lot multiplication in extreme scenarios
  • New bar check prevents duplicate orders on the same candle

Weaknesses

  • Martingale-like lot multiplication can blow the account rapidly in extreme markets
  • No individual stop-loss or take-profit on orders, relying entirely on aggregate P/L control
  • Bug in SymbProfit and Lots functions: pos.Select expects an index but receives a symbol name, causing incorrect profit/lot calculations
  • No spread or slippage filter, short-interval grid is vulnerable to spread costs
  • Profit $60 vs Loss $5100 creates an extremely skewed risk-reward ratio
  • No margin check before opening new positions, risk of order failure due to insufficient margin

Improvements

  • Fix the pos.Select bug—use PositionGetSymbol or iterate by index then filter by symbol name
  • Set individual stop-loss and take-profit for each order to reduce unprotected exposure
  • Add margin sufficiency checks and a maximum position count limit
  • Add a spread filter to avoid adding positions during high-spread periods

风险点

  • 类马丁格尔手数倍增可在连续不利行情中快速放大风险敞口至爆仓
  • 单笔无止损，完全依赖全局亏损阈值，极端跳空可能直接穿越阈值
  • 盈亏比严重失衡（60:5100），需要极高的胜率才能长期存活
  • 代码bug导致盈亏和持仓量计算错误，可能在错误的时机平仓或加仓

Risk Assessment

Overall:DANGEROUS

Risk Points

  • Martingale-like lot multiplication can rapidly amplify exposure to account-blowing levels in consecutive adverse moves
  • No per-order stop-loss means a gap can blow past the loss threshold before the EA can react
  • Severely skewed risk-reward ratio (60:5100) demands an unrealistically high win rate for long-term survival
  • Code bug causes incorrect profit and volume calculations, potentially triggering closes or additions at wrong times
