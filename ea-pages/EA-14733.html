摘要

一个半自动EA，用户通过点击图表上的买入/卖出按钮，使用OrderSendAsync()异步函数下单。止损和止盈基于26根K线的最高价和最低价计算，并包含基于账户风险百分比的自动手数计算功能。

策略分析

该EA的策略概念是基于N周期最高价和最低价的突破交易，属于通道突破类策略。入场条件是用户手动点击图表上的Buy或Sell按钮，EA不自动入场，属于半自动交易。出场条件依赖止损和止盈，止损设在26周期极值的另一侧加2倍点差偏移，止盈设在极值方向加2倍点差偏移，当止损或止盈距当前价格不足20点时会额外偏移minstop个点。仓位管理通过TradeSize()函数实现，根据账户余额和风险百分比自动计算手数，并受合约规模和杠杆影响。资金管理方面，使用RiskPercentage参数控制每笔交易的风险比例，但计算方式是按余额百分比直接除以合约价值/杠杆，而非基于止损距离的风险计算，这可能导致实际风险与预期不符。整体策略简单直接，但缺少对市场趋势方向的判断，完全依赖用户决策。

Summary

A semi-automated Expert Advisor that places Buy/Sell orders via asynchronous OrderSendAsync() when the user clicks chart buttons. It calculates stop-loss and take-profit based on the highest and lowest prices over a 26-bar lookback period, and includes automatic lot sizing based on account risk percentage.

Strategy Analysis

The EA's strategy concept is based on N-period high/low breakout trading, falling into the channel breakout category. Entry conditions are manual — the user clicks Buy or Sell buttons on the chart, so the EA does not auto-enter trades, making it semi-automated. Exit conditions rely on stop-loss and take-profit, where the SL is placed on the opposite side of the 26-period extreme plus a 2-spread offset, and TP is placed in the direction of the extreme plus a 2-spread offset; when SL or TP is within 20 points of current price, an additional minstop-point offset is applied. Position sizing is implemented via the TradeSize() function, which calculates lot size based on account balance and risk percentage, factoring in contract size and leverage. Money management uses the RiskPercentage parameter to control risk per trade, but the calculation divides the risked balance by contract value/leverage rather than computing risk based on stop-loss distance, which may result in actual risk deviating significantly from expectations. The overall strategy is straightforward but lacks any trend direction judgment, relying entirely on the user's decision.

优势

  • 使用OrderSendAsync()异步下单，不阻塞主线程，适合高频操作场景
  • 包含自动手数计算功能，根据账户余额和风险百分比动态调整仓位
  • 有止损止盈保护机制，且在距离不足时自动偏移，避免过小的止损止盈
  • 包含自动交易权限检查和账户交易权限检查，防止在禁止交易的环境下运行
  • 使用OnTrade()事件处理函数跟踪交易状态变化，便于调试和监控

劣势

  • 资金管理计算方式有缺陷：使用余额/合约价值而非基于止损距离计算风险，实际每笔交易风险不可控
  • iHighest和iLowest函数存在数组越界风险，循环从depth到startPos但未检查depth是否超出数组大小
  • 缺少持仓检查和重复下单保护，用户可能多次点击按钮导致重复开仓
  • 止损止盈逻辑在BuyAsync中tp基于最高价计算但对买入来说方向可能有误，逻辑不够清晰
  • 使用OrderSendAsync()但不检查返回结果的retcode是否为交易成功，仅检查函数调用是否成功
  • 硬编码的参数（xhilo=26, minstop=28）未暴露为可配置输入变量，缺乏灵活性

改进建议

  • 改进资金管理算法：应基于止损距离和风险百分比计算手数，确保每笔交易的最大亏损金额可控
  • 将硬编码参数（xhilo、minstop、20点最小距离阈值等）暴露为可配置的输入变量
  • 增加持仓检查和订单重复提交保护，防止用户多次点击导致重复开仓
  • 在OrderSendAsync()调用后增加retcode详细检查和交易结果回调处理，确保异步订单状态可追踪

Strengths

  • Uses OrderSendAsync() for non-blocking trade execution, suitable for high-frequency operation scenarios
  • Includes automatic lot sizing based on account balance and risk percentage for dynamic position adjustment
  • Has SL/TP protection with automatic offset when distances are insufficient, avoiding overly tight stops
  • Performs autotrading permission and account trading permission checks to prevent running in restricted environments
  • Uses OnTrade() event handler to track trading state changes, useful for debugging and monitoring

Weaknesses

  • Flawed money management calculation: uses balance/contract value instead of risk-based sizing on stop-loss distance, making actual per-trade risk uncontrollable
  • iHighest/iLowest functions have array out-of-bounds risk; loop iterates from depth to startPos without validating depth against array size
  • Lacks position check and duplicate order protection; users may click buttons multiple times causing repeated position openings
  • SL/TP logic in BuyAsync calculates TP based on highest price but the directional logic may be incorrect for buy orders, lacking clarity
  • Uses OrderSendAsync() but only checks if the function call succeeded, not whether the retcode indicates actual trade success
  • Hardcoded parameters (xhilo=26, minstop=28) are not exposed as configurable input variables, limiting flexibility

Improvements

  • Improve money management algorithm: calculate lot size based on stop-loss distance and risk percentage to ensure maximum loss per trade is controllable
  • Expose hardcoded parameters (xhilo, minstop, 20-point minimum distance threshold, etc.) as configurable input variables
  • Add position checking and duplicate order submission protection to prevent repeated openings from multiple button clicks
  • Add detailed retcode checking and trade result callback handling after OrderSendAsync() calls to ensure async order status is trackable
