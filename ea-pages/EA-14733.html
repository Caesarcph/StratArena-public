摘要

一个半自动EA，通过图表上的买入/卖出按钮手动执行交易，使用OrderSendAsync()发送异步订单。它基于可配置回溯周期内的最高价和最低价计算止损和止盈水平，并包含基于账户风险百分比的自动仓位计算功能。

策略分析

该EA是一个基于价格突破的半自动交易工具，不自动产生交易信号，而是由交易者通过点击Buy/Sell按钮手动触发入场。入场条件为交易者主观判断后点击按钮，EA随后根据最近26根K线的最高价和最低价自动计算止损和止盈。买入止损设为最低价减去两倍点差，止盈设为最高价减去两倍点差；卖出则相反。如果止损或止盈距离当前价格过近（小于20点），则额外偏移minstop（28点）来确保最小距离。仓位管理支持两种模式：自动模式根据账户余额和风险百分比计算手数，手动模式则使用固定手数。资金管理公式为(余额×风险百分比/100)/(合约规模/杠杆)，并对手数进行标准化和上下限约束。EA使用OrderSendAsync()异步发送订单，并在OnTrade()回调中监控持仓、订单和成交的变化。

Summary

A semi-automated EA that provides Buy/Sell buttons on the chart for manual trade execution using OrderSendAsync(). It calculates stop-loss and take-profit levels based on the highest and lowest prices over a configurable lookback period, and includes automatic lot sizing based on account risk percentage.

Strategy Analysis

This EA is a semi-automated breakout-based trading tool that does not generate trading signals automatically; instead, entries are triggered manually by the trader clicking Buy/Sell buttons on the chart. Upon clicking, the EA calculates stop-loss and take-profit based on the highest and lowest prices over the last 26 bars. For a buy, SL is set at the lowest price minus two spreads, and TP is set at the highest price minus two spreads; for a sell, the logic is inverted. If the SL or TP distance from the current price is too small (less than 20 points), an additional offset of minstop (28 points) is applied to ensure a minimum distance. Position sizing supports two modes: automatic mode calculates lot size based on account balance and risk percentage, while manual mode uses a fixed lot size. The money management formula is (balance × risk% / 100) / (contract size / leverage), with normalization and min/max lot constraints applied. The EA uses OrderSendAsync() for asynchronous order sending and monitors changes in positions, orders, and deals via the OnTrade() callback.

优势

  • 使用OrderSendAsync()异步下单，不会阻塞EA主线程，适合高频操作场景
  • 具备完善的资金管理模块，根据风险百分比自动计算仓位，并考虑了杠杆和合约规模
  • 止损和止盈基于市场实际高低点动态计算，具有一定的市场适应性
  • 包含账户交易权限和自动交易权限的初始化检查，防止在不可交易环境下运行

劣势

  • iHighest和iLowest函数存在数组越界风险，当depth大于数组实际大小时可能访问非法索引
  • 使用OrderSendAsync()异步下单但不检查返回的retcode是否表示真正成交，仅检查函数调用是否成功
  • PlaySound文件名包含多余点号（"ok.wav."），可能导致音效播放失败
  • 没有持仓检查逻辑，多次点击按钮可能重复开仓，缺乏防止过度交易的机制

改进建议

  • 修复iHighest/iLowest函数中的数组越界问题，添加depth与ArraySize的边界检查
  • 添加持仓检查和订单重复检测逻辑，防止重复开仓导致风险敞口过大
  • 在OnTrade()回调中添加对异步订单结果的验证逻辑，检查retcode确认成交状态
  • 修正PlaySound文件名中的多余点号，并添加错误处理音效反馈

Strengths

  • Uses OrderSendAsync() for non-blocking order execution, suitable for high-frequency operation scenarios
  • Includes a comprehensive money management module that calculates position size based on risk percentage, leverage, and contract size
  • SL and TP are dynamically calculated from actual market highs and lows, providing market-adaptive levels
  • Performs account and terminal trading permission checks during initialization to prevent running in non-tradable environments

Weaknesses

  • iHighest and iLowest functions have array out-of-bounds risk when the depth parameter exceeds the actual array size, potentially accessing invalid indices
  • Uses OrderSendAsync() but does not verify the retcode for actual trade execution; only checks if the function call itself succeeded
  • PlaySound filename contains an extra period ("ok.wav."), which will likely cause the sound playback to fail
  • No position check logic exists; repeated button clicks can open duplicate positions without any over-trading prevention mechanism

Improvements

  • Fix array out-of-bounds issues in iHighest/iLowest functions by adding boundary checks between depth and ArraySize
  • Add position check and duplicate order detection logic to prevent repeated entries that could cause excessive risk exposure
  • Add asynchronous order result verification in OnTrade() callback by checking retcode to confirm execution status
  • Fix the extra period in the PlaySound filename and add error handling sound feedback
