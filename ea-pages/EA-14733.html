摘要

一个半自动EA，通过图表上的买入/卖出按钮使用OrderSendAsync()下单。它根据可配置回溯期内的最高价和最低价计算止盈止损，并基于风险百分比自动计算手数。该EA由用户手动点击按钮触发，而非自动信号驱动。

策略分析

策略概念是基于价格突破的半自动交易，利用26根K线回溯期内的最高价和最低价确定关键价位。入场条件为用户手动点击Buy或Sell按钮触发，买入以ASK价入场、卖出以BID价入场。出场条件为止盈和止损，买入时TP设在26周期最高价减去2倍点差、SL设在最低价减去2倍点差；卖出反之。仓位管理采用固定手数或自动计算两种模式，自动模式根据账户余额和风险百分比计算手数，并按手数步长规范化。资金管理通过RiskPercentage参数控制风险敞口，每笔交易的风险金额=余额×风险百分比/100，再根据合约大小和杠杆换算为手数。当TP或SL距离当前价格不足20点时，会额外调整minstop(28点)的距离以确保最小止损空间。

Summary

A semi-automated EA that places Buy/Sell orders via on-chart buttons using OrderSendAsync(). It calculates TP/SL based on the highest high and lowest low over a configurable lookback period, with automatic lot sizing based on risk percentage. The EA is triggered manually by the user clicking Buy or Sell buttons, not by automated signals.

Strategy Analysis

The strategy concept is semi-automated breakout trading that uses the highest high and lowest low over a 26-bar lookback period to determine key price levels. Entry conditions are user-initiated via Buy or Sell button clicks on the chart, entering at ASK for buys and BID for sells. Exit conditions use fixed TP and SL levels: for buys, TP is set at the 26-period high minus 2 spreads, and SL at the 26-period low minus 2 spreads; the logic is inverted for sells. Position sizing supports both fixed lot and auto-calculated modes, where auto mode computes lots based on account balance and risk percentage, normalized to the broker's lot step. Money management controls exposure via RiskPercentage, where risk amount per trade equals balance × risk% / 100, then converted to lots using contract size and leverage. When TP or SL distance from current price is less than 20 points, an additional minstop (28 points) adjustment is applied to ensure minimum stop distance compliance.

优势

  • 使用异步下单OrderSendAsync()提高执行效率，不阻塞EA运行
  • 具备完善的风险管理机制，包括风险百分比控制、最小止损距离检查和手数规范化
  • 自动计算仓位大小考虑了杠杆、合约大小、最小/最大手数和步长等细节
  • OnInit中包含多重前置检查（自动交易许可、账户交易权限等），启动安全性好
  • UI交互设计直观，通过按钮操作降低了手动交易的操作门槛

劣势

  • iHighest和iLowest函数存在数组越界风险，循环范围未正确绑定数组实际大小
  • 没有对CopyHigh/CopyLow的返回值进行错误检查，数据获取失败时会导致错误交易
  • 使用OrderSendAsync()异步下单但缺少OnTradeTransaction回调来确认订单状态
  • 没有检查是否已有同方向持仓，可能导致重复开仓
  • TPvsSLRatio仅在止损距离不足时生效，正常情况下TP/SL比率不受该参数控制

改进建议

  • 为iHighest/iLowest添加数组边界检查，防止越界访问导致崩溃
  • 添加OnTradeTransaction回调处理异步订单结果，确保交易状态可追踪
  • 增加持仓检查逻辑，避免同方向重复开仓；添加新K线检测防止重复触发

Strengths

  • Uses OrderSendAsync() for non-blocking order execution, improving EA responsiveness
  • Comprehensive risk management including risk percentage control, minimum stop distance checks, and lot normalization
  • Auto lot sizing accounts for leverage, contract size, min/max lots, and lot step granularity
  • OnInit performs multiple pre-checks (autotrading permission, account trade rights) for safe startup
  • Intuitive UI with Buy/Sell buttons lowers the operational barrier for manual trading decisions

Weaknesses

  • iHighest and iLowest functions have array out-of-bounds risk — loop range is not properly bound to actual array size
  • No error checking on CopyHigh/CopyLow return values; failed data retrieval could lead to incorrect trades
  • Uses OrderSendAsync() but lacks OnTradeTransaction callback to confirm order status and handle rejections
  • No check for existing positions in the same direction, potentially leading to duplicate entries
  • TPvsSLRatio only applies when stop distance is insufficient; under normal conditions TP/SL ratio is not controlled by this parameter

Improvements

  • Add array bounds checking in iHighest/iLowest to prevent out-of-bounds access crashes
  • Add OnTradeTransaction callback to handle async order results and ensure trade status is trackable
  • Add position check logic to avoid duplicate entries in the same direction; add new bar detection to prevent repeated triggers

风险评估 / Risk Assessment

总体 / Overall:MEDIUM

风险点

  • iHighest/iLowest函数数组越界风险，可能导致EA崩溃或计算错误价位
  • 异步下单缺少订单状态确认机制，订单失败可能被忽略
  • 没有持仓检查，用户可能无意中重复点击按钮导致过度开仓
  • CopyHigh/CopyLow失败时未处理，可能以零值计算SL/TP导致异常订单

Risk Assessment

Overall:MEDIUM

Risk Points

  • Array out-of-bounds risk in iHighest/iLowest could crash the EA or produce incorrect price levels
  • Async order submission lacks status confirmation; failed orders may go unnoticed
  • No position check means repeated button clicks could cause overexposure
  • Unhandled CopyHigh/CopyLow failures could result in zero-value SL/TP calculations leading to abnormal orders
