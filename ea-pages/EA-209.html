摘要

这是一个脚本而非EA，它监控市场观察窗口中所有交易品种，当任何品种出现新报价时触发自定义图表事件。它与配套EA（exOnTickMarketWatch）配合使用，后者接收并处理这些自定义事件以打印报价信息。

策略分析

此脚本没有交易策略，它是一个市场监控工具。核心概念是通过轮询方式检测市场观察窗口中所有品种的新报价。具体实现是在while循环中每隔500毫秒检查一次TimeCurrent()是否更新，若更新则遍历所有市场观察品种，比较每个品种的SYMBOL_TIME与当前报价时间，如果品种时间大于等于当前报价时间，则通过EventChartCustom发送自定义事件，事件参数包含品种索引、点差和买入价。没有入场条件、出场条件、仓位管理或资金管理，因为它不执行任何交易操作。该脚本利用_StopFlag检测用户是否终止运行，使用Sleep(500)控制轮询频率以降低CPU占用。配套EA通过OnChartEvent回调接收事件并打印品种名称、列表索引、买入价和点差信息。

Summary

This is a script (not an EA) that monitors all symbols in the Market Watch window and fires custom chart events whenever a new tick arrives on any symbol. It works in conjunction with a companion EA (exOnTickMarketWatch) that receives and processes those custom events to print tick information.

Strategy Analysis

This script has no trading strategy; it is a market monitoring utility. The core concept is to detect new ticks across all symbols in the Market Watch window through a polling mechanism. Specifically, it runs a while loop checking TimeCurrent() every 500 milliseconds, and when a new server time is detected, it iterates through all Market Watch symbols, comparing each symbol's SYMBOL_TIME against the current tick time. If a symbol's time is greater than or equal to the current tick time, it fires a custom chart event via EventChartCustom, passing the symbol index, spread, and bid price as event parameters. There are no entry conditions, exit conditions, position sizing, or money management because it does not execute any trades. The script uses _StopFlag to detect user termination and Sleep(500) to control the polling frequency and reduce CPU usage. The companion EA receives these events through the OnChartEvent callback and prints the symbol name, list index, bid price, and spread information.

优势

  • 实现了跨品种报价监控，无需为每个品种单独运行EA即可获取所有市场观察品种的报价事件
  • 使用自定义事件机制实现脚本与EA之间的解耦通信，架构设计合理
  • 通过Sleep和_StopFlag实现可控的轮询循环，兼顾性能与用户控制

劣势

  • 轮询方式效率较低，500毫秒延迟可能导致报价事件不及时，在高频场景下存在滞后
  • 事件ID使用品种索引（pos），当市场观察列表变化时索引会偏移，可能导致事件识别错误
  • 脚本而非EA，每次重启需手动运行，不支持持久化自动启动

改进建议

  • 改用OnBookEvent或SymbolInfoTick方式替代轮询，减少CPU占用并提高报价检测实时性
  • 使用品种名称的哈希值或固定ID作为事件标识，避免索引偏移导致的事件错配

Strengths

  • Enables cross-symbol tick monitoring without running a separate EA for each symbol in Market Watch
  • Uses custom event mechanism for decoupled communication between script and EA, with reasonable architecture
  • Implements controlled polling loop via Sleep and _StopFlag, balancing performance with user control

Weaknesses

  • Polling approach is inefficient; 500ms delay may cause untimely tick events with lag in high-frequency scenarios
  • Event ID uses symbol index (pos) which can shift when Market Watch list changes, potentially causing misidentification
  • It is a script not an EA, requiring manual execution on each restart without auto-start support

Improvements

  • Replace polling with OnBookEvent or SymbolInfoTick approach to reduce CPU usage and improve real-time tick detection
  • Use a hash of the symbol name or a fixed ID as event identifier instead of positional index to prevent event misassignment when Market Watch list changes
