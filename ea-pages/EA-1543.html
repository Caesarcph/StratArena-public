策略分析

分析 ### 2.1 核心策略概念 **⚠️ 这不是一个自动交易EA，而是一个账户级止损保护工具。** Exp_ToCloseLoss的作用是监控账户总盈亏，当账户亏损达到预设阈值时，自动平掉所有持仓，起到"熔断保护"的作用。 **工作原理**: 1. 每个Tick检测账户当前盈亏 (`ACCOUNT_PROFIT`) 2. 当亏损达到 `-MaxLoss` (默认-1000货币单位) 时触发熔断 3. 熔断触发后，遍历所有持仓并全部平仓 4. 使用全局变量记录熔断状态，防止重复触发 ### 2.2 入场条件 **无入场逻辑** - 本EA不进行自动开仓交易。 ### 2.3 出场条件 **熔断平仓机制**: - 触发条件: `AccountProfit <= -MaxLoss` - 平仓范围: 当前账户所有持仓 (多单+空单) - 平仓方式: 按持仓顺序从后向前遍历平仓 - 滑点容忍: 10点 ### 2.4 风险管理 | 功能 | 实现方式 | | **账户止损** | MaxLoss参数控制最大可承受亏损 | | **熔断状态持久化** | GlobalVariable存储熔断标志 | | **账户隔离** | 全局变量名包含AccountLogin，多账户互不干扰 | | **状态重置** | 无持仓时自动清除熔断标志 | | **实时监控显示** | Comment显示当前盈亏和阈值 |

优势

  • 账户隔离设计: 使用AccountLogin区分不同账户，多账户环境安全
  • 全局变量持久化: MT5重启后熔断状态不丢失
  • 状态自动重置: 无持仓时自动清除熔断标志，逻辑完整
  • 代码简洁: 主文件仅112行，逻辑清晰易懂
  • 复用标准库: 使用Nikolay Kositsin的tradealgorithms.mqh，平仓逻辑可靠

劣势

  • 无多级警告: 直接触发全平，无预警告机制
  • 无通知功能: 仅Comment显示，不适合无人值守
  • 参数命名误导: 注释与实际功能不符
  • 无日志记录: 熔断触发无持久化日志，难以复盘分析
  • 平仓顺序固定: 从后向前遍历，无法控制平仓优先级
