摘要

这是一个交易复制EA，分为服务端和客户端两种模式：服务端将交易操作写入共享文件，客户端读取并按复制因子调整手数后在本地复制这些交易。服务端与客户端通过MetaTrader公共文件夹中的文件进行进程间通信。

策略分析

此EA是一个交易复制工具而非自主交易策略。服务端模式通过OnTradeTransaction回调捕获主账户的所有交易事件（开仓和平仓），将交易数据（方向、手数、止损、止盈、品种、杠杆、净值等）序列化为二进制结构写入共享文件。客户端模式通过OnTick和OnTimer定时读取该文件，根据copy_factor按比例调整手数后执行复制交易，手数计算公式为：(本地净值 × 源手数 / 源净值) × (copy_factor/100)。出场逻辑通过维护sr_ticket与cl_ticket的映射表，在服务端发送平仓信号时关闭对应的本地持仓。仓位管理依赖VerifyLots函数规范化手数至品种最小步长和合法范围内。资金管理方面，复制手数与源账户净值和本地净值的比例挂钩，实现了基于资金比例的自适应仓位缩放。

Summary

This is a trade copier EA that operates in two modes: Server mode broadcasts trade transactions to a shared file, and Client mode reads those transactions and replicates them locally with configurable lot sizing via a copy factor. Communication between Server and Client instances uses file-based IPC through MetaTrader's common data folder.

Strategy Analysis

This EA is a trade copying utility rather than an autonomous trading strategy. The Server mode captures all trade events (opens and closes) from the master account via the OnTradeTransaction callback, serializing trade data (direction, lot size, SL, TP, symbol, leverage, equity, etc.) into a binary structure written to a shared file. The Client mode reads this file on each tick and timer event, replicating trades with lot sizes adjusted by a configurable copy factor, using the formula: (local equity × source lots / source equity) × (copy_factor/100). Exit logic maintains a mapping table of server tickets to client tickets, closing the corresponding local position when the server sends a close signal. Position sizing is handled by the VerifyLots function which normalizes lot sizes to the instrument's minimum step and valid range. In terms of money management, the copied lot size is proportionally scaled based on the ratio between source and local account equity, implementing equity-ratio-based adaptive position sizing.

优势

  • 基于净值比例的仓位缩放设计合理，能自动适配不同资金量的账户
  • 支持重试机制，当交易因requote失败时可排队重试而非直接放弃
  • 通过共享文件进行IPC通信，无需网络配置，同终端实例间通信简单可靠
  • VerifyLots函数完善地处理了手数规范化，考虑了最小步长、最小手数和最大手数限制
  • 服务端异常退出时通过delete文件通知客户端自动断开，具备基本的断线检测

劣势

  • 文件通信机制无并发控制，多客户端同时读取可能导致数据竞争和重复交易
  • pair_ticket映射表存储在静态数组中，EA重启后映射丢失，无法关闭重启前复制的持仓
  • 缺少心跳检测机制，服务端静默崩溃时客户端可能长时间无感知
  • Data结构中symbol仅8字节，无法支持较长的品种名称
  • 客户端读取文件后未验证数据完整性（如hash字段已声明但未使用），存在读到不完整数据的风险

改进建议

  • 增加心跳机制和超时检测，服务端定期写入时间戳，客户端检测超时后自动断开并报警
  • 使用管道或socket通信替代文件共享，支持跨终端和跨机器的远程复制场景
  • 利用hash字段实现数据完整性校验，防止客户端读到半写状态的数据

Strengths

  • Equity-ratio-based position scaling is well-designed, automatically adapting to accounts of different sizes
  • Retry mechanism queues failed trades due to requotes instead of silently discarding them
  • File-based IPC requires no network configuration, making same-terminal instance communication simple and reliable
  • VerifyLots function properly normalizes lot sizes, accounting for volume step, minimum and maximum lot constraints
  • Server abnormal shutdown notifies clients via a delete file marker, providing basic disconnection detection

Weaknesses

  • No concurrency control for file-based communication; multiple clients reading simultaneously may cause data races and duplicate trades
  • The pair_ticket mapping is stored in a static array and is lost on EA restart, making it impossible to close positions copied before restart
  • No heartbeat mechanism; if the server crashes silently, the client may remain unaware for extended periods
  • The Data structure allocates only 8 bytes for symbol name, insufficient for longer instrument names
  • The client does not verify data integrity after reading; the hash field is declared but never used, risking processing of incomplete data

Improvements

  • Add heartbeat mechanism and timeout detection: server periodically writes timestamps, client auto-disconnects and alerts on timeout
  • Replace file sharing with pipes or socket communication to support cross-terminal and cross-machine remote copying scenarios
  • Utilize the hash field for data integrity verification to prevent the client from reading partially-written data

风险点

  • EA重启后ticket映射丢失，可能导致复制的持仓无法被正确关闭

  • copy_factor可设置任意值，过大的复制因子可能导致超出账户承受能力的仓位
  • 多客户端场景下缺乏并发控制，可能导致重复开仓

Risk Assessment

Overall:MEDIUM

Risk Points

  • Ticket mapping is lost on EA restart, potentially leaving copied positions uncloseable
  • File read/write lacks atomicity guarantees; client may read incomplete trade data
  • copy_factor accepts arbitrary values; excessively large factors may create positions beyond account capacity
  • Lack of concurrency control in multi-client scenarios may cause duplicate position openings
