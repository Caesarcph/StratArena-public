摘要

该EA实现了周期性区间突破策略，在每周指定日期和时段确定价格区间中心，当价格突破计算区间时入场交易。结合ATR指标计算区间范围，并采用马丁格尔仓位恢复系统来弥补累计亏损，止盈止损基于区间大小设定。

策略分析

策略概念：该EA是一种周期性区间突破策略，在用户指定的星期和小时，以前一小时的收盘价作为区间中心，结合ATR指标或价格百分比计算突破范围。入场条件：当Ask价格突破上轨(pHighStop)时开多单，当Bid价格跌破下轨(pLowStop)时开空单，每次只开一个方向的单。出场条件：通过止盈(pHighProfit/pLowProfit)和止损(pHighLoss/pLowLoss)自动平仓，止盈止损距离基于Range乘以百分比系数计算。仓位管理：采用马丁格尔系统，亏损后手数翻倍(kLot *= 2)，盈利后重置为1倍手数，同时计算累计亏损补偿值(comLoss)调整止盈止损。资金管理：入场前检查自由保证金是否充足(要求大于1000*Lot)，但该检查未考虑kLot倍数放大后的实际保证金需求，存在风险低估。整体策略逻辑清晰但马丁格尔机制风险极高，可能在小账户上迅速爆仓。

Summary

This EA implements a periodic range breakout strategy that identifies a price range center at a specified day and hour each week, then places pending-style breakout trades when price breaks above or below the calculated range. It incorporates ATR-based range calculation with a martingale position sizing recovery system after losses, and uses take-profit/stop-loss levels derived from the range size.

Strategy Analysis

Strategy concept: This EA is a periodic range breakout system that establishes a price center using the previous H1 candle close at a user-specified day and hour each week, then calculates breakout boundaries using either ATR or a price percentage. Entry conditions: A buy order is opened when the Ask price breaks above the upper range boundary (pHighStop), and a sell order is opened when the Bid price breaks below the lower range boundary (pLowStop); only one trade direction is allowed at a time. Exit conditions: Trades are closed automatically via take-profit and stop-loss levels derived by scaling the Range value by configurable percentages. Position sizing: A martingale system doubles the lot multiplier (kLot) after each loss and resets it to 1 after a win, while also computing a cumulative loss compensation value (comLoss) that inflates the take-profit target to recover prior losses. Money management: The EA checks if free margin exceeds 1000*Lot before opening a trade, but this check fails to account for the kLot multiplier, significantly underestimating the actual margin requirement when martingale scaling is active. The strategy logic is coherent but the martingale mechanism introduces extreme risk, potentially causing rapid account blowup on small accounts during losing streaks.

优势

  • 策略概念清晰，区间突破逻辑简洁明了，易于理解和调优
  • 使用ATR指标动态计算突破范围，能够自适应市场波动率变化
  • 参数输入校验完善，对所有百分比参数和周末日期都有边界检查和默认值处理
  • 仓位规范化处理到位，SetVolume函数正确处理了最小/最大手数和手数步长对齐

劣势

  • 马丁格尔系统风险极高，连续亏损时手数指数增长，极易导致账户爆仓
  • 保证金检查存在严重bug：使用1000*Lot而非1000*Lot*kLot，在马丁格尔倍增时严重低估实际保证金需求
  • 没有持仓状态同步机制，依赖PositionSelectByTicket判断平仓，在网络异常或重启后可能丢失交易状态
  • comLoss补偿机制不安全，亏损后将止盈设为comLoss值同时增大止损，导致风险收益比严重恶化
  • 缺少点差过滤，在低流动性时段突破可能因大点差而虚假触发

改进建议

  • 移除或限制马丁格尔系统，改为固定仓位或基于波动率的仓位管理(如ATR比例缩仓)，避免指数级风险增长
  • 修复保证金检查bug，将1000*Lot改为1000*Lot*kLot以正确反映实际保证金需求
  • 增加持仓状态持久化机制(如全局变量或文件存储)，确保EA重启或断线后能正确恢复交易状态
  • 增加点差过滤和最小波动阈值，避免低流动性时段的虚假突破信号
  • 增加最大连续亏损次数限制和最大手数上限，防止马丁格尔系统失控

Strengths

  • Clean and intuitive strategy concept with straightforward breakout logic that is easy to understand and tune
  • Uses ATR indicator for dynamic range calculation, allowing the strategy to adapt to changing market volatility
  • Thorough input validation with boundary checks and sensible defaults for all percentage parameters and weekend day selection
  • Proper lot size normalization in SetVolume function that correctly handles min/max volume and step alignment

Weaknesses

  • Martingale system carries extreme risk; lot size doubles after each loss, potentially causing rapid account blowout during losing streaks
  • Critical margin check bug: uses 1000*Lot instead of 1000*Lot*kLot, severely underestimating actual margin requirement when martingale scaling is active
  • No trade state persistence mechanism; reliance on PositionSelectByTicket for detecting closure means trade state can be lost on disconnect or EA restart
  • The comLoss compensation mechanism is unsafe: setting TP to comLoss while widening SL creates severely unfavorable risk-reward ratios after losses
  • No spread filter, meaning breakouts during low-liquidity sessions could be falsely triggered by wide spreads

Improvements

  • Remove or cap the martingale system; replace with fixed lot or volatility-based position sizing (e.g., ATR-proportional scaling) to avoid exponential risk growth
  • Fix the margin check bug by changing 1000*Lot to 1000*Lot*kLot to correctly reflect the actual margin requirement under martingale scaling
  • Add trade state persistence (e.g., global variables or file storage) to ensure correct trade state recovery after EA restart or connection loss
  • Add spread filter and minimum volatility threshold to prevent false breakout signals during low-liquidity sessions
  • Add maximum consecutive loss count limit and maximum lot cap to prevent the martingale system from running out of control

  • 保证金检查使用基础手数而非实际倍增手数，可能允许超出账户承受能力的大额交易

  • 双分号语法错误(return;;)虽不影响编译但暗示代码审查不足
