摘要

Peter Panel是一个半自动交易面板EA，通过GUI界面让用户手动放置、修改和平仓交易。它使用三条水平价格线（AQUA/GREEN/RED）来设定入场价、止盈和止损，用户拖动线条后点击按钮执行订单，EA本身不产生交易信号。

策略分析

此EA并非自动策略系统，而是一个交易辅助面板工具。入场条件完全由用户手动决定：用户在图表上拖动AQUA线设定入场价，GREEN线设定止盈价，RED线设定止损价，然后点击Buy/Sell/Stop/Limit按钮下单。出场条件同样由用户通过面板上的Modify和Close按钮手动操作。仓位管理通过面板上的Lot控件实现，包括手数增减（+/-按钮）、最大手数（Max按钮根据可用保证金计算）、最小手数（Min按钮）和规范化手数（Norm按钮）。资金管理方面，Max按钮调用OrderCalcMargin计算可用保证金允许的最大手数，但未考虑已用保证金和多重持仓的累积风险。止损止盈的设定依赖于用户对GREEN和RED线的正确放置，BUY单GREEN为止盈RED为止损，SELL单则反转，这要求用户理解线条含义。

Summary

Peter Panel is a semi-automated trading panel (EA) that provides a GUI for manually placing, modifying, and closing trades via three horizontal price lines (AQUA, GREEN, RED). It does not generate its own trading signals; the user drags the lines to set entry price, take-profit, and stop-loss levels, then clicks buttons to execute orders.

Strategy Analysis

This EA is not an automated strategy system but a trading assistance panel tool. Entry conditions are entirely determined by the user manually: the user drags the AQUA line to set the entry price, GREEN line for take-profit, and RED line for stop-loss, then clicks Buy/Sell/Stop/Limit buttons to place orders. Exit conditions are likewise manually operated by the user through the Modify and Close buttons on the panel. Position sizing is managed through the Lot controls on the panel, including lot increment/decrement (+/- buttons), maximum lot (Max button calculates based on available margin), minimum lot (Min button), and normalized lot (Norm button). For money management, the Max button calls OrderCalcMargin to calculate the maximum lot size allowed by available margin, but it does not account for already-used margin or cumulative risk from multiple positions. Stop-loss and take-profit settings depend on the user correctly placing the GREEN and RED lines—BUY orders use GREEN as TP and RED as SL, while SELL orders reverse this—requiring the user to understand the line semantics.

优势

  • 提供直观的GUI交易面板，集成下单、修改、平仓功能，操作便捷
  • 使用三条可拖动水平线可视化设定入场价/止盈/止损，直观易懂
  • 手数管理功能完善，支持增减、最大（按保证金计算）、最小和规范化手数
  • 实时刷新持仓和挂单列表，支持通过列表选择订单进行修改或平仓
  • 半自动模式给予交易者完全的控制权，不会盲目开仓

劣势

  • Max按钮仅根据单笔保证金计算最大手数，未考虑已有持仓的保证金占用，可能导致过度杠杆
  • 没有交易时间过滤（如新闻时段、休市时段），用户可能在不利时段下单
  • 构造函数中调用GetLot()时edits[0]尚未创建，导致lotSet从空控件读取为0，存在初始化顺序Bug
  • OnClickListItem中对Position和Order的选择逻辑可能冲突：如果同一个ticket既是Position又是Order，两者都会执行
  • 缺少点差过滤和滑点保护机制，市价单在剧烈波动时可能以极差价格成交

改进建议

  • 修复构造函数初始化顺序Bug：将GetLot()从构造函数移至Create()方法中在控件创建后调用
  • 在Max手数计算中加入已用保证金和已持仓手数的考量，防止过度杠杆
  • 添加对Position和Order互斥选择的逻辑，避免同一ticket被重复处理
  • 增加点差过滤和最大滑点限制，提高市价单成交质量
  • 为GREEN/RED线添加标签提示（如TP/SL），降低用户混淆线条含义的风险

Strengths

  • Provides an intuitive GUI trading panel integrating order placement, modification, and closing functions for convenient operation
  • Uses three draggable horizontal lines to visually set entry price/TP/SL, making it intuitive and easy to understand
  • Comprehensive lot management with increment/decrement, max (margin-based), min, and normalize functions
  • Real-time refresh of positions and pending orders list, supporting order selection for modification or closing
  • Semi-automated mode gives the trader full control, preventing blind order placement

Weaknesses

  • The Max button calculates maximum lot based on single-order margin without considering existing position margin usage, potentially leading to over-leveraging
  • No trading time filter (e.g., news events, market close periods), users may place orders during unfavorable sessions
  • Constructor calls GetLot() before edits[0] is created, causing lotSet to read 0 from an empty control—an initialization order bug
  • OnClickListItem logic for Position and Order selection may conflict: if the same ticket is both a Position and an Order, both blocks execute
  • Lacks spread filter and slippage protection; market orders during high volatility may fill at very unfavorable prices

Improvements

  • Fix the constructor initialization order bug: move GetLot() from the constructor to the Create() method after controls are created
  • Incorporate used margin and existing position lots into Max lot calculation to prevent over-leveraging
  • Add mutually exclusive logic for Position vs Order selection to avoid duplicate processing of the same ticket
  • Add spread filter and maximum slippage limit to improve market order fill quality
  • Add label hints (e.g., TP/SL) to the GREEN/RED lines to reduce the risk of users confusing line semantics
