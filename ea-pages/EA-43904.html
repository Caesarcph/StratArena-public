摘要

此EA在没有持仓时自动开仓卖出，然后监控持仓，当盈利或亏损达到用户设定的账户余额百分比时自动平仓，同时考虑了手数佣金和点差成本。P_pro版本增加了自动卖出入场逻辑，而Money manager 1.0仅处理平仓逻辑。两者共享基于账户余额百分比的盈亏平仓机制。

策略分析

策略概念：该EA的核心逻辑是基于账户余额百分比的盈亏管理工具，而非基于技术指标的趋势跟踪或动量策略。入场条件：P_pro版本在没有持仓时，每个tick都会自动以当前Bid价开仓卖出0.1手，缺乏任何技术分析信号或方向判断。出场条件：当持仓盈利达到(PD%×账户余额 + 佣金 + 点差)时平仓获利，当亏损达到(-(LD%×账户余额) - 佣金 - 点差)时平仓止损。仓位管理：固定手数0.1手，没有任何动态仓位调整或资金管理比例计算。资金管理：基于账户余额百分比设置盈亏阈值，同时将佣金和点差成本纳入计算，但Spread计算存在问题——ClosePosLoss中用Bid-Ask得到负值而非正确点差。整体策略缺乏方向性判断，纯粹是开仓后等待盈亏阈值触发的机械操作。

Summary

This EA automatically opens a sell position on every tick when no positions exist, then monitors open positions and closes them when profit or loss reaches a user-defined percentage of account balance, factoring in lot commissions and spread costs. P_pro adds the auto-entry sell logic while Money manager 1.0 only handles the closing logic. Both share identical profit/loss closing mechanisms based on account balance percentages.

Strategy Analysis

Strategy concept: The core logic is an account-balance-percentage-based profit/loss management utility rather than a technically-driven trend following or momentum strategy. Entry conditions: The P_pro variant automatically opens a 0.1-lot sell position at the current Bid price on every tick when no positions exist, with absolutely no technical analysis signal or directional judgment. Exit conditions: Positions are closed when profit reaches (PD% × account balance + commission + spread) or when loss reaches (-(LD% × account balance) - commission - spread). Position sizing: Fixed lot size of 0.1 lots with no dynamic position sizing or proportional money management calculation. Money management: Profit/loss thresholds are set based on account balance percentage with commission and spread costs factored in, but the spread calculation in ClosePosLoss is buggy — using Bid-Ask yields a negative value instead of the correct spread. The overall strategy lacks any directional analysis and is purely a mechanical operation of opening a position then waiting for profit/loss thresholds to trigger.

优势

  • 将佣金和点差成本纳入盈亏计算，提供了更真实的盈亏阈值
  • 可灵活启用或禁用盈利/亏损平仓功能，具有一定的配置灵活性
  • 使用账户余额百分比而非固定点数来设定阈值，能随资金变化自适应调整
  • 循环遍历持仓时从后向前遍历，避免了删除元素时的索引错位问题

劣势

  • ClosePosLoss中Spread计算错误：使用Bid-Ask而非Ask-Bid，导致点差值为负数，使亏损阈值计算失真
  • 入场逻辑仅为无条件卖出，没有任何技术指标或方向判断，纯粹是盲目开仓
  • 缺乏止损和止盈的订单级别设置，完全依赖程序运行时的tick检测来平仓，若EA断线则持仓无保护
  • 手数固定为0.1手，没有根据账户余额或风险比例动态调整仓位
  • ClosePosLoss函数中有多余的花括号层级，代码结构混乱
  • 没有新K线检测或时间过滤，每个tick都执行全部逻辑，可能造成不必要的性能开销

改进建议

  • 修复ClosePosLoss中的点差计算：应使用Ask-Bid而非Bid-Ask，确保点差为正值
  • 为入场逻辑添加技术指标判断或方向性信号，而非无条件卖出
  • 在开仓时设置订单级别的止损和止盈，作为EA断线时的安全网
  • 添加动态仓位计算，根据账户余额和风险比例自动调整手数
  • 添加新K线检测机制，避免每个tick重复执行不必要的计算和检测
  • 添加最大持仓数量限制和持仓时间限制，防止长时间暴露于市场风险中

Strengths

  • Factors commission and spread costs into profit/loss calculations, providing more realistic thresholds
  • Allows flexible enabling or disabling of profit/loss closing functions with configurable toggles
  • Uses account balance percentage rather than fixed pip amounts for thresholds, enabling adaptive adjustment as capital changes
  • Iterates positions from back to front, avoiding index shift issues when closing positions during iteration

Weaknesses

  • Spread calculation bug in ClosePosLoss: uses Bid-Ask instead of Ask-Bid, producing a negative spread value that distorts the loss threshold calculation
  • Entry logic is an unconditional sell with no technical indicators or directional judgment — purely blind order opening
  • No order-level stop loss or take profit is set, relying entirely on tick-level monitoring; if the EA disconnects, positions have zero protection
  • Fixed lot size of 0.1 with no dynamic position sizing based on account balance or risk percentage
  • Extra unnecessary brace nesting in ClosePosLoss function, indicating messy code structure
  • No new bar detection or time filtering; all logic executes on every tick, potentially causing unnecessary performance overhead

Improvements

  • Fix spread calculation in ClosePosLoss: should use Ask-Bid instead of Bid-Ask to ensure a positive spread value
  • Add technical indicator-based entry signals or directional judgment instead of unconditional selling
  • Set order-level stop loss and take profit when opening positions as a safety net when the EA is disconnected
  • Add dynamic position sizing that automatically adjusts lot size based on account balance and risk percentage
  • Add new bar detection mechanism to avoid redundant calculations and checks on every tick
  • Add maximum position count limits and maximum holding time limits to prevent prolonged market risk exposure

风险评估 / Risk Assessment

总体 / Overall:HIGH

风险点

  • 入场逻辑为无条件卖出，没有任何方向判断，等同于随机方向交易
  • 没有订单级别的止损止盈，EA断线时持仓完全无保护，可能造成远超LD%的亏损
  • 点差计算Bug导致亏损平仓阈值不准确，可能延迟止损或过早止损

Risk Assessment

Overall:HIGH

Risk Points

  • Entry logic is an unconditional sell with no directional judgment, equivalent to random-direction trading
  • No order-level stop loss/take profit; if EA disconnects, positions are completely unprotected and losses can far exceed LD%
  • Spread calculation bug causes inaccurate loss-closing thresholds, potentially delaying or prematurely triggering stops
