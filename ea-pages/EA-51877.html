摘要

这是一个工具型EA，在图表上显示一个对话框面板，展示基于当前可用保证金的最大可开仓手数，包括买入、卖出、挂单买入和挂单卖出四种情况。它本身不执行任何交易，仅计算并向交易者展示基于保证金的仓位信息。

策略分析

该EA并非交易策略，而是一个保证金计算工具。其核心概念是根据账户可用保证金和当前市场价格，计算各订单类型（买入、卖出、挂单买入、挂单卖出）的最大可开仓手数。入场条件和出场条件不适用于此工具，因为它不执行交易。仓位管理方面，它使用OrderCalcMargin函数计算1手所需保证金，然后用可用保证金除以每手保证金得出最大手数，并通过MathFloor向下取整到合法步长。资金管理方面，它使用AccountInfoDouble(ACCOUNT_MARGIN_FREE)获取可用保证金作为计算基础，并使用SymbolInfoDouble获取品种的最小手数、最大手数和手数步长进行规范化。然而，该工具存在一个严重BUG：在LotCheckPendingBuy和LotCheckPendingSell中使用了'||'运算符连接两个订单类型枚举值，这会执行按位或运算产生无效的枚举值，而非逻辑选择。此外，计算结果未与SYMBOL_VOLUME_MAX上限做比较，可能返回超过经纪商允许的最大手数。

Summary

This EA is a utility tool that displays a dialog panel on the chart showing the maximum lot sizes available for buy, sell, pending buy, and pending sell orders based on the current free margin. It does not open any trades itself; it merely calculates and presents margin-based lot size information to the trader.

Strategy Analysis

This EA is not a trading strategy but a margin calculation utility tool. Its core concept is to compute the maximum lot size available for each order type (buy, sell, pending buy, pending sell) based on the account's free margin and current market prices. Entry and exit conditions are not applicable since it does not execute trades. Position sizing logic uses the OrderCalcMargin function to determine the margin required for 1 lot, then divides the available free margin by the per-lot margin requirement to derive the maximum lot size, rounding down to the nearest valid lot step via MathFloor. Money management relies on AccountInfoDouble(ACCOUNT_MARGIN_FREE) to obtain the current free margin as the calculation basis, and uses SymbolInfoDouble to fetch the symbol's minimum lot, maximum lot, and lot step for normalization. However, there is a critical bug: in LotCheckPendingBuy and LotCheckPendingSell, the '||' operator is used to combine two order type enum values, which performs a bitwise OR operation producing an invalid enum value rather than a logical selection. Additionally, the calculated lot size is never clamped against SYMBOL_VOLUME_MAX, so it may return values exceeding the broker's maximum allowed lot size.

优势

  • 提供直观的GUI面板显示各订单类型的最大可开仓手数，方便交易者快速决策
  • 使用了OrderCalcMargin函数进行保证金计算，这是MQL5官方推荐的计算方式，准确性较高
  • 手数规范化处理考虑了最小手数和手数步长，避免出现不合法的下单手数
  • 覆盖了买入、卖出、挂单买入、挂单卖出四种常见订单类型，信息全面

劣势

  • LotCheckPendingBuy和LotCheckPendingSell中使用'||'运算符连接枚举值，执行的是按位或运算而非逻辑选择，产生无效的OrderCalcMargin调用
  • 计算的最大手数未与SYMBOL_VOLUME_MAX做上限比较，可能返回超过经纪商允许的最大手数
  • 对话框中显示的数值只在面板创建时计算一次，不会随行情或保证金变化自动更新
  • static关键字在lotSize变量上的使用没有必要，且所有四个LotCheck函数逻辑高度重复，未做代码复用
  • 定时器功能(pause变量)被创建但未实际用于任何逻辑，属于无用代码

改进建议

  • 修复OrderCalcMargin调用中的枚举值BUG：挂单买入应使用ORDER_TYPE_BUY_STOP，挂单卖出应使用ORDER_TYPE_SELL_STOP（或分别计算两种挂单类型）
  • 添加SYMBOL_VOLUME_MAX上限检查，确保计算结果不超过经纪商允许的最大手数
  • 实现定时器驱动的自动刷新功能，利用已有的OnTimer和pause变量定期更新面板显示的数值
  • 将四个重复的LotCheck函数重构为一个带参数的通用函数，减少代码冗余

Strengths

  • Provides an intuitive GUI panel displaying maximum available lot sizes for each order type, enabling traders to make quick decisions
  • Uses the OrderCalcMargin function for margin calculation, which is the officially recommended MQL5 method and provides good accuracy
  • Lot size normalization accounts for minimum lot and lot step, preventing invalid order sizes
  • Covers four common order types: buy, sell, pending buy, and pending sell, providing comprehensive information

Weaknesses

  • LotCheckPendingBuy and LotCheckPendingSell use the '||' operator to combine enum values, which performs a bitwise OR operation instead of logical selection, resulting in an invalid OrderCalcMargin call
  • The calculated maximum lot size is never compared against SYMBOL_VOLUME_MAX upper limit, potentially returning values exceeding the broker's maximum allowed lot
  • Displayed values are only calculated once when the panel is created and do not automatically update when market conditions or margin changes
  • The 'static' keyword on lotSize variables is unnecessary, and all four LotCheck functions have highly duplicated logic with no code reuse
  • The timer functionality (pause variable) is created but not actually used in any logic, making it dead code

Improvements

  • Fix the enum value bug in OrderCalcMargin calls: pending buy should use ORDER_TYPE_BUY_STOP and pending sell should use ORDER_TYPE_SELL_STOP (or calculate each pending order type separately)
  • Add SYMBOL_VOLUME_MAX upper bound check to ensure calculated results never exceed the broker's maximum allowed lot size
  • Implement timer-driven auto-refresh functionality, leveraging the existing OnTimer and pause variable to periodically update the displayed values on the panel
  • Refactor the four duplicated LotCheck functions into a single parameterized utility function to reduce code redundancy

风险评估

总体:SAFE

风险点

  • 挂单保证金计算使用了按位或产生的无效枚举值，OrderCalcMargin可能返回错误结果，导致显示的最大手数不准确
  • 未与SYMBOL_VOLUME_MAX做上限比较，显示值可能误导交易者尝试下超出限制的订单

Risk Assessment

Overall:SAFE

Risk Points

  • Pending order margin calculation uses invalid enum values produced by bitwise OR, which may cause OrderCalcMargin to return incorrect results, leading to inaccurate displayed maximum lot sizes
  • No comparison with SYMBOL_VOLUME_MAX upper limit means displayed values may mislead traders into attempting orders that exceed broker limits
