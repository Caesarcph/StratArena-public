摘要

这是一个多货币马丁格尔EA，首先开一个初始买入或卖出订单，亏损后反转方向并将手数乘以倍数。它使用虚拟止损/止盈，支持可选的移动止损，并通过紧凑的字符串语法支持多品种同时运行的独立配置。

策略分析

策略核心是马丁格尔反转策略：初始按StartType方向开仓，若订单以亏损平仓则反转方向并将手数乘以Factor倍数，若盈利则重置为初始手数继续同方向开仓。入场条件为：无持仓时按StartType开首单；前单盈利平仓后同方向重新开初始手数订单；前单亏损平仓后反方向开Factor倍手数订单。出场条件采用虚拟止损止盈：当价格触及开仓价±止损/止盈点数时市价平仓，也支持移动止损（盈亏平衡或直线跟踪模式）。仓位管理上，手数每次亏损后乘以Factor并用lots_step取整，但受限于Limit设定的最大倍数和最大手数限制。资金管理方面，有checkFreeMargin检查可用保证金，不足时回退到初始手数，若仍不足则不开仓并触发SkipBadTime机制暂停交易。支持时间过滤（HourStart到HourEnd）和坏时段跳过机制。

Summary

A multi-currency martingale EA that opens an initial BUY or SELL order and, upon a loss, reverses direction with a multiplied lot size. It uses virtual stop-loss/take-profit with optional trailing stops and supports per-symbol configuration via a compact string syntax for running multiple instruments simultaneously.

Strategy Analysis

The core strategy is a martingale reversal system: it opens an initial order in the StartType direction, and upon a losing close, reverses direction with the lot size multiplied by the Factor. On a profitable close, it resets to the initial lot size and continues in the same direction. Entry conditions are: when no position exists, open the first order per StartType; after a profitable close, re-open in the same direction with initial lots; after a losing close, open in the opposite direction with Factor-multiplied lots. Exit conditions use virtual stop-loss and take-profit: market close when price hits open price ± SL/TP points in price terms, with optional trailing stop support (breakeven or straight trailing modes). Position sizing multiplies lots by Factor on each loss, rounded to the lot step, but capped by the Limit parameter (max multiplications) and the broker's maximum lot size. Money management includes a checkFreeMargin function that verifies available margin before opening, falling back to initial lots if insufficient, and skipping the trade entirely if margin is still inadequate while triggering the SkipBadTime pause mechanism. The EA also supports time filtering (HourStart to HourEnd) and a bad-time skipping mechanism to avoid repeatedly hitting margin errors.

优势

  • 支持多品种同时运行，通过紧凑的字符串语法实现灵活的独立配置
  • 有保证金检查机制，不足时回退到初始手数，避免爆仓
  • SkipBadTime机制可在连续下单失败时暂停交易，防止频繁报错消耗资源
  • 虚拟止损止盈实现灵活，支持移动止损模式
  • 代码结构清晰，使用面向对象设计（Settings/ExpMartin/ExpMartinPool）

劣势

  • 马丁格尔策略本质风险极高，连续亏损时手数指数增长，可能在几次亏损后就达到最大手数或爆仓
  • 虚拟止损止盈依赖EA持续运行，若EA断线或重启则止损止盈失效，无服务器端保护
  • 订单选择逻辑有缺陷：init中只查找第一个BUY或SELL订单即break，可能遗漏同方向的其他订单
  • 没有真正的止损单挂到服务器，极端行情下滑点可能远超预设止损
  • Limit参数控制的是预计算的最大手数而非实际开仓次数，连续亏损后可能超过预期的资金承受范围

改进建议

  • 将止损单真正挂到服务器而非虚拟止损，确保EA断线时仍有保护
  • 增加最大回撤百分比限制和最大连续亏损次数限制，作为资金管理的硬性保护
  • 修复init中订单扫描逻辑，应收集所有相关订单而非只取第一个就break
  • 增加新K线检测机制，避免在同一个tick内重复执行交易逻辑
  • 增加点差过滤，避免在高点差时段开仓

Strengths

  • Supports multi-currency simultaneous operation with flexible per-symbol configuration via compact string syntax
  • Includes margin check mechanism that falls back to initial lots when insufficient, helping prevent account blow-up
  • SkipBadTime mechanism pauses trading after order failures, preventing resource waste from repeated errors
  • Virtual stop-loss/take-profit implementation is flexible with trailing stop support
  • Clean code structure using object-oriented design (Settings/ExpMartin/ExpMartinPool classes)

Weaknesses

  • Martingale strategy carries extreme inherent risk: lot sizes grow exponentially on consecutive losses, potentially hitting max lots or blowing the account in just a few losing streaks
  • Virtual stop-loss/take-profit depends on EA running continuously; if the EA disconnects or restarts, SL/TP protection is lost with no server-side safeguard
  • Order selection logic in init() has a flaw: it breaks after finding the first BUY or SELL ticket, potentially missing other orders in the same direction
  • No real stop-loss orders are placed on the server, so extreme market gaps can result in losses far exceeding the intended stop-loss
  • The Limit parameter controls pre-calculated max lot size rather than actual number of martingale steps, so consecutive losses may exceed expected capital tolerance

Improvements

  • Place real stop-loss orders on the server instead of virtual SL/TP, ensuring protection even when the EA is disconnected
  • Add maximum drawdown percentage limit and maximum consecutive loss count limit as hard capital protection guards
  • Fix the order scanning logic in init() to collect all relevant orders rather than breaking after finding the first one
  • Add new bar detection mechanism to avoid repeated trade execution within the same tick
  • Add spread filter to avoid opening positions during high-spread periods
