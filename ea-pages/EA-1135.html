摘要

该EA将基于CCI指标的基础交易信号与最多三个感知器神经网络（卖出、买入和通用）相结合来生成买卖信号。感知器使用可配置历史周期上的加权价格差值，运行模式（pass参数）选择哪个信号源驱动交易决策。持仓以固定手数和可配置的止损/止盈水平开仓。

策略分析

策略概念：该EA融合了传统CCI指标信号与感知器神经网络，构成一个混合交易系统。入场条件：基础系统以CCI值作为信号（正值为买入，负值为卖出）；感知器系统通过计算多个时间偏移的收盘价差值的加权和来输出信号，卖出感知器输出负值触发卖出，买入感知器输出正值触发买入，通用感知器决定最终方向优先级。出场条件：完全依赖固定点数的止损和止盈来平仓，没有动态追踪止损或其他出场机制。仓位管理：使用固定手数（lots参数），没有根据账户余额或风险动态调整仓位大小的机制。资金管理：三套感知器各自有独立的止损止盈参数（sl2/tp2, sl3/tp3），基础系统也有独立的sl1/tp1，但缺乏整体资金管理框架。运行模式通过pass参数控制：1=仅基础系统，2=仅卖出感知器，3=仅买入感知器，4=所有感知器联合决策。

Summary

This EA combines a basic CCI-based trading signal with up to three perceptron neural networks (sale, buying, and general) to generate buy/sell signals. The perceptrons use weighted price differences over configurable historical periods, and the operating mode (pass parameter) selects which signal source drives trade decisions. Positions are opened with fixed lot sizes and configurable stop-loss/take-profit levels.

Strategy Analysis

Strategy concept: This EA merges a traditional CCI indicator signal with perceptron neural networks, forming a hybrid trading system. Entry conditions: The basic system uses the CCI value as a signal (positive for buy, negative for sell); the perceptron system computes a weighted sum of close price differences across multiple time offsets, where the sale perceptron negative output triggers sells, the buying perceptron positive output triggers buys, and the general perceptron determines final direction priority. Exit conditions: Relies entirely on fixed-point stop-loss and take-profit for position closure, with no trailing stop or other dynamic exit mechanisms. Position sizing: Uses a fixed lot size (lots parameter) with no dynamic sizing based on account balance or risk percentage. Money management: Three perceptron sets each have independent SL/TP parameters (sl2/tp2, sl3/tp3), and the basic system has sl1/tp1, but there is no overall money management framework. Operating mode is controlled via the pass parameter: 1=basic system only, 2=sale perceptron only, 3=buying perceptron only, 4=all perceptrons combined for joint decision-making.

优势

  • 多模式运行设计灵活，可选择纯CCI信号或感知器增强信号
  • 感知器使用价格差值作为输入，具有一定的价格动量捕捉能力
  • 止损止盈校验机制（CheckBuySL/TP等）防止在止损级别附近开仓

劣势

  • 感知器权重默认值全为0（100-100=0），默认配置下感知器输出恒为零，形同虚设
  • 固定手数无资金管理，未根据账户风险动态调整仓位
  • 感知器无训练/优化机制，权重需要手动调参，缺乏自适应学习能力
  • 止损止盈参数类型为double但作为int点数使用，存在类型不一致隐患
  • 无追踪止损、无部分平仓、无信号反转平仓机制

改进建议

  • 增加感知器权重的自动优化机制，如遗传算法或梯度下降，使系统能自适应市场变化
  • 实现动态仓位管理，根据账户余额和风险比例自动计算手数
  • 添加追踪止损和信号反转平仓逻辑，提升出场策略的灵活性
  • 修复止损止盈参数的类型不一致问题，统一使用int或double

Strengths

  • Flexible multi-mode operation design allowing choice between pure CCI signals or perceptron-enhanced signals
  • Perceptrons use price differences as inputs, providing some price momentum capture capability
  • SL/TP validation mechanism (CheckBuySL/TP etc.) prevents opening positions too close to stop levels

Weaknesses

  • Default perceptron weights are all zero (100-100=0), making perceptron output always zero in default config, effectively useless
  • Fixed lot sizing with no money management, no dynamic position adjustment based on account risk
  • No training/optimization mechanism for perceptrons, weights require manual tuning, lacking adaptive learning
  • SL/TP parameters declared as double but used as int point values, type inconsistency risk
  • No trailing stop, no partial close, no signal-reversal close mechanism

Improvements

  • Add automatic optimization mechanism for perceptron weights such as genetic algorithm or gradient descent for market adaptivity
  • Implement dynamic position sizing based on account balance and risk ratio for automated lot calculation
  • Add trailing stop and signal-reversal close logic to improve exit strategy flexibility
  • Fix the SL/TP parameter type inconsistency, standardize to either int or double throughout

风险评估

总体:MEDIUM

风险点

  • 默认权重全为零导致感知器无效，用户可能误以为感知器在工作
  • 固定手数无风险控制，小账户可能因单笔亏损过大而爆仓
  • 止损止盈参数类型为double但函数签名接收int，存在隐式截断风险

Risk Assessment

Overall:MEDIUM

Risk Points

  • Default weights all zero makes perceptrons ineffective, users may mistakenly believe perceptrons are active
  • Fixed lot sizing without risk control, small accounts could blow up from a single large loss
  • SL/TP parameters are double type but functions expect int, implicit truncation risk exists
