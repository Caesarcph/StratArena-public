ASCTrendND

This EA trades based on ASCTrend indicator signals, filtered by NRTR and TrendStrength indicators to confirm trend direction. It uses ASCTrend signal values as stop loss levels and manages open positions via a trailing stop mechanism with no take profit target.

Strategy analysis

The strategy core relies on the ASCTrend indicator to generate primary trade signals, triggered when valid values appear in the sell or buy signal buffers. Entry signals must pass through two filter layers: the NRTR indicator confirms trend direction (buys require NRTR uptrend confirmation, sells require NRTR downtrend confirmation), and the TrendStrength indicator further validates trend strength. Exit relies entirely on a trailing stop mechanism with no fixed take profit target. Position sizing uses fixed lots, as the money management module is explicitly declared unimplemented (lotsMode=0). Stop loss is based on ASCTrend signal values, constrained by the broker's stop level requirements. Signals are checked only on new bar formation to prevent repeated trades. Only one position is held at a time, identified by Magic Number.

Strengths

  • Multi-layer filtering (ASCTrend+NRTR+TrendStrength) reduces false signals
  • Signal check only on new bar formation avoids tick-level overtrading
  • Magic Number isolates positions preventing conflicts with other EAs
  • Stop loss constrained by broker stop level requirements reduces rejected orders
  • Clean code architecture with separated signal checking, filtering, and execution

Weaknesses

  • Money management module unimplemented, only fixed lots supported, lacking risk control flexibility
  • No take profit, exit relies entirely on trailing stop which may miss profit locking before quick reversals
  • NRTR and TrendStrength IndicatorRelease calls are commented out in OnDeinit, causing resource leaks
  • Breakeven and ProfitLock features marked as untested, present in code but not configurable via inputs
  • Async trading mode enabled without complete transaction confirmation and retry mechanisms
  • CheckPositionExist only checks single symbol single position, cannot handle multi-position scenarios

Possible improvements

  • Implement money management module supporting dynamic lot sizing based on risk percentage and stop loss distance
  • Uncomment IndicatorRelease calls in OnDeinit to fix indicator handle resource leaks
  • Add take profit option or ATR-based dynamic take profit to complement trailing stop
  • Convert Breakeven and ProfitLock to input parameters and complete testing validation

Risk assessment

Overall risk: Medium

  • Money management unimplemented, fixed lots cannot dynamically adjust based on account risk
  • Async trading mode lacks complete error handling and retry mechanisms
  • No take profit target, trailing stop may suffer severe slippage in extreme market conditions
  • Indicator resources not properly released may cause memory leaks during long-term operation
