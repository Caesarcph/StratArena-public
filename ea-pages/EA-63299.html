策略分析

分析 ### 2.1 核心策略概念 HedgeCover是一款**智能仓位对冲保护工具**，而非传统意义上的趋势跟踪或均值回归交易EA。其核心功能是： **当主策略持仓达到一定亏损阈值时，自动开启反向对冲仓位以限制风险敞口。** 这是一个**风险管理辅助工具**，设计用于： - 配合其他主交易策略使用 - 当主策略出现浮亏时提供保护性对冲 - 防止单笔交易亏损无限扩大 ### 2.2 入场条件 **对冲开仓触发条件**（必须全部满足）： 1. **亏损阈值触发**: 持仓浮亏达到设定的点数阈值（默认50点） - 买单亏损计算: `(开仓价 - 当前价) / (Point × 调整系数)` - 卖单亏损计算: `(当前价 - 开仓价) / (Point × 调整系数)` 2. **冷却期检查**: 距离上次对冲必须经过设定时间（默认5分钟） - 防止频繁开仓对冲 3. **魔法编号过滤**: 只对符合设定的主策略仓位进行对冲 - 可设置为0以监控所有仓位 4. **重复对冲保护**: 同一仓位只对冲一次 - 通过`hedged_positions[]`数组跟踪已对冲的仓位 5. **最大对冲数限制**: 不超过设定的最大对冲数量（默认3个） 6. **品种过滤**: 只对冲当前图表品种的仓位 7. **保证金安全检查**: 对冲后剩余保证金需 > 20% **对冲方向**： - 多头仓位亏损 → 开空单对冲 - 空头仓位亏损 → 开多单对冲 **对冲手数计算**： ### 2.3 出场条件 **注意**: 此EA本身**不会主动平仓**，仅用于开对冲仓位。 对冲仓位的出场需依赖： 1. 主策略的平仓逻辑 2. 手动干预 3. 其他风控EA ### 2.4 风险管理 **内置风控措施**： | 措施 | 说明 | 参数 | | 冷却期 | 防止高频对冲 | 5-15分钟 | | 最大对冲数 | 总体风险控制 | 2-5个 | | 保证金检查 | 80%安全边际 | 硬编码 | | 魔法编号隔离 | 防止对冲对冲 | 可配置 | | 已对冲追踪 | 防止重复对冲 | 内存数组 | | 手数规范化 | 合法手数校验 | 自动处理 |

优势

  • 完善的风险控制架构
  • 冷却期、最大对冲数、保证金检查
  • 多重保护机制防止失控
  • 防重复对冲设计
  • 数组追踪
  • 有效防止同一仓位多次对冲
  • 魔法编号隔离
  • 主策略和对冲仓位分离
  • 便于后续管理和统计
  • 代码清晰专业
  • 使用标准库封装
  • 注释详细，易于理解
  • 日志完整
  • 可选的详细日志输出
  • 便于监控和调试

劣势

  • 不主动平仓
  • 对冲仓位无出场机制
  • 需要外部干预才能解除
  • 可能扩大风险
  • 对冲后实际敞口增加
  • 锁仓不等于风险消除
  • 依赖主策略
  • 作为辅助工具无法独立工作
  • 主策略质量决定最终效果
  • 无止损止盈
  • 对冲仓位开仓后无SL/TP
  • 需要其他风控补充
  • 内存持久性问题
  • 数组仅保存在内存
  • EA重启后追踪状态丢失

改进建议

  • 添加对冲仓位止损
  • 添加自动解除机制
  • 持久化追踪状态
  • 添加止盈目标
