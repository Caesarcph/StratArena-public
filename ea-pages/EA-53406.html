摘要

该EA是一个交易复制器，分为主模式和从模式：主模式将持仓数据写入二进制文件，从模式读取该文件并在对应的从账户品种上镜像复制持仓。它支持主从品种映射，并通过50毫秒定时器实时处理开仓、修改和平仓操作。

策略分析

该EA并非策略型交易程序，而是一个交易复制工具。其核心概念是将主账户的持仓信息（票据号、品种、手数、方向、开仓价、止损、止盈）通过共享二进制文件传递给从账户。入场条件是当从账户检测到主账户存在新票据号时，以市价在对应从品种上开同方向仓位，并在注释字段中记录主账户票据号以便追踪。出场条件是当主账户的持仓已不存在时，从账户会根据注释中的票据号匹配并关闭对应的复制仓位。仓位管理完全依赖主账户的手数，从账户不做任何缩放或调整，1:1复制。资金管理方面没有任何独立的风控机制，不检查账户余额、可用保证金或最大持仓数，纯粹依赖主账户的决策。

Summary

This EA is a trade copier that operates in two modes: Master mode writes open position data to a binary file, and Slave mode reads that file to mirror positions on corresponding slave symbols. It supports symbol mapping between master and slave accounts and handles opening, modifying, and closing copied positions in real-time via a 50ms timer.

Strategy Analysis

This EA is not a strategy-based trading program but rather a trade copying utility. Its core concept is transmitting master account position data (ticket number, symbol, volume, direction, open price, SL, TP) to slave accounts via a shared binary file. Entry conditions are triggered when the slave detects a new ticket number from the master, opening a same-direction market position on the corresponding slave symbol, with the master ticket stored in the comment field for tracking. Exit conditions occur when the master position no longer exists, causing the slave to match and close the corresponding copied position based on the comment field ticket number. Position sizing is entirely dependent on the master account's volume with no scaling or adjustment — it copies 1:1. Money management has no independent risk control mechanisms, with no checks on account balance, free margin, or maximum position count, relying purely on the master account's decisions.

优势

  • 结构简单清晰，主从模式分离设计易于理解和维护
  • 支持品种映射，可在不同品种后缀的经纪商之间复制交易
  • 实现了完整的复制生命周期管理：开仓、修改止损止盈、平仓同步
  • 使用二进制文件共享数据，跨终端通信无需网络配置
  • 50毫秒定时器提供近实时的复制响应速度

劣势

  • 没有保证金检查，从账户可能在余额不足时仍尝试开仓导致失败
  • 仅支持2个品种映射，扩展性差，无法灵活添加更多品种对
  • 文件读写没有加锁机制，主从同时访问可能造成数据竞争或读取不完整
  • 1:1固定手数复制，无多倍手数或按比例缩放功能
  • 没有错误重试机制，交易失败后仅Print而不做任何恢复处理
  • 从模式平仓后删除copiedTickets元素可能导致索引错乱

改进建议

  • 增加品种映射的动态配置，支持任意数量的品种对，使用结构体数组替代硬编码
  • 添加文件锁定机制（如使用独立的锁文件）防止主从并发读写冲突，并增加交易错误重试逻辑
  • 加入保证金预检查、手数倍数参数、最大持仓数限制等风控功能，提升从账户安全性
  • 修复copiedTickets删除操作中的索引问题，使用从后往前遍历或可靠的数据结构

Strengths

  • Simple and clear architecture with separated master/slave modes that is easy to understand and maintain
  • Supports symbol mapping, enabling trade copying between brokers with different symbol suffixes
  • Implements complete copy lifecycle management: opening, SL/TP modification, and closing synchronization
  • Uses binary file sharing for cross-terminal communication without requiring network configuration
  • 50ms timer provides near-real-time copying response speed

Weaknesses

  • No margin check — slave may attempt to open positions when balance is insufficient, leading to failures
  • Only supports 2 symbol mappings with poor extensibility, cannot flexibly add more symbol pairs
  • No file locking mechanism — concurrent master/slave access may cause data races or incomplete reads
  • 1:1 fixed volume copying with no lot multiplier or proportional scaling functionality
  • No error retry mechanism — trade failures are only logged via Print without any recovery handling
  • Deleting copiedTickets elements after slave position close may cause index disorder in the array

Improvements

  • Add dynamic symbol mapping configuration supporting arbitrary number of symbol pairs using struct arrays instead of hardcoding
  • Implement file locking mechanism (e.g., using a separate lock file) to prevent concurrent read/write conflicts, and add trade error retry logic
  • Add margin pre-checks, lot multiplier parameter, maximum position limit, and other risk controls to improve slave account safety
  • Fix the index issue in copiedTickets deletion by iterating backwards or using a more reliable data structure

Risk Assessment

Overall:CAUTION

Risk Points

  • No file locking creates data race risk — slave may read incomplete or corrupted position data
  • No margin pre-check means slave may fail to open positions due to insufficient funds without timely user awareness
  • copiedTickets array deletion may cause index disorder, leading to subsequent position tracking failures
  • 1:1 fixed copying with no risk control layer means any erroneous master decision is executed without filtering
