Pass Wait then Pass

A tick-counting utility EA that implements a two-phase cycle: it counts ticks up to a configurable limit, then waits for another configurable number of ticks, before resetting and repeating. It displays the current count and wait values on the chart via Comment() but does not execute any trades.

摘要

一个计数工具EA，实现双阶段循环：先计数到设定上限的tick数，再等待另一个设定上限的tick数，然后重置并重复循环。通过Comment()在图表上显示当前计数和等待值，但不执行任何交易操作。

策略分析

该EA并非交易策略，而是一个tick计数与等待的工具框架。策略概念是基于tick频率的分阶段执行框架：第一阶段（Pass阶段）累计tick达到count参数后停止执行；第二阶段（Wait阶段）累计wait个tick的等待期；等待期结束后自动重置两个计数器，重新开始循环。入场条件完全由tick计数驱动，不存在任何交易信号生成逻辑。出场条件同样不存在，因为没有开仓操作。仓位管理和资金管理均未实现，EA仅提供计数骨架供用户填入自定义逻辑。整体而言，这是一个模板/脚手架代码，设计意图是让用户在指定tick间隔内执行代码块。

Summary

A tick-counting utility EA that implements a two-phase cycle: it counts ticks up to a configurable limit, then waits for another configurable number of ticks, before resetting and repeating. It displays the current count and wait values on the chart via Comment() but does not execute any trades.

Strategy Analysis

This EA is not a trading strategy but a tick-counting and waiting utility framework. The strategy concept is a two-phase cycle driven by tick frequency: Phase 1 (Pass phase) accumulates ticks until the 'count' parameter is reached, then stops executing user code; Phase 2 (Wait phase) accumulates 'wait' number of ticks as a cooldown period; after the wait completes, both counters reset and the cycle repeats. There are no entry conditions for trades whatsoever, as no trading signal generation logic exists. Exit conditions are similarly absent since no positions are ever opened. Position sizing and money management are completely unimplemented — the EA only provides a counting skeleton for users to insert their own custom logic. Overall, this is a template/scaffold code designed to let users execute code blocks at specified tick intervals with a built-in cooldown mechanism.

优势

  • 简洁的双阶段循环框架，逻辑清晰易懂
  • 提供可配置的计数和等待参数，灵活性好
  • 自动重置机制确保循环持续运行，无需手动干预
  • 通过Comment()实时显示计数状态，便于调试和监控
  • 代码结构简单，适合初学者学习和扩展

劣势

  • 没有任何交易逻辑，仅是一个空壳模板
  • 缺少新K线检测，同一根K线内可能多次执行
  • 没有错误处理机制，计数器溢出或异常值无防护
  • Comment()刷新频繁可能导致图表闪烁，影响性能
  • 等待阶段的代码块为空，用户容易误解执行时机

改进建议

  • 添加新K线检测（isNewBar），避免同一K线内重复执行逻辑
  • 使用计时器（OnTimer）替代tick计数，使执行间隔更稳定可预测
  • 增加输入参数校验，防止count和wait设为0或负值导致逻辑异常

Strengths

  • Clean two-phase cycle framework with clear and understandable logic
  • Configurable count and wait parameters provide good flexibility
  • Automatic reset mechanism ensures continuous cycling without manual intervention
  • Real-time counter display via Comment() aids debugging and monitoring
  • Simple code structure makes it suitable for beginners to learn and extend

Weaknesses

  • Contains no trading logic whatsoever — it is merely an empty shell template
  • Lacks new bar detection, potentially causing multiple executions within the same bar
  • No error handling mechanism — no protection against counter overflow or abnormal values
  • Frequent Comment() refreshes may cause chart flickering and impact performance
  • The wait phase code block is empty, making it easy for users to misunderstand execution timing

Improvements

  • Add new bar detection (isNewBar) to prevent repeated logic execution within the same bar
  • Use timer (OnTimer) instead of tick counting for more stable and predictable execution intervals
  • Add input parameter validation to prevent setting count or wait to 0 or negative values which would cause logic anomalies
